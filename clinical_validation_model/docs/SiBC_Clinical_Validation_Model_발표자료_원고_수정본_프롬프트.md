# Codex 작업 프롬프트 — SiBC Clinical Validation Model 쉬운 설명 발표자료

## 역할

당신은 복잡한 의료·데이터 모델을 처음 접하는 사람에게 설명하는 프레젠테이션 기획자다. 아래 원고를 바탕으로 SiBC Clinical Validation Model 발표자료와 발표자 스크립트를 작성한다.

## 발표 목적

발표가 끝났을 때 처음 보는 청중이 다음 네 가지를 이해해야 한다.

1. 진단 후보는 확정 진단이 아니며 다시 검증해야 한다.
2. 모델은 근거·시점·상충·설명 가능성을 확인한다.
3. 불명확하면 자동 통과하지 않고 제한·검토·보류한다.
4. 현재 결과는 기술 기준선이며 실제 임상 성능은 아직 검증되지 않았다.

## 작성 원칙

- 제목과 목차를 포함해 정확히 15장으로 구성한다.
- Clinical Layer 내부 구조, Workflow 위치, production schema, Profile·Behavior handoff 설명은 제외한다.
- NANDA/Omaha의 세부 기준이나 라이선스 설명은 본문에 넣지 않는다.
- 처음 나오는 용어는 같은 슬라이드 하단에서 짧게 설명하거나 용어 설명 슬라이드에서 정의한다.
- 영어 전문용어보다 쉬운 한국어를 먼저 쓰고, 기술 명칭은 괄호나 표에 보조적으로 표시한다.
- 한 슬라이드에는 한 가지 핵심 메시지만 둔다.
- 긴 문장, 과도한 상태 코드, 구현 필드명, 산식은 본문에서 제외한다.
- `VALIDATED`를 확정 진단이나 질병 확률로 표현하지 않는다.
- 기술 테스트와 합성 검증 통과를 실제 임상 성능으로 표현하지 않는다.
- 현재 저장소 기준 자동화 테스트는 99/99 통과, 합성 검증은 19개 시나리오·23/23 후보 일치로 표시한다.
- 임상 검증은 전문가 비교 기준이 없어 아직 차단된 상태이며 실제 성능은 미확인으로 표시한다.

### Slide 02. 오늘 볼 내용

**핵심 메시지:** 세 가지 질문으로 전체 구조를 이해한다.

1. 왜 필요한가 — 후보와 정답의 차이
2. 어떻게 검증하나 — 근거·시점·상충 확인
3. 결과는 무엇인가 — 세 지표·네 상태·다음 단계

### Slide 03. 한눈에 보는 Clinical Validation

**핵심 메시지:** 후보를 바로 확정하지 않고 필요한 조건을 다시 확인한다.

- 입력: 진단 후보 — 아직 확정되지 않은 검토 대상
- 확인: 안전 검증 — 근거·시점·상충·설명 확인
- 결과: 검증 결과 — 사용·제한·검토·보류
- 이 모델이 하는 일: 후보가 현재 자료로 사용 가능한지 확인
- 하지 않는 일: 새 진단이나 질병 확률 생성
- 용어: Gate는 통과·제한·검토·보류를 결정하는 안전 관문

### Slide 04. 왜 검증이 필요한가

**핵심 메시지:** 그럴듯한 후보에도 네 가지 위험이 남을 수 있다.

- 근거 부족 — 필수 자료 누락
- 시점 오류 — 너무 오래되거나 미래의 값
- 자료 상충 — 여러 자료가 서로 반대
- 설명 불명 — 사용한 기준과 버전을 추적하기 어려움
- 불명확하면 자동 통과하지 않고 이유를 남긴다.

### Slide 05. 먼저 알아둘 네 가지 용어

**핵심 메시지:** 같은 단어를 같은 의미로 이해한다.

- Candidate: 진단 후보 — 시스템이 제안한 검토 대상
- Evidence: 근거 — 판단에 사용한 관찰·측정·응답
- Rule: 규칙 — 무엇을 어떻게 확인할지 정한 기준
- Gate: 안전 관문 — 조건 충족 여부에 따라 통과 또는 보류
- Status: 검증 후 정해진 결과 상태
- Hard gate: 실패하면 다른 점수와 관계없이 멈추는 필수 조건

### Slide 06. 네 가지 질문만 기억하면 된다

**핵심 메시지:** 복잡한 검증도 네 질문으로 요약할 수 있다.

1. 필요한 근거가 충분한가?
2. 근거의 시점이 맞는가?
3. 반대되거나 적용하면 안 되는 근거가 있는가?
4. 어떤 기준과 이유로 판단했는지 설명할 수 있는가?

### Slide 07. 검증은 다섯 단계로 진행된다

**핵심 메시지:** 모든 후보를 같은 순서로 확인한다.

1. 후보 받기 — 검토 대상 확인
2. 근거 확인 — 필수·참고 자료 확인
3. 품질·시간 — 출처와 시점 확인
4. 위험 확인 — 상충과 배제 조건 확인
5. 결과 결정 — 상태와 이유 기록

### Slide 08. 필수 조건과 참고 근거는 다르다

**핵심 메시지:** 참고 근거가 많아도 필수 조건을 대신할 수 없다.

- 필수 조건: 반드시 모두 확인
- 참고 근거: 판단을 보완
- Hard gate: 필수 조건 실패 시 점수로 상쇄할 수 없음
- 필수 충족 + 참고 충분: 사용 가능 검토
- 필수 충족 + 참고 부족: 제한사항 표시
- 필수 누락·미충족: 통과하지 않고 검토 또는 보류

### Slide 09. 좋은 데이터는 값·출처·시점이 맞아야 한다

**핵심 메시지:** 정확한 값도 언제·어떻게 측정됐는지가 틀리면 근거가 될 수 없다.

- 값과 출처: 필드·단위·중복과 수집 경로 확인
- 인정 기간: 판단 이전이고 정해진 기간 안의 자료만 사용
- 범위 밖 값: 미래 값은 제외하고 오래된 값은 제한 표시
- 용어: 관찰 기간은 근거로 인정하는 시간 범위
- 주의: 기록이 없다는 사실을 행동이 없었다는 뜻으로 해석하지 않는다.

### Slide 10. 결과는 세 가지 관점으로 읽는다

**핵심 메시지:** 세 지표는 서로 다른 질문에 답한다.

- 기준 충족 정도 — 필수·참고 기준을 얼마나 충족했는가
- 판단 안정성 — 현재 자료에서 판단이 얼마나 안정적인가
- 설명 가능성 — 어떤 근거와 기준으로 판단했는지 추적 가능한가
- Clinical Validation Score는 질병 확률이 아니다.
- Decision Confidence는 정답 확률이 아니다.
- CDEI는 설명·추적 가능성 지표이며 정확도 지표가 아니다.

### Slide 11. 최종 결과는 네 가지 상태로 정리한다

**핵심 메시지:** 점수 하나보다 실제 사용 결정을 먼저 본다.

- 사용 가능 — 현재 기준의 검증 통과
- 제한 사용 — 제한사항을 함께 유지
- 사람 검토 — 충돌이나 불명확한 부분을 사람이 확인
- 사용 보류 — 근거 부족·상충·적용 불가·판단 불가
- `VALIDATED`는 확정 진단이 아니라 현재 Rule 검증을 통과했다는 뜻이다.

### Slide 12. 세 사례를 보면 결과가 더 쉽게 보인다

**핵심 메시지:** 같은 점수처럼 보여도 상충과 버전 문제에 따라 결정이 달라진다.

- A: 필수 조건 충족·품질 양호·상충 없음 → 사용 가능
- B: 필수 조건 충족·참고 근거 일부 부족 → 제한 사용
- C: 필수 조건 충족·겉보기 품질 양호·상충 또는 버전 불명 → 사람 검토
- 숫자나 높음·중간 표시는 설명용이며 승인된 cutoff가 아니다.

### Slide 13. 현재 확인된 범위와 한계

**핵심 메시지:** 기술 기준선은 통과했지만 실제 임상 성능은 아직 확인하지 않았다.

- 자동화 테스트: 99/99 통과
- 합성 후보 검증: 23/23 기대 결과 일치
- 시험 시나리오: 19개
- 임상 검증: 전문가 비교 기준 필요
- 실제 성능: 아직 측정하지 않음
- 용어: 합성 데이터는 실제 환자 정보가 아닌 시험용 사례

### Slide 14. 다음은 전문가 기준과 실제 자료 검증이다

**핵심 메시지:** 실제 성능을 말하려면 세 단계를 더 거쳐야 한다.

1. 기준 확정 — Rule의 출처·판본·사용 권한과 전문가 승인
2. 비교 기준 구축 — 실제 사례와 독립 전문가 합의
3. 임상·운영 검증 — 성능 확인, 수치 보정, 승인 기준 확정
- 용어: Reference standard는 모델과 독립적으로 전문가가 합의한 비교 기준

### Slide 15. 멈출 줄 아는 검증 모델

**핵심 메시지:** 더 높은 점수보다 언제 멈출지 아는 것이 중요하다.

- 근거·시점·상충·설명을 후보별로 확인한다.
- 불명확하면 검토하거나 보류한다.
- 기술 기준선 통과를 확정 진단이나 실제 임상 성능으로 표현하지 않는다.
