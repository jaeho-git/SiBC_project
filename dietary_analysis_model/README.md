# SiBC 식이분석 모델

작성: 오재호 과장 · 헬스커넥트(주) AI플랫폼본부 SiBC · 2026-10-26 기준

인바이츠루프 앱의 푸드렌즈 식사 기록과 웨어러블 데이터로부터 **사용자의 식습관 변화를 유도하는 행동변화 알람의 근거**를 만드는 시스템입니다.
산출물은 두 가지입니다. (1) 사용자·끼니·기간별로 계산된 **세분화된 결과 값**(기준 대비 %, 에너지 지수, 집단 백분위, 창 상태, 추세, 방향, 영양소별 판정 등),
(2) 문헌으로 세운 **판단 기준·규칙**(조건표, 방향 규칙, 판정 구간). 앱 개발 파트는 결과 값을 기준에 대조해 "지난주 대비 식이조절이 필요하다"와 같은
결론을 얻고 알람을 보냅니다. 식이분석은 결론의 재료와 잣대를 만들며, 진단이나 처방을 하지 않습니다.

현재 설계의 기준 문서는 [docs/system_design_20261022.md](docs/system_design_20261022.md)(정리본 2026-10-26)입니다.

## 원칙

- 시스템은 근거를 제공할 뿐 진단이나 처방을 하지 않습니다. 판정은 섭취 수준의 평가이며 건강 상태의 진단이 아닙니다.
- 사용자 목표는 입력으로 받지 않습니다. 방향은 신체 상태(BMI, 체중 추세, 의료진 가이드라인)로 정하고, 기준은 외부 표준(KDRIs 2025, 대한비만학회)에 고정합니다.
- 미기록과 결식, 미착용과 비활동을 구분합니다. 불완전한 데이터로는 판단 범위를 줄입니다.
- 에너지 지수와 집단 백분위는 품질 평가를 통과하기 전까지 추세·순위 참고용입니다. 정확한 kcal이나 백분위 수치를 판정 문구에 쓰지 않습니다.
- 거짓 알람률을 성능의 1차 기준으로 둡니다.
- 합성 데이터나 smoke 결과를 실제 성능으로 보고하지 않습니다. 검증 전에는 성능을 주장하지 않습니다. 페르소나 데이터는 로컬 파일로만 만들고 공유 DB(loop-dev, release)에 적재하지 않습니다.

## 보안 및 데이터 규칙

- 원본 사용자 식별자, 원시 식사 기록과 건강정보 row, `.env` 내용과 DB 접속정보는 저장소에 올리지 않습니다. 집계 통계, 합성 fixture, 버전 관리되는 규칙표만 허용합니다.
- 국민건강영양조사 원자료는 개인 재식별과 제3자 제공이 금지됩니다. 원본과 개인 단위 추출은 `00_Data/`·`01_Results/`(git 제외)에만 두고, 저장소에는 집계 표와 회귀 계수만 둡니다.
- release DB(`invites_loop`)는 운영 데이터가 누적되는 곳이므로 읽기만 하고, 식이분석 결과는 loop-dev에 저장합니다.
- CAN-Pro 데이터의 대량 추출과 재사용은 금지합니다. 농진청 국가표준식품성분표의 상용 서비스 사용 라이선스는 [확인 필요]입니다.
