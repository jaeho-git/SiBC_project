## 0. 목적과 역할 경계

식이 기록과 신체활동·신체 상태 데이터로부터 사용자의 **식습관 변화를 유도하는 행동변화 알람의 근거**를 만든다.

- **적용 대상은 인바이츠루프 앱**이다. 현재 사용자가 쓰는 운영 앱이며 기능·성능 업그레이드가 진행 중이다. 라이프트윈은 별개 앱이 아니라 인바이츠루프에 포함될 기능으로 개발 중이다. 푸드렌즈 식이 기록, 웨어러블 데이터 전송, 알람이 모두 이 한 앱에서 일어난다.
- **산출물은 두 가지다.** (1) 세분화된 결과 값: 사용자·끼니·기간별로 계산된 수치와 분류값(열량 기준 대비 %, 에너지 지수, 집단 백분위, 유효 일수, 창 상태, 추세, 방향, 영양소별 판정, 끼니의 평소 대비 배수, 플래그 등). (2) 판단 기준과 규칙: 문헌으로 세운 조건표(어느 값이면 과잉인지, 어느 BMI 구간이면 방향이 줄임인지, 어떤 조합이면 "지난주 대비 식이조절 필요"인지). 기준은 git에 버전 관리하고, 결과 값 레코드에는 계산에 쓴 기준 버전을 남긴다.
- **앱 개발 파트는 결과 값을 판단 기준에 대조해 결론을 얻고 알람·표시를 보낸다.** 예: "이 사용자는 지난주 대비 식이조절이 필요하다", "체중·신장이 마른 체형이므로 현재 식이조절이 요구되지 않는다", "이 끼니는 평소보다 크고 지난주 상태가 과잉이므로 조절 대상이다". 판단의 재료(결과 값)와 잣대(기준)는 식이분석이 만들고, 대조해 적용하는 실행과 알람 문구·전달은 앱의 역할이다. 식이분석은 앱에 기능을 요청하거나 조건을 붙이지 않고 지금 있는 데이터로 결과 값을 낸다.
- 사용자 목표(체중감량 등)는 입력으로 받지 않는다. 방향은 사용자의 **신체 상태**에서 추론하고, 기준은 **외부 표준**에 고정한다.
- 대체 음식 제안은 범위에서 제외한다. "현재 음식의 섭취량을 줄이라/유지하라/채우라"는 판단과 그 근거까지가 범위다.

## 2. 설계 원칙

1. 결과물은 그림이 아니라 레코드다. 끼니 기록 1건마다 **행동 층** 레코드, 기준일마다 **습관 층** 레코드를 만든다.
2. 끼니를 고정 배분과 비교하지 않는다. 하루 누적 섭취를 **하루 섭취 기준량**과 비교하고 **남은 섭취 허용량**으로 판단한다. (기준량·허용량은 열량과 영양소의 양이며 금전과 무관하다.)
3. 판정은 세 층으로 나눈다. **기준 층**(필요량, 얼마나 많은가), **방향 층**(신체 상태, 어느 쪽으로 가야 하는가), **맥락 층**(집단 위치, 비슷한 사람과 얼마나 다른가). 판정은 기준 층과 방향 층이 내고, 맥락 층은 설득력을 보강하고 오류를 검증한다.
4. 기준은 성·연령 평균이 아니라 가능한 한 개인 소모량이다. 섭취 − 소모가 **에너지 지수**다. 소모량은 추정하지 않고 도착한 실측값만 쓴다.
5. 미기록과 결식을 구분하고, 불완전한 데이터로는 판단 범위를 줄인다.
6. 에너지 지수와 개인 패턴은 품질·성능 평가를 통과한 범위에서만 사용한다. 통과 전에는 집단 기준(KDRIs)을 쓴다.
7. **거짓 알람률**을 성능의 1차 기준으로 둔다. 잘못된 "줄이라"는 근거는 신뢰와 기록률을 함께 떨어뜨린다.

## 3. 시스템 구조

### 3.1 입력

| 입력 | 출처 | 시점 | 역할 |
|---|---|---|---|
| 식이 기록 | 푸드렌즈 → loop-dev `sibc.meal`(끼니, `meal_type` 7종), `sibc.meal_food`(음식, `food_name_norm`, `serving_qty`), `sibc.meal_food_master`(식약처 기준 식품 마스터 21,172건, 100 g/100 ml 기준) | 실시간 | 끼니 1건이 판단 트리거 |
| 결식 표시 | 앱(현재 없음) | 실시간 | 미기록·결식 구분. 있으면 정확도가 오르는 **설계 가정**. 없으면 미기록을 불확실로 처리 |

| 소모 열량 | release DB `sibc.baseline_lifelog_daily / _window`(`total_kcal_burned`, `active_kcal_burned`, `heartrate_bpm` 등) | 수집 주기 고정 없음. iOS는 백그라운드 전송, Android는 앱 사용 시 전송. 수신 지연 중앙값 4.4일, 90백분위 23.5일 | 습관 층 에너지 지수. 추정하지 않고 도착한 데이터만 사용. 읽기는 release DB, 저장은 loop-dev |

### 3.2 처리 단계

1. **참조 표준화.** 음식명 → 식품코드 → 1인분 영양성분 × 인분 수. 매핑표의 EXACT/BASE/PREFIX 규칙과 검수 열을 유지하고, 목적지는 `meal_food_master`다.
2. **끼니·하루 집계와 완전성 산정.** 끼니 합계, 하루 누적, 기록 끼니 수, 결식 표시, 미기록 끼니 수를 계산한다. 하루를 **완전 / 결식 포함 완전 / 불완전 / 미기록**으로 분류한다. 끼니 안 음식별 기여도(열량·주요 영양소 비중)와 야식·운동 후 2시간 플래그를 함께 계산한다.
3. **소모 데이터 결합.** 웨어러블 baseline DB의 기준일 행을 식이 baseline의 같은 기준일·같은 창 길이 행과 결합한다. 에너지 지수(섭취 − 소모)는 **식이 유효일과 웨어러블 유효일이 겹치는 날만**으로 계산하고, 겹치는 날이 최소 일수 미만이면 지수를 비우고 창 상태를 "섭취만"으로 둔다. 늦게 도착한 웨어러블 데이터는 최근 기준일 행을 매일 재계산해 반영한다(웨어러블 baseline DB는 최근 35일을 재계산한다).
4. **세 층 판정.**
   - 기준 층: KDRIs 또는 개인 소모량(창 상태 "완전"인 주가 4주 이상 쌓인 뒤 최근 4주 평균)으로 하루 섭취 기준량을 정하고, 누적 섭취와 남은 끼니 예상으로 남은 섭취 허용량을 계산한다.
   - 방향 층: 상태 기반 방향 규칙표(§3.4)로 줄임·유지·채움을 정한다.
   - 맥락 층: 국민건강영양조사 참조 모형(§3.8)으로 사용자의 기대 섭취량을 구하고, 창 평균 섭취량의 z값과 집단 백분위를 계산한다. 설명변수는 성별·연령·연령²·신장·체중·주말(창 평균에는 2/7 고정)이며, 신뢰구간은 개인 창 안의 일별 값을 재표집해 구한다.
   - 근거와 트리거의 분리: 알람의 **근거**는 습관 층(전주 기준일 행, 소모 포함), **트리거**는 행동 층(지금 기록한 끼니, 섭취만)에서 가져온다. 웨어러블 지연은 근거에만 영향을 주고 트리거는 영향을 받지 않는다 (§3.7).
   - 영양소별 가이드라인 판정(KDRIs 등 13종)은 의료진용으로 병행 유지한다.
5. **baseline·추세.** 식이 baseline은 웨어러블 baseline DB와 같은 구조로, **매일 그날을 기준일**로 7/14/30/60/180일 창의 섭취·소모·에너지 지수·주요 영양소 평균, 식이 유효일·웨어러블 유효일·동시 유효일, 기록률, 창 상태(완전·섭취만·비교 불가), 집단 백분위, 계산 시각을 저장한다. 하루 경계는 00시~24시(KST)로 두 DB가 같다.
   - 매일 기준일 행은 의료진용 추이와 모니터링에 쓴다.
   - **알람 근거는 기준일 = 지난주 일요일인 행**을 쓴다. 7일 창은 지난주 월~일과 같고, 14일 창은 지난 2주, 30/60/180일 창은 지난주 일요일까지의 장기 추이다. 이번 주 내내 모든 사용자가 같은 기준일의 행을 쓰고, 다음 주 월요일에 기준일이 한 주 앞으로 옮겨간다.
   - 추세는 창 간 비교(7일 vs 14일·30일 평균)와 전주 대비 전전주 변화로 **점진적 초과 / 점진적 감소 / 유지 / 판정 보류**를 낸다.
6. **평가.** 6-a 입력 품질, 6-b 학습 품질, 6-c 집단 참조 품질 (§5). 결과로 사용자별 준비 상태를 갱신한다.
7. **개인화 단계 전환.** 유효 일수와 평가 통과 여부에 따라 **집단 기준 → 개인 baseline → 개인 예측**으로 전환한다.

### 3.3 판정 기준점

- 끼니 기록 시점에 "오늘 누적 + 남은 끼니 예상"을 하루 섭취 기준량과 비교한다.
- **과잉 판정은 불완전한 날에도 가능하다.** 기록된 것만으로 이미 초과면 더 먹었어도 초과다.
- **부족 판정은 완전한 날에만 낸다.** 미기록을 결식으로 읽는 오류를 막기 위함이다.
- 끼니 배분은 고정값이 아니라 개인 패턴에서 가져오며, 패턴이 없으면 집단 평균을 쓴다. 기존 `MEAL_SLOTS` 고정 비율(아침 25 / 점심 30 / 저녁 30 / 간식 5%)은 의료진용 끼니별 판정에서만 유지한다.
- 집단 위치는 두 용도로 한정한다. 첫째, 근거의 설득력(예: "같은 조건 사용자 중 상위 15%"; 사회 규범 피드백은 효과가 입증된 행동변화 기법). 둘째, 기준·방향 층이 "줄임"인데 집단 위치가 하위권이면 데이터 오류 가능성을 의심하는 검증 신호. **집단 위치가 단독으로 판정을 내지 않는다.** 참조는 외부 자료(§3.8)를 쓰고 버전을 고정하며, 내부 코호트 분포는 비교·검증용이다. 참조가 하루 단위 분포이므로 사용자의 다일 평균을 대면 백분위가 중앙으로 쏠린다. 보정 전까지 백분위는 순위 참고용이며 수치 자체를 판정 문구에 쓰지 않는다.

### 3.4 상태 기반 방향 규칙표

우리가 정하는 방향 관련 유일한 산출물이다. 위에서부터 우선한다. 수치 초안은 [direction_rules_draft_20261026.md](direction_rules_draft_20261026.md).

| 상태 근거 | 방향 | 비고 |
|---|---|---|
| 의료진 지정 가이드라인(당뇨·고지혈 등) | 해당 기준의 영양소별 방향 | 최우선 |
| BMI 비만(≥25) | 열량 줄임 | 대한비만학회 기준에 고정 |
| BMI 비만전단계(23~24.9) | 열량 줄임(약) | |
| BMI 저체중(<18.5) | 열량 채움 | |
| BMI 정상 + 체중 지속 증가(30일 평균 vs 180일 평균, 초안 ±1.0 kg) | 줄임 쪽 가중 | 체중계 연동 데이터가 있을 때만 |
| BMI 정상 + 에너지 지수 점진적 초과 | 줄임 쪽 가중 | 에너지 지수 평가(§5.1) 통과 후 |
| 그 외 | 유지 | |

**사용자 목표와의 관계.** 방향은 신체 상태가 정한다. 추후 앱에 목표 설정 기능이 생기더라도 목표는 이 표를 **덮어쓰지 못하며**, 신체 상태가 허용하는 방향 안에서 강도를 조절하는 데만 쓴다. 신체 상태와 충돌하는 목표(예: 표준 체형 사용자의 감량 목표)는 근거로 쓰지 않고 그 사실을 앱에 전달한다.

| 신체 상태(방향 층 결정) | 사용자 목표가 들어왔을 때 |
|---|---|
| 의료진 가이드라인 있음 | 목표 무시. 의료진 기준 우선 |
| BMI 저체중 | "줄임" 목표 차단. 방향은 채움 유지 |
| BMI 정상, 체중 안정 | 방향은 유지. "줄임" 목표는 근거를 만들지 않고 앱에 "표준 체형이므로 감량 근거 없음"을 전달 |
| BMI 과체중·비만 | 방향은 줄임. 목표는 강도·속도 조절에만 사용 |
| BMI 정상, 체중 지속 증가 | 방향은 줄임 쪽 가중. 목표는 참고만 |

**체중 최신성.** `user_master`의 체중은 갱신 이력이 없고 `updated_at`은 체중 변경 시각이 아니다. 체중계 연동 사용자(baseline `weight_kg`)만 추세와 최신성을 알 수 있다. 최신 체중 근거가 오래되면(초안: 90일·180일 경계) 레코드의 신뢰도 등급을 낮춘다.

### 3.5 완전성 보완

규칙 초안은 [completeness_rules_draft_20261026.md](completeness_rules_draft_20261026.md).

- **결식 표시 입력이 있으면 정확도가 가장 크게 오른다.** 없으면 "결식 포함 완전" 분류는 비어 있고 미기록은 불확실로 처리한다.
- 불완전한 날은 "하루 평가"를 내리지 않고 "기록된 끼니 기준 평가"만 낸다.
- 추세 계산에서 완전한 날과 결식 포함 완전한 날은 가중 1, 불완전한 날은 0(초안). 창 안 유효 일수가 최소치 미만이면 **판정 보류**. 기존 `PERIOD_MIN_RECORD_SHARE`(50%) 규칙을 이 용도로 확장한다.
- 개인 데이터가 부족한 초기에는 KDRIs와 집단 평균 소모량을 쓰고, 유효 일수가 쌓이는 만큼 개인 패턴으로 넘어간다. 전환 기준 일수는 §5.2로 정한다.
- **주간 기록률**을 습관 층 레코드에 넣어 앱이 기록 유도의 근거로 쓸 수 있게 한다.
- 유효 일수는 캘린더 일수가 아니라 **완전성 기준을 통과한 일수**로 센다.
- **웨어러블 완전성**도 같은 구조로 둔다. 미착용일은 baseline에 행이 없고, 부분 착용일은 심박 측정 수(`heartrate_bpm`의 `n_records`, 초안 480건 ≈ 8시간)로 걸러 소모 0(비활동)으로 읽지 않는다.
- 창 상태는 식이 유효일과 웨어러블 유효일의 조합으로 **완전 / 섭취만 / 비교 불가**로 나눈다 (§3.7.1).

### 3.6 시간 정렬

섭취 영양이 에너지로 쓰이는 시점을 문헌으로 확인해 소모 열량을 어느 날의 섭취에 맞출지 정했다. 상세는 [time_alignment_literature_20261022.md](time_alignment_literature_20261022.md)와 보고서 `SiBC_식이분석_섭취활동_시간정렬_문헌조사보고서_20261022.docx`.

| 결정 항목 | 채택값 | 근거 |
|---|---|---|
| 정렬 단위 | **같은 날 00시~24시(KST).** 하루 뒤로 밀지 않음 | 혼합 식사 흡수는 4~6시간(늦어도 8시간) 내 완료, 식후 저장분은 그날 밤~다음 날 아침에 동원, 같은 날 섭취–소모 상관은 원래 없고 주 단위 이상에서 나타남 |
| 하루 경계 | 자정(로컬). 웨어러블 baseline DB와 동일. 야식은 경계 이동 대신 **플래그**(21시 이후 또는 취침 전 N시간 내, `LATE_NIGHT_SNACK`) | 식이조사·웨어러블 모두 자정 집계. 늦은 식사의 문제는 날짜 귀속이 아니라 시간 자체 |
| 운동 후 창 | 운동 종료 후 2시간 플래그. 열량 판정은 완화하지 않고(당일 합산, 보상 섭취 없음) 단백질·탄수 해석에만 보조 | 단백질 직후~2시간, 급속 글리코겐 회복 4시간 내. 좁은 창의 중요성에는 반론 있음 |
| 에너지 지수 해석 단위 | 7일 이상 창의 평균과 창 간 비교 | 하루 단위 균형은 노이즈 |
| 개인 baseline 최소 유효 일수 | 영양소별 개인 내/간 분산 비율로 산정. 초기 가설 에너지·다량영양소 7일 | §5.2 A형 평가로 확정 |

끼니 단위 상관 학습은 이 정렬 규칙과 충분한 데이터가 확보된 뒤의 2단계 과제다.

### 3.7 전주 기반 알람 근거

웨어러블 수집이 사용자별로 들쭉날쭉하고(수신 지연 중앙값 4.4일) 하루 단위 균형은 문헌상 노이즈이므로, "오늘 소모 대비 오늘 섭취"는 근거로 쓰지 않는다.
알람 근거는 **기준일 = 지난주 일요일인 baseline 행**(7일 창 = 전주 월~일)에서 만들고, 끼니 기록 시점에는 그 근거를 실시간 섭취 트리거와 결합한다.

#### 3.7.1 근거 주의 상태

| 창 상태 | 조건(초안, 7일 창) | 가능한 근거 |
|---|---|---|
| 완전 | 식이 유효일 ≥ 4일 AND 웨어러블 유효일 ≥ 4일 AND 동시 유효일 ≥ 3일 | 에너지 지수, 섭취 판정, 추세 모두 |
| 섭취만 | 식이 유효일 ≥ 4일, 웨어러블 조건 미달 | 섭취 판정(KDRIs·개인 기준)과 섭취 추세만. 에너지 지수 없음 |
| 비교 불가 | 식이 유효일 < 4일 | 알람 근거 없음. 기록률만 산출(기록 유도용) |

식이 유효일은 주요 끼니(아침·점심·저녁)가 기록되었거나 결식 표시가 된 날, 웨어러블 유효일은 착용 기준을 넘긴 날이다. 14/30/60/180일 창의 조건은 완전성 규칙 초안 §3에 있다. 최소 일수는 초안이며 §5.2 평가로 확정한다.

#### 3.7.2 주간 지표

| 구분 | 지표 | 계산 |
|---|---|---|
| 섭취 | 열량, 탄·단·지 비율, 단백질, 나트륨, 당류, 포화지방 등 판정 영양소의 일평균 | 식이 유효일 평균. 끼니 배분, 결식·야식 빈도, 주중·주말 평균, 기록률 포함 |
| 소모 | 총 소모 열량 일평균, 활동 열량 일평균 | 웨어러블 유효일 평균 |
| 에너지 지수 | 섭취 − 소모의 일평균 | 동시 유효일만 사용. 창 상태 "완전"에서만 산출 |
| 판정 | 영양소별 부족·적절·과잉 | 주간 평균값에 기존 가이드라인 판정 규칙 적용 |
| 집단 위치 | 영양소별 백분위 | §3.8 참조 모형 |

#### 3.7.3 세 가지 비교

| 비교 | 질문 | 산출 |
|---|---|---|
| 기준 비교 | 전주 섭취가 필요량 대비 어떤가 | 영양소 판정, 열량 대비 %(KDRIs 또는 개인 소모량) |
| 자기 비교(추세) | 전주가 전전주·최근 4주 평균 대비 어떻게 바뀌었나 | 변화량·변화율, 추세 판정(점진적 초과·점진적 감소·유지·불가) |
| 상태 비교 | 신체 상태가 어느 방향을 요구하나 | 방향 층(§3.4) |

자기 비교만 쓰면 두 주 모두 과잉인 사용자가 "유지"로 나오고, 기준 비교만 쓰면 개선 중인 사용자에게 계속 "줄임"이 나간다. 셋을 결합해 **상태**는 기준 비교, **방향**은 상태 비교, **긴급도**는 자기 비교에서 가져온다.

#### 3.7.4 결론 종류와 성립 조건표 (앱이 대조할 판단 기준)

앱은 습관 층·행동 층의 결과 값을 아래 조건에 대조해 결론을 얻는다. 이 표는 판단 기준으로 버전 관리한다.

| 결론 종류 | 성립 조건(초안) | 비고 |
|---|---|---|
| 식이조절 필요(줄임) | 방향 = 줄임 AND (전주 에너지 지수가 균형 폭 위 OR 전주 열량 판정 과잉) | "섭취만" 주에는 열량 판정으로 대체 |
| 식이조절 긴급 | 위 조건 AND 추세 = 점진적 초과 | 두 주 연속 악화. 우선순위 최상 |
| 영양섭취 필요(채움) | 방향 = 채움 AND (전주 지수가 균형 폭 아래 OR 열량·단백질 판정 부족) | 저체중·체중 감소 사용자 |
| 영양소 단위 조절 | 특정 영양소(나트륨·당류·포화지방 등) 과잉이 2주 연속 | 열량과 무관. 의료진 가이드라인 지정 시 우선 |
| 개선 확인(긍정) | 전주가 전전주 대비 개선되어 "유지" 범위에 들어옴 | 행동변화 유지에 필요. 줄이라는 알람만 있으면 기록률이 떨어짐 |
| 기록 유도 | 창 상태 = 비교 불가 | 식이분석 결과가 아니라 기록률이 근거 |

결론 종류마다 우선순위를 두고, 결과 값 레코드에는 근거 기준일(지난주 일요일), 창 상태, 계산 시각, 기준 버전을 넣어 앱이 같은 조건으로 재현할 수 있게 한다.

#### 3.7.5 끼니 기록 시점과의 결합

전주 근거는 "이번 주 동안 유효한 상태"이고, 끼니 기록은 그 상태를 지금 이 끼니에 적용하는 트리거다.

- 트리거(섭취만, 실시간): 이 끼니 열량이 본인 평소 같은 끼니 평균 또는 하루 기준량의 끼니 몫보다 일정 비율 이상 크거나, 오늘 누적이 하루 기준량을 넘음.
- 결합: 근거 = 줄임 AND 트리거 충족 → "이 끼니를 줄이라"는 끼니 단위 근거. 근거 = 채움이면 트리거는 반대 방향(끼니가 평소보다 작음, 누적 부족).
- 상쇄: 이번 주 현재까지 누적 섭취가 전주 같은 시점보다 이미 낮으면 줄임 근거를 보류한다. 전주 근거가 이번 주 행동으로 이미 해소된 경우를 거른다.

#### 3.7.6 보완 규칙

- **주 전환과 재계산.** 전주는 월요일 0시에 닫히지만 웨어러블 데이터는 그 뒤에도 들어온다(월요일 시점에는 절반 이상의 사용자에서 소모 데이터가 비어 있음). 최근 기준일 행을 매일 재계산하고, 근거 레코드에는 계산 시각과 당시 창 상태를 남긴다. 웨어러블 baseline DB가 최근 35일을 재계산하므로 식이 baseline도 같은 구간을 재계산한다.
- **에너지 지수의 균형 폭.** 섭취 과소보고와 소모 오차 때문에 지수 절대값은 신뢰가 낮다. 초기값으로 일평균 ±150 kcal(또는 소모의 ±8%) 안은 "균형"으로 보고 그 밖에서만 방향을 낸다. §5.1 평가로 확정한다. kcal 수치로 제시하지 않는 원칙은 유지한다.
- **추세 임계값.** 전주 대비 전전주 변화의 초기값은 열량 ±5% 또는 지수 ±100 kcal/일. 인접 주 판정 일치율로 안정성을 평가한다.
- **개인 기준으로의 전환.** 처음 몇 주는 KDRIs 기준만 쓴다. 창 상태 "완전"인 주가 4주 이상 쌓이면 최근 4주 평균 소모를 개인 기준량으로 쓰고, 자기 비교의 기준도 4주 평균으로 넓힌다. 준비 상태 플래그에 기록한다.
- **주말과 특수 주.** 근거 주는 월~일로 잡아 주말 섭취를 포함한다. 주중·주말 평균을 보조 지표로 분리해 "주말에만 초과" 패턴을 드러낸다. 명절·연휴가 낀 주는 추세 비교에서 제외하거나 표시한다.
- **알람 피로.** 알람 횟수는 앱 영역이지만, 근거 레코드의 우선순위와 "이번 주 같은 유형 트리거 누적 횟수"로 앱이 제한할 수 있게 한다.

#### 3.7.7 결정 사항

| 항목 | 결정 | 비고 |
|---|---|---|
| 근거 주 범위 | 월~일 | 주말 섭취를 빼면 과잉 패턴을 놓침. 주중·주말은 보조 지표 |

### 5.2 학습 품질 — 필요 데이터량과 성능 (6-b)

학습 대상을 두 종류로 나눈다.

| 종류 | 학습 대상 | 성격 | 예 |
|---|---|---|---|
| A. 기술 통계형 | 개인 baseline과 패턴 | 평균·비율 추정 | 평소 하루 섭취 열량, 끼니 배분 비율, 결식·야식 빈도, 시간대별 소모량 |
| B. 예측·분류형 | 다음 행동이나 추세의 예측 | 모델 학습 | 추세 분류, 다음 끼니 섭취량 예측, 방향 이탈 예측 |

**필요 데이터량.**

- A형: 개인 내 변동 계수와 허용 오차로 필요 유효 일수를 산정한다(영양역학의 표준 방법). 유효 일수를 1일부터 늘려가며 추정치가 최종값(예: 90일 평균)에 수렴하는 **안정화 곡선**을 그리고, 오차가 기준 아래로 떨어지는 지점을 전환 일수로 한다. 문헌상 에너지·다량영양소는 수 일~2주, 변동이 큰 미량영양소는 수 주 이상이 필요하므로 이 범위를 우리 데이터로 확인한다.
- B형: 사용자당 학습 데이터를 늘려가며 검증 성능을 측정하는 **학습 곡선**. 사용자 수가 수백 명이고 개인당 데이터가 적으므로 **집단 모델 + 개인 보정** 구조를 쓰고, 개인 보정이 유의하게 기여하기 시작하는 데이터량을 찾는다. 검증은 **과거로 학습하고 미래로 검증**한다(요일·계절 효과).

### 5.4 사용 가능 기준

- 절대값이 아니라 **집단 기준 대비 유의한 우위**로 정한다. 개인 패턴이 KDRIs·집단 평균보다 오차를 유의하게 줄일 때만 개인 패턴을 사용한다.
- 사용자별 **준비 상태 플래그**(집단 기준 / 개인 baseline / 개인 예측)를 두고 유효 일수와 성능 통과로 전환한다. 이 플래그가 레코드의 신뢰도 등급에 들어간다.
- 거짓 알람률 상한, 오차 감소 폭, 최소 유효 일수는 **파일럿 측정 전에 확정**하고 결과를 보고 바꾸지 않는다.
- 사용자 수와 데이터가 늘면 정기 재평가하여 기준과 전환 일수를 갱신한다.

## 6. 산출 레코드와 판단 기준 명세 (앱 연동 시 전달)

식이분석이 **제공하는 것**이다. 앱 개발 파트는 결과 값을 판단 기준에 대조해 결론을 얻고 알람·표시로 전달한다.

- **결과 값 레코드 명세:** 행동 층·습관 층 레코드의 열 정의(§4), 각 분류값의 종류와 뜻, 갱신 시점(끼니 기록 즉시 / 매일 기준일 / 지난주 일요일 행), 신뢰도 등급의 뜻
- **판단 기준 명세:** 결론 종류와 성립 조건표(§3.7.4), 우선순위, 끼니 트리거·상쇄 조건(§3.7.5), 영양소별 판정 구간, 방향 규칙표(§3.4). 모두 버전을 붙여 git에서 관리하고, 레코드의 기준 버전과 짝지어 전달
- 사용자 목표가 앱에 생기더라도 방향 규칙표(§3.4)를 덮어쓰지 않고 신체 상태가 허용하는 범위 안에서 강도 조절에만 쓴다는 원칙

**있으면 결과 값의 정확도가 오르는 것 (설계 가정, 요청이 아님).** 결식 표시 입력이 있으면 미기록과 결식을 구분할 수 있고, 체중이 주기적으로 갱신되면 방향 층의 BMI 판단이 최신이 된다. 둘 다 없어도 결과 값은 나오며, 그 경우 신뢰도 등급으로 불확실성을 표시한다.

## 8. 작업 순서

순서는 "무엇이 무엇에 의존하는가"와 "무엇이 외부 대기 시간을 먹는가"로 정했다. 문헌 조사와 데이터 확인·외부 자료 확보를 먼저 끝냈고, 다음은 지금 있는 데이터로 행동 층·습관 층의 핵심을 만든 뒤 웨어러블·집단 참조를 붙이는 순서다. 평가는 측정 전에 기준을 확정해 병행한다.

| 8. 평가 기준 확정과 2차 측정 | 6단계 전에 거짓 알람률 상한, 집단 기준 대비 오차 감소 폭, 최소 유효 일수를 문서로 확정. 6·7단계 결과가 쌓인 뒤 지수 타당성(체중 변화 상관), 결측 민감도, 추세 안정성, 학습 곡선 측정 → 준비 상태 플래그 규칙 확정 | 평가 기준 문서(측정 전), 평가 2차 결과, 준비 상태 규칙 | 예정 |
| 9. 개인화 전환과 예측형 학습 | 준비 상태 플래그에 따라 집단 기준 → 개인 baseline 전환, 데이터 축적 후 예측형 모델 도입 | 전환 로직, 예측 모델 | 예정 |

### 8.3 순서의 이유

- **구조를 먼저 검증한다.** 4·5단계는 지금 데이터로 끝까지 만들 수 있고, 여기서 레코드 구조와 판정 규칙의 문제가 드러난다.
- **노이즈가 큰 입력은 뒤에 붙인다.** 소모 열량과 에너지 지수는 오차가 크고 평가가 필요하므로 안정된 섭취 쪽 구조 위에 올린다.
- **평가는 측정 전에 기준을 적는다.** 결과를 보고 기준을 바꾸지 않기 위해 8단계의 기준 확정을 6단계 앞에 둔다.

### 8.4 병행 트랙

| 트랙 | 내용 | 단계 |
|---|---|---|
| A 데이터 | 참조 표준화·매핑표 | 3 |
| B 로직 | 행동 층 → 습관 층 → 웨어러블 결합 → 맥락 층 | 4, 5, 6, 7 |
| D 평가 | 1차 측정 → 기준 확정 → 2차 측정 → 전환 규칙 | 5, 8, 9 |

A·D는 B와 나란히 갈 수 있다. 5단계의 개인 내 변동, 안정화 곡선, 내부 코호트 분포는 현재 loop-dev의 식이 기록으로 1차 실측이 가능하다(개발 테스트 데이터라 수치는 참고용이지만 절차 검증에는 충분하다).
진행상황 보고서(2026-10-21)의 11월 일정은 이 순서에 맞춰 다시 잡으며, 4·5단계 완료가 새 1차 마일스톤이다.
