# SiBC 웨어러블(라이프로그) 기반 건강검진 예측 모델 구축 계획

## 문서의 목적과 읽는 방법

이 문서는 SiBC가 보유한 `discovery.disc_lifelog_user_*` 데이터 16개와, 첨부된 **Samsung SDK 취득가능데이터 통합 활용 전략 검토수정본**의 `01_통합 매트릭스`를 근거로 작성한 모델 구축 계획서다. 지금 하는 일은 모델을 학습하거나 성능을 발표하는 일이 아니라, **어떤 데이터를 어떤 조건에서 모델에 쓸 수 있는지, 무엇이 부족한지, 어떤 검증을 통과해야 모델을 사용할 수 있는지**를 정하는 일이다.

이 문서에서 다음 표현은 엄격히 구분한다.

| 표현 | 의미 |
|---|---|
| 현재 보유 | release DB 스키마 또는 감사 결과에서 확인된 데이터 |
| 입력 후보 | 시간·품질·출처 조건을 통과하면 모델 특징으로 사용할 수 있는 값 |
| 직접 측정 요약 | 워치·연결기기·입력값을 최근 기간으로 요약한 관찰값. 모델 예측이 아님 |
| 예측 가능성 | 충분한 시간 정렬 정답과 독립 검증을 전제로 한 연구·개발 가능성 |
| 검증된 예측 | 독립 평가를 통과해 `pred_*`로 제공 가능한 모델 결과 |

## 1. 결론 요약

### 1.1 프로젝트 목적

SiBC의 목표는 건강검진값을 그대로 복사하거나 단순히 과거 결과를 표시하는 것이 아니다. 예측 기준시점 이전에 수집된 웨어러블/라이프로그를 사용해 건강검진 관련 현재 상태를 추정하는 것이다. 적용 대상은 다음 두 경우를 모두 포함한다.

1. **건강검진 이력이 없는 사용자**: 충분한 웨어러블 데이터만으로 건강검진 관련 값을 추정하는 M0(웨어러블 전용) 경로
2. **건강검진 이력이 있는 사용자**: 과거 실제 건강검진값과 그 이후 누적 웨어러블을 함께 이용해 최신 상태 또는 변화량을 추정하는 M1/M2(개인화) 경로

건강검진의 시점과 웨어러블의 시점이 같은 날일 필요는 없다. 그러나 모델을 학습·평가할 때에는 반드시 시간 순서를 지켜야 한다. 즉, 과거 웨어러블로 이후 건강검진을 예측해야 하며, 이후 데이터를 과거 검진의 입력으로 사용하면 안 된다.

### 1.2 현재 데이터로 가능한 일과 불가능한 일

| 구분 | 현재 가능한 일 | 현재 불가능하거나 보류해야 하는 일 |
|---|---|---|
| 데이터 감사 | 16개 lifelog의 스키마·시간 필드·참조 키·수집량·출처 필드를 점검 | 데이터가 있다는 이유만으로 임상적으로 같은 의미라고 단정 |
| 사용자 출력 | 최신 실제 건강검진값(`actual_*`)과 최근 웨어러블 직접 측정 요약(`measured_*`)을 분리 출력 | 직접 측정값을 AI 건강검진 예측값으로 표시 |
| 모델 설계 | M0/M1/M2, 특징, 알고리즘 후보, 검증 지표, 보류 기준 설계 | 현 시점 release 결과만으로 모델 성능을 주장 |
| 지도학습 | 후속 건강검진이 시간상 올바르게 연결되면 가능 | 검진 이후 웨어러블로 과거 검진을 맞히는 방식의 학습 |

2026-07-30 release 프로토타입에서는 건강검진 정답 이전 90일 웨어러블과 연결된 사용자가 2명뿐이었다. 초기 정책의 최소 학습 사용자 100명과 독립 평가 사용자 30명에 못 미쳐 모델 상태는 `BLOCKED_BY_DATA`였다. 이 문서 작성 시점(2026-08-14)에는 기존 lifelog 유형의 신규 행이 계속 적재되는 정황이 확인됐지만, **시간 정렬된 건강검진 정답이 충분해졌는지는 별도 재감사가 필요하다.**

### 1.3 가장 중요한 판단

현재 데이터가 계속 누적되더라도, 다음 건강검진 결과가 연결되지 않으면 건강검진 예측 모델의 신뢰성은 확보되지 않는다. 모델 성능 향상의 첫 번째 과제는 복잡한 알고리즘이 아니라 다음 건강검진 `measuredDt`와 그 이전 웨어러블 구간을 지속적으로 연결하는 종단 데이터 구조다.

## 2. 데이터 원천, 시간, 보안의 비협상 원칙

### 2.1 건강검진 정답

건강검진 정답의 유일한 논리 원천은 다음과 같다.

```text
discovery.disc_medical_user_info.user_health_sn.health_info_data
```

구현상 사용자 연결이 필요하면 `disc_medical_user_info.user_health_sn`에서 참조한 `disc_health_user_info.user_health_sn`을 통해 `health_info_data`를 읽는다. 이는 다른 건강검진 데이터 원천과 비교·대조·병합하는 작업이 아니다.

건강검진의 임상 측정일은 반드시 다음 필드를 사용한다.

```text
health_info_data[].measuredDt
```

`ins_dt`, `upd_dt`, 적재 시각은 데이터 계보·신선도 확인에는 사용할 수 있지만, 임상 건강검진 측정일로 대체하면 안 된다.

### 2.2 데이터 환경과 보안

- 최초 프로토타입 환경은 `release`다. 한 번의 실행에서 하나의 `--data-env`만 선택한다.
- `release`, `dev`, `stg`는 사용자 수준 데이터·라벨·특징·모델을 병합하지 않는다.
- 선택 DB는 읽기 전용 세션으로만 사용하며, 데이터 변경 SQL은 금지한다.
- `.env.*`의 비밀값, 원본 사용자 ID, 원시 건강검진 JSON, 개인별 민감 로그를 산출물·Git·프롬프트에 저장하지 않는다.
- 원본 `user_id`는 메모리에서 가명키로 변환한 뒤에만 스냅샷과 결과 파일에 보관한다.

### 2.3 시간 누출 방지

건강검진 정답의 시점을 `T`라고 하면, 해당 정답의 모델 입력에는 `T` 이전 데이터만 사용한다.

```text
허용:  [T - 관측창, T) 의 웨어러블 특징 → T의 실제 건강검진값
금지:  T 이후 웨어러블 특징             → T의 실제 건강검진값
```

예측 기준시점 이후 정보가 특징에 들어가면 실제 서비스에서는 알 수 없는 미래를 모델이 이미 알고 있게 된다. 이 경우 오차가 작아 보여도 실제 적용 성능은 재현되지 않는다.

## 3. 현재 SiBC lifelog 16개 데이터의 구조와 활용 판단

### 3.1 `*_sn` 연결 구조

`disc_lifelog_user_info`는 사용자의 lifelog 원천·기기·시간대 정보를 담는 상위 테이블이다. 나머지 측정 테이블은 `user_lifelog_sn`을 통해 이 테이블에 연결된다. 따라서 모델 데이터셋을 만들 때는 각 측정 테이블만 읽지 말고 상위 테이블의 출처·기기·시간대 정보를 함께 결합해야 한다.

```text
disc_lifelog_user_info (user_lifelog_sn, user_id, platform, device, timezone, raw JSON)
  ├─ activity / bloodglucose / bloodpressure / body_info / bodyfat
  ├─ calories / food / grip_strength / heartrate / meal / mood
  ├─ oxygen_saturation / step
  └─ sleep (user_sleep_sn)
       └─ sleep_detail (user_sleep_sn)

oxygen_saturation.user_sleep_sn ──(선택적 연결)──► sleep.user_sleep_sn
```

확인 결과 `sleep_detail.user_sleep_sn → sleep.user_sleep_sn`은 선언된 외래키다. 산소포화도의 `user_sleep_sn`은 선택적으로 채워지지만, 채워진 레코드는 수면 세션과 연결되는지 매 실행에서 점검해야 한다. 산소포화도와 수면의 `user_lifelog_sn` 값이 동일하지 않을 수 있으므로, 최종 사용자 일치 여부는 상위 `disc_lifelog_user_info.user_id` 기준으로 확인한다.

- `disc_lifelog_user_info`는 149,460행, 411명의 사용자, 최종 적재시각 2026-08-14를 보유했다.

따라서 ‘기존 항목만 누적된다’는 우려는 일부 타당하지만, 적어도 칼로리·기분 데이터는 새로 들어오기 시작했다. 다만 신규 소스의 최초 날짜가 매우 최근이므로, **새로운 데이터 유형이 생겼다**는 사실만으로 건강검진 예측 입력으로 즉시 사용하면 안 된다. 충분한 관측 기간, 정확한 의미, 건강검진 정답과의 시간 정렬을 다시 감사해야 한다.

## 4. Samsung Health Data SDK 취득 가능 항목과 통합 판단

### 4.1 적용 범위

첨부 파일의 `01_통합 매트릭스`에서 **Samsung / Health Data SDK** 열이 `○` 또는 `△`인 항목만 아래에 포함했다. `✕`, `-`, 빈칸은 모델 입력 후보에서 제외했다. Sensor SDK만 가능한 항목(예: HRV, ECG, EDA)은 이번 Data SDK 범위에 포함하지 않는다.

`○`는 SDK 경로상 취득 가능, `△`는 기기·권한·설정·국가·기록 생성·사용자 조작 등 조건부 취득을 뜻한다. 두 경우 모두 사용자의 권한과 실제 데이터 생성은 별도 조건이다.

## 5. 건강검진 목표별 모델 구축 방향

### 5.1 목표 항목의 우선순위

| 우선도 | 건강검진 목표 | 목표 유형 | 현재 직접 대응 데이터 | 모델화 판단 |
|---|---|---|---|---|
| 1 | 수축기/이완기 혈압 | 회귀 | 혈압, 심박, 수면, 활동, 체성분 | 가장 먼저 검토. 직접 웨어러블 혈압과 건강검진 혈압을 별도 값으로 유지 |
| 1 | 체중, BMI, 허리둘레 | 회귀 | 체중·체성분, 활동, 걸음, 수면 | 높은 가능성. 특히 변화량·개인화 경로에 적합 |
| 2 | 공복혈당 | 회귀 | 혈당, 식사 상태, 활동, 수면, 체성분 | 가능성은 있으나 공복 여부·측정 출처 없이는 정밀 수치 예측에 제한 |
| 2 | 중성지방, HDL, LDL, 총콜레스테롤 | 회귀 | 활동, 운동, 체성분, 수면, 시간 있는 영양 | 데이터 보완 후 연구. 약물·음주·공복 상태가 큰 교란요인 |
| 3 | 대사위험 | 분류 | 혈압·비만·혈당·활동·수면 | 임상 정의·임계값·사건 수 승인 후 진행 |
| 3 | 간기능 위험 | 분류 | 체성분·활동·수면·영양 | 음주·약물·기저질환 정보가 없으면 탐색적 수준 |

키, AST, ALT, GGT, 혈색소, eGFR, 크레아티닌, 요단백 등은 건강검진 원본에서 정규화 가능하더라도, 현재 웨어러블만으로 수치를 정확히 예측한다고 가정하지 않는다. 임상적·생활습관적 교란요인이 큰 항목은 충분한 근거와 라벨 정렬 전에는 ‘향후 연구 후보’로 유지한다.

### 5.2 M0/M1/M2의 구체적 정의

| 경로 | 예측 시점 | 입력 | 정답 | 비교해야 하는 기준선 | 사용자 출력 |
|---|---|---|---|---|---|
| M0 웨어러블 전용 | 현재 시점 `T0` | `T0` 이전 웨어러블 특징만 | `T0` 이후 최초 건강검진 | 인구 중앙값/연령·성별 기준선, 단순 선형모델 | `pred_*`, 구간, coverage, ABSTAIN |
| M1 개인화 절대값 | 이전 검진 `E0` 후 현재 `T0` | `E0` 실제값 + `(E0,T0]` 웨어러블 + 경과시간 | `T0` 이후 다음 건강검진 `E1` | 이전 검진값 그대로 유지(carry-forward), M0 | `pred_*`, 이전값 대비 변화, 구간 |
| M2 개인화 변화량 | 반복 검진 구간 | `E0` 실제값 + `(E0,E1)` 웨어러블 | `E1 - E0` 변화량 | 변화 없음(0), 이전값 유지 | 변화량과 예측 절대값, 구간 |

M1은 과거 건강검진값을 그대로 보여 주는 것보다 좋아야 한다. M2는 변화 없음 기준선보다 좋아야 한다. 이 기준을 이기지 못하면 복잡한 모델을 사용하지 않는다.

## 6. 특징(입력 지표) 설계와 계산 방법

### 6.1 공통 관측창

예측 기준시점 `T`의 직전 7일, 30일, 90일을 기본 관측창으로 사용한다. 데이터가 충분한 항목에 한해 180일 창을 추가로 비교한다. 모든 특징에는 창 길이와 유효일 수를 함께 저장한다.

| 지표군 | 정의/계산 | 의미 | 사용 시 주의 |
|---|---|---|---|
| 유효일 수 | `window` 내 최소 1개 유효 관측이 있는 날짜 수 | 실제 관측의 지속성 | 행 수가 많아도 한 날에 몰렸으면 유효일은 낮음 |
| 수준(중앙값) | `median(x_t)` | 극단값에 강한 최근 대표 수준 | 서로 다른 기기·방법을 섞기 전 출처 분리 |
| 평균 | `mean(x_t)` | 전체 기간의 평균 수준 | 이상치·불규칙 관측에 민감 |
| 변동성 | `sd(x_t)` 또는 `IQR(x_t)` | 일상 변동과 안정성 | 매우 적은 관측 수에서는 산출하지 않음 |
| 추세 | 시간 대비 값의 선형 회귀 기울기 `slope(x_t ~ t)` | 증가/감소 방향 | 관측일 수·기간 충족 시에만 계산 |
| 최근 변화 | `median(last 7d) - median(previous 23d)` | 최근 생활 변화 | 두 구간 모두 최소 유효일 필요 |
| 규칙성 | 취침·기상·식사·운동 시각의 표준편차/원형 분산 | 생활 리듬 | 시간대 표준화와 실제 이벤트시각 필요 |
| 결측/출처 | 결측률, 기기별 비율, 수동입력 비율 | 데이터 신뢰도·선택편향 | 결측=정상/미측정으로 해석 금지 |

### 6.2 소스별 우선 특징

| 특징 블록 | 계산할 지표 | 주요 적용 목표 |
|---|---|---|
| 활동·걸음 | 일별 걸음/거리/활동시간/칼로리의 평균·중앙값·유효일·변동성·7일 대비 30일 변화·운동 없는 날 비율 | 체중/BMI/허리둘레, 혈압, 중성지방 |
| 운동 세션(추가 수집) | 주당 세션 수, 총 시간, 운동 종류별 시간, 심박 반응, 회복, VO₂max 추세 | 혈압, 체성분, 지질, 대사위험 |
| 심박 | 중앙값, 10/90 분위수, 안정 구간 심박, 일중/수면·활동별 분포 | 혈압, 대사위험 보조 |
| 혈압 직접 측정 | 수축기/이완기 중앙값, 측정 횟수·유효일, 변동성, 기기·보정 상태 | 혈압 개인화, 직접 요약 |
| 체성분 | 체중·체지방률·골격근량·허리둘레·내장지방 수준과 추세 | 체중/BMI/허리둘레, 대사위험 |
| 수면 | 수면시간, 취침·기상 시각, 규칙성, 분할수면, 수면 부채 | 혈압, 혈당, 체중, 대사위험 보조 |
| 수면 단계 | 단계별 총 시간/비율, 각성시간, 분절 횟수, 최근 변화 | 혈압, 혈당, 대사위험 보조 |
| SpO₂ | 수면 연결 측정의 중앙값·하위 분위수·측정일·반복 저값 패턴 | 수면/호흡 문맥, 안전 보조 |
| 혈당 | 식사 상태별 분리 수준·변동성, 측정 시간대 | 공복혈당 보조 |
| 영양(시간 확보 후) | 열량·탄수화물·단백질·지방·나트륨·당의 일/주 합·식사 시간 규칙성 | 혈당, 중성지방, 체중 |
| 기분/에너지 | 일별 기분·에너지·건너뜀 비율 및 수면/활동과의 결합 | 이행성·결측 패턴 보조 |

### 6.3 결측 처리 원칙

- 임상시간이 없는 `food`, `meal`은 실제 식사시각이 별도로 확보될 때까지 시간 정렬 학습 특징으로 사용하지 않는다.
- 결측값을 자동으로 ‘정상’이나 ‘0’으로 바꾸지 않는다. 수동입력·기기미착용·동기화 실패를 구분할 수 있으면 결측 사유를 별도 특징으로 둔다.
- 수치형 값의 모델 내 결측 처리는 학습 폴드 안에서만 수행한다. 중앙값 대치, 결측 지시변수, 결측을 지원하는 트리 모델을 사전에 비교할 수 있다.
- 동일 Samsung Health 이벤트가 여러 경로로 들어오면 `source_system`, `source_record_id`, 시간, 값, 기기, 앱 버전으로 중복 후보를 찾고, 중복 여부가 불명확하면 제거 대신 플래그로 남긴다.

## 7. 데이터 품질·준비도 지표

모델을 만들기 전에 아래 지표를 매 실행에 계산한다. 이 지표들은 ‘모델 성능’이 아니라 모델 학습 가능 여부를 판단하는 지표다.

| 지표 | 계산 | 의미 | 사용 결정 |
|---|---|---|---|
| 원천 행 수 | 테이블별 `COUNT(*)` | 수집량 변화 | 급감·급증 시 적재 점검 |
| 사용자 수 | 가명 사용자 기준 `nunique(user_key)` | 적용 가능 집단 크기 | 적은 경우 일반화 주장 금지 |
| 최신성 | `max(event_time)` | 실제 신규 데이터 적재 여부 | 적재시각과 이벤트시각을 분리 확인 |
| 유효일 수 | 사용자·창별 관측 날짜 수 | 지속 착용/기록 여부 | coverage gate의 핵심 |
| 시간 정렬률 | `정답 전 유효 웨어러블 사용자 / 라벨 사용자` | 지도학습 가능성 | 최소 학습/테스트 표본 gate |
| 출처 완결성 | 출처/기기/방법 비결측 비율 | 직접값의 해석 가능성 | 낮으면 층화 또는 제외 |
| 중복 의심률 | 중복 후보 행 / 전체 행 | 과대가중 위험 | 중복 정책 적용 |
| 비정상값률 | 생리적 범위·sentinel 탈락 행 / 전체 행 | 측정 품질 | 임계값 사전 문서화 |
| 라벨 완결성 | 목표 건강검진값 비결측 사용자 수 | 목표별 학습 가능성 | 목표별 독립 판정 |
| 다음 검진 연결률 | 예측 기준시점 후 정답이 생긴 사용자 / 예측 고정 사용자 | 전향 검증 가능성 | M0/M1/M2 개선의 핵심 |

예시 coverage gate는 ‘30일 창에서 최소 7일 이상’, ‘90일 창에서 최소 30일 이상’처럼 사전 정의한다. 이 값은 모델 성능을 높이기 위해 사후에 낮추지 않으며, 목표·소스별로 임상·운영팀이 승인해야 한다.

## 8. 모델 후보와 성능 지표

### 8.1 모델 후보 선정 원칙

처음부터 복잡한 딥러닝 모델을 사용하지 않는다. 현재 예상 표본 수와 해석·재현성 요구를 고려해 단순 기준선부터 비교한다.

| 문제 | 기준선 | 후보 모델 | 선택 이유 |
|---|---|---|---|
| 연속형 수치 회귀 | 인구 중앙값, 이전 건강검진값 유지(M1), 최근 직접 측정값 | Elastic Net, Histogram Gradient Boosting | 선형·희소 특징과 비선형·상호작용을 모두 비교 가능 |
| 이분 위험도 분류 | 유병률, 사전 승인된 단순 규칙 | 보정된 Logistic Regression, 보정된 Histogram Gradient Boosting | 확률 보정·설명 가능성·비선형 비교 |
| 변화량 회귀(M2) | 변화 없음(0), 이전값 유지 | Elastic Net, 강건/Histogram Gradient Boosting 회귀 | 개인 내 변화량과 비선형 관계 비교 |

모델 후보는 교육·검증 데이터 안에서만 선택한다. 봉인된 최종 테스트 집합은 마지막 한 번의 성능 확인에만 사용한다.

### 8.2 회귀 성능 지표

연속형 건강검진 항목(혈압, 체중, BMI, 공복혈당, 지질 등)에 사용한다. `y_i`는 실제 건강검진값, `ŷ_i`는 모델 예측값, `n`은 독립 평가 사용자 수다.

| 지표 | 계산식 | 의미 | 좋은 결과의 방향 |
|---|---|---|---|
| MAE | `MAE = (1/n) Σ |y_i - ŷ_i|` | 평균 절대 오차. 단위가 원래 건강검진 단위와 같아 직관적 | 작을수록 좋음 |
| RMSE | `RMSE = sqrt((1/n) Σ (y_i - ŷ_i)^2)` | 큰 오차에 더 큰 벌점을 주는 오차 | 작을수록 좋음 |
| R² | `1 - Σ(y_i-ŷ_i)^2 / Σ(y_i-ȳ)^2` | 평균만 예측하는 기준보다 설명한 분산의 비율 | 클수록 좋음. 음수 가능 |
| Bias | `(1/n) Σ(ŷ_i-y_i)` | 체계적으로 높게/낮게 예측하는 정도 | 0에 가까울수록 좋음 |
| Calibration-in-the-large | `mean(ŷ) - mean(y)` | 전체 평균 수준의 과대·과소 예측 | 0에 가까울수록 좋음 |
| Calibration slope | 독립 평가에서 `y ~ α + βŷ`의 `β` | 예측 분포가 너무 좁거나 넓은지 | 1에 가까울수록 좋음 |
| PICP | `포함된 실제값 수 / 예측구간 수` | 예: 90% 예측구간이 실제값을 포함한 비율 | 선언한 구간 수준에 가까울수록 좋음 |

MAE가 작아도 특정 사용자군에서 오차가 크거나 예측구간이 지나치게 좁으면 사용 승격을 보류한다. 임상 허용오차는 목표별 의료·사업 책임자가 사전에 승인해야 하며, 모델 점수를 보고 사후 완화하지 않는다.

### 8.3 분류 성능 지표

대사위험·간기능 위험처럼 사전 승인된 임상 정의와 이분 라벨이 있는 경우에만 사용한다.

| 지표 | 계산/의미 | 주의점 |
|---|---|---|
| AUROC | 모든 분류 임계값에서 양성과 음성을 구별하는 순위 성능 | 불균형 데이터에서 단독 사용 금지 |
| AUPRC | 양성 사례를 얼마나 효율적으로 찾는지 나타내는 Precision–Recall 면적 | 유병률과 함께 제시 |
| Brier score | `(1/n) Σ(p_i-y_i)^2` | 예측 확률의 정확도·보정을 함께 반영. 작을수록 좋음 |
| Calibration plot | 예측 확률 구간별 실제 발생률 비교 | 확률을 사용자에게 표시하려면 필수 |
| 민감도/특이도/PPV/NPV | 사전 승인된 임계값에서의 혼동행렬 지표 | 임계값을 테스트 성능에 맞춰 사후 선택하지 않음 |

### 8.4 공통 보고 지표

| 지표 | 계산 | 의미 |
|---|---|---|
| Coverage | 예측을 산출한 사용자 / 대상 사용자 | 실제 적용 가능한 범위 |
| ABSTAIN 비율 | 보류 사용자 / 대상 사용자 | 데이터 부족을 숨기지 않는 정도 |
| 95% 신뢰구간 | 사용자 단위 bootstrap으로 성능 지표의 분위수 구간 | 표본 불확실성 |
| 하위집단 성능 | 연령·성별·기기·출처·coverage 그룹별 동일 지표 | 기기/수집량 편향 탐지 |
| 기준선 대비 개선 | 후보 모델 지표 - 사전 정의 기준선 지표 | 복잡한 모델의 추가 가치 |

## 9. 검증 설계와 승격 기준

### 9.1 분할 방법

1. **사용자 단위 분리**: 한 사용자의 여러 검진·웨어러블 구간이 학습과 평가 양쪽에 섞이지 않게 한다.
2. **시간 순서 분리**: 과거 기간으로 모델을 학습하고 더 이후 건강검진으로 평가한다.
3. **봉인된 독립 평가**: 모델·특징·하이퍼파라미터 선택 중에는 확인하지 않는다.
4. **목표별 준비도**: 혈압에 충분한 라벨이 있어도 혈당·지질에 충분하다는 뜻은 아니다. 목표별로 별도 gate를 적용한다.

### 9.2 초기 표본 gate

현재 프로젝트 정책의 최소 기준은 다음과 같다.

| 항목 | 초기 최소 기준 | 미달 시 처리 |
|---|---:|---|
| 학습 사용자 | 100명 | `BLOCKED_BY_DATA` |
| 독립 평가 사용자 | 30명 | 성능 수치 미산출 |
| 분류 양성/음성 사건 | 각 30건 | 분류 모델 미학습 |
| 예측 기준시점 전 웨어러블 | 사전 정의 coverage 충족 | 해당 사용자 ABSTAIN |
| M1/M2 반복 검진 구간 | 사용자·기간 기준을 별도 충족 | M0 또는 보류로 라우팅 |

이 최소 기준은 시작점이며, 최종 표본 수는 목표별 효과 크기·예측 변수 수·라벨 변동성·임상 허용오차를 반영해 통계 검토로 확정한다.

### 9.3 모델 승격 기준

모델은 아래 조건을 모두 만족할 때만 ‘검증된 예측’으로 승격할 수 있다.

- 봉인된 독립 평가에서 사전 정의된 기준선보다 개선됨
- 목표별 MAE/RMSE/R² 또는 AUROC/AUPRC/Brier score가 임상·운영 승인 기준을 충족함
- calibration과 예측구간 포함률이 허용 범위임
- 주요 하위집단에서 성능 급락 또는 과도한 coverage 차이가 없음
- 재현 실행에서 동일한 데이터 스냅샷·코드 버전·랜덤 시드로 결과를 재생성할 수 있음
- 사용자 결과 파일에서 실제값·직접 측정값·예측값·보류 사유가 분리됨

하나라도 충족하지 못하면 후보 모델로 기록하되, 사용자용 `pred_*`는 출력하지 않는다.

## 10. 제한된 자동화와 품질보완

이 프로젝트에서의 적절한 용어는 **자율형 엔드투엔드 ML 엔지니어링과 폐쇄루프 품질관리(autonomous end-to-end ML engineering with closed-loop quality control)**다.

자동화 흐름은 다음과 같다.

```text
데이터 감사 → 데이터 계약 검사 → 가명 스냅샷 → 특징 생성
→ 기준선/후보 학습 → 사용자·시간 분리 검증 → 실패 원인 분류
→ 허용된 보완 → 재학습·재검증 → 모델 선택 또는 안전한 보류
→ 결과 파일·성능 그림·초심자용 보고서 생성
```

### 10.1 허용된 자동 보완

- 스키마·형식 오류 수정
- 단위·필드 별칭 매핑 수정과 원천 계보 기록
- 문서화된 sentinel 또는 명백한 불가능값 제거
- 사전 정의된 7/30/90일 특징 창 비교
- 특징 집합 축소·모델 단순화
- 학습/검증 내부에서만 하이퍼파라미터 조정
- 보정 또는 예측구간 방법 비교

### 10.2 금지된 자동 보완

- 봉인된 독립 평가를 반복 관찰하며 튜닝
- 성능을 높이기 위해 건강검진 라벨 정의·허용오차를 완화
- coverage를 높이기 위해 품질 기준을 임의로 하향
- 실제 정답 부족을 합성 성능이나 실제값 복사로 대체
- 환경 간 사용자 수준 데이터 병합
- 승인된 lifelog/Data SDK 범위 밖 데이터의 무단 사용

| `prediction_route` | M0/M1/M2/직접 요약/ABSTAIN |
| `coverage_grade` | 웨어러블 수집 충분성. 성능 등급이 아님 |
| `abstain_reason` | 예측을 보류한 이유 |
| `data_provenance_summary` | 기기·출처·수동입력·파생값·버전 요약 |

### 11.2 모델 성능 그림

모델이 실제로 검증된 뒤에만 아래 그림을 만든다. 현재 데이터 감사 그림을 성능 그림으로 부르면 안 된다.

| 그림/표 | 독자가 이해할 수 있는 내용 |
|---|---|
| 실제값 대 예측값 산점도와 기준선 | 예측값이 실제 건강검진값을 얼마나 따르는지 |
| 절대오차 분포와 목표별 MAE/RMSE 표 | 일반적인 오차 크기와 큰 오차의 빈도 |
| calibration plot·Brier score | 위험확률 또는 수치 수준이 과대/과소 예측되는지 |
| 예측구간 포함률 그래프 | 불확실성 구간이 실제값을 약속한 비율로 포함하는지 |
| 기준선 대비 성능 비교 | 복잡한 모델이 단순 기준보다 실제로 나은지 |
| coverage/ABSTAIN 그래프 | 누구에게 예측할 수 있고 누구에게 보류하는지 |
| 하위집단 forest plot 또는 표 | 기기·성별·연령·수집량에 따른 성능 차이 |

### 11.3 의료적 표현의 한계

Samsung Health Data SDK는 fitness/wellness 목적으로 제공되며 진단·치료를 위한 것이 아니라는 공식 제한이 있다. 따라서 SiBC 결과는 건강검진 또는 의료진 판단을 대체하지 않는 ‘웨어러블 기반 추정/연구 결과’로 표시한다. AFib 알림, 수면무호흡 등 의료적 해석이 민감한 값은 일반 예측 점수보다 별도 안전 플래그와 의료진 검토 경로로 다룬다.

## 최종 판단

SiBC가 보유한 16개 lifelog는 활동·심박·혈압·체성분·수면·SpO₂·걸음 수 축을 이미 갖고 있으며, 특히 심박·수면 단계·걸음·체성분은 건강검진 예측의 유망한 특징 기반이다. 반면 공복혈당·지질·간기능처럼 생활습관 외의 교란요인이 큰 항목은 시간 있는 영양, 측정·기기 출처, 약물·공복 등 보완 정보 없이는 정확한 수치 예측을 약속할 수 없다.

Samsung Health Data SDK에서는 운동 세션, VO₂max, 활동/칼로리, 시간 있는 Nutrition, 수면 단계, 기기·출처 정보가 현재 공백을 가장 효과적으로 보완한다. 다만 데이터 추가는 필요조건일 뿐 충분조건이 아니다. 예측 기준시점 이후의 실제 건강검진 `measuredDt`를 계속 연결하고, M0/M1/M2를 사용자·시간 분리된 독립 평가로 검증할 때에만 사용자별 건강검진 예측값을 안전하게 제공할 수 있다.
