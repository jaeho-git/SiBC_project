# SiBC 웨어러블 기반 건강검진 예측 모델

## 프로젝트 컨텍스트 및 AI 협업 지침

> 이 문서는 ChatGPT 또는 Claude의 프로젝트 자료로 업로드해, 분석·코드 검토·모델 설계·보고서 작성 시 동일한 전제와 안전 기준을 사용하기 위한 기준 문서다. 개별 요청이 이 문서와 충돌하면 **사용자의 최신 명시 지시가 우선**한다.

## 0. 먼저 알아야 할 핵심 사실

### 프로젝트 한 문장

SiBC는 지속적으로 수집된 웨어러블/라이프로그 데이터를 이용해, 건강검진을 받지 않은 사용자에게도 예측 가능한 건강검진 항목의 추정값을 제공하고, 과거 건강검진이 있는 사용자에게는 그 이후 누적 웨어러블 데이터를 반영한 최신 추정값을 별도로 제공하려는 프로젝트다.

### 현재 상태를 정확히 표현하면

**파이프라인과 데이터 감사는 구현됐지만, 검증된 건강검진 예측 모델은 아직 없다.**

2026-07-30 `release` 환경의 읽기 전용 프로토타입 감사 결과, 건강검진 정답 시점 이전 90일의 웨어러블 데이터가 있는 사용자가 2명뿐이었다. 사전에 정의한 최소 학습 인원(100명)과 독립 평가 인원(30명)을 충족하지 못했으므로, 모델 학습·성능 수치·개인별 예측 수치는 의도적으로 생성하지 않았다. 이 상태는 `BLOCKED_BY_DATA`다.

따라서 아래 두 문장을 혼동해서는 안 된다.

| 구분 | 현재 가능한 주장 | 현재 불가능한 주장 |
|---|---|---|
| 데이터 | 건강검진과 15개 lifelog 원천을 감사하고, 일부 최근 웨어러블 측정값을 요약할 수 있다. | 현재 데이터만으로 모든 건강검진 항목을 정확히 예측한다고 말할 수 없다. |
| 모델 | 시간 누출 방지, 사용자 분리 검증, 보류(ABSTAIN) 규칙을 갖춘 모델 골격이 있다. | 모델 성능이 검증됐거나 실제 예측이 배포 가능하다고 말할 수 없다. |
| 출력 | 최신 실제 검진값과 최근 웨어러블 직접 측정 요약을 분리해 출력할 수 있다. | 웨어러블 직접 측정값을 ‘AI 예측값’이라고 표시할 수 없다. |

## 1. 프로젝트의 목표와 사용자 시나리오

### 1.1 궁극적 목표

목표는 단순히 과거 건강검진 결과를 재현하는 것이 아니다. **예측 시점 이전에 누적된 웨어러블 데이터를 바탕으로 건강검진 관련 현재 상태를 추정**하는 것이다. 건강검진이 해당 시점에 존재하지 않아도 예측할 수 있어야 한다.

단, 모델을 학습하고 검증할 때는 정답이 필요하다. 따라서 과거 또는 이후의 건강검진 결과는 다음 역할로만 사용한다.

- 학습 정답(label): 예측 시점 이후 또는 해당 임상 시점의 실제 건강검진값
- 개인화 입력: 건강검진 이력이 있는 사용자의 이전 실제 건강검진값
- 전향 검증 정답: 예측을 고정한 뒤 새로 수집된 건강검진값

**예측 시점에 건강검진이 없다는 점**과 **모델 학습·평가에서 시간 순서를 지켜야 한다는 점**은 동시에 성립한다.

### 1.2 적용 대상과 모델 경로

| 경로 | 적용 대상 | 입력 | 학습/평가의 정답 | 사용 목적 |
|---|---|---|---|---|
| M0: 웨어러블 전용 | 건강검진 이력이 없거나 이력을 사용하지 않는 사용자 | 예측 시점 이전 웨어러블 특징만 | 이후 건강검진 결과 | 건강검진 미보유자에게 적용하는 핵심 경로 |
| M1: 개인화 절대값 | 과거 건강검진 이력이 있는 사용자 | 이전 실제 검진값 + 그 이후 웨어러블 + 경과시간 | 다음 건강검진의 절대값 | 과거 상태를 반영한 현재값 추정 |
| M2: 개인화 변화량 | 반복 건강검진이 있는 사용자 | 이전 실제 검진값 + 두 검진 사이 웨어러블 | 다음 검진값과 이전 검진값의 차이 | 사용자의 변화 방향·크기 추정 |
| 직접 측정 요약 | 모델 요건을 충족하지 못한 사용자도 포함 | 최근 웨어러블/연결기기 측정값 | 해당 없음 | 최근 관찰값을 투명하게 보여 줌 |
| ABSTAIN(보류) | 웨어러블 유효일·검증 근거가 부족한 사용자 | 해당 없음 | 해당 없음 | 신뢰할 수 없는 숫자를 생성하지 않음 |

### 1.3 사용자 결과 화면/파일에서 반드시 분리할 값

| 값의 종류 | 컬럼 접두어 | 의미 | 예시 표시 문구 |
|---|---|---|
| 실제 건강검진값 | `actual_*` | 최신 건강검진에서 실제로 측정된 값 | 최근 건강검진 실제값 |
| 웨어러블 직접 측정 요약 | `measured_*` | 워치·연결기기·입력값의 최근 관찰값을 요약한 값 | 최근 웨어러블 측정 요약 |
| 모델 예측값 | `pred_*` | 독립 검증을 통과한 모델의 추정값과 불확실성 구간 | 웨어러블 기반 예측값 |
| 위험도 | `risk_*` | 임상 정의가 승인되고 보정된 분류모델의 확률 | 위험도(모델 기준) |

`actual_*`, `measured_*`, `pred_*`는 절대로 서로 덮어쓰거나 같은 의미로 표시하지 않는다. 현재 release 프로토타입에서는 검증된 모델이 없으므로 `pred_*`는 비어 있고, `ABSTAIN_NO_VALIDATED_MODEL` 등의 상태가 기록된다.

- 선택하지 않은 환경은 읽지 않고, 연결 실패 시 다른 환경으로 자동 전환하지 않음
- 환경 간 사용자 수준 데이터·라벨·특징·모델을 병합하지 않음
- DB는 읽기 전용 세션으로만 접근하며, `INSERT`, `UPDATE`, `DELETE`, `MERGE`, DDL, write-back을 금지함

`.env.release`, `.env.dev`, `.env.stg`의 경로와 존재는 운영상 필요한 정보지만, 파일 내용·DB 비밀번호·접속 문자열은 이 문서, 프롬프트, 로그, 보고서, Git에 절대 포함하지 않는다.

### 2.2 건강검진 정답의 유일한 원천

건강검진 데이터는 다음 논리 경로만 사용한다.

```text
discovery.disc_medical_user_info.user_health_sn.health_info_data
```

구현상 사용자 연결이 필요할 때는 `disc_medical_user_info.user_health_sn`에서 참조된 `disc_health_user_info.user_health_sn` 레코드를 읽어 `health_info_data`를 사용한다. 이는 다른 건강검진 데이터 원천과의 비교·대조·병합을 의미하지 않는다.

건강검진의 임상 측정 시점은 반드시 다음 필드다.

```text
health_info_data[].measuredDt
```

다음은 임상 건강검진 날짜로 사용하면 안 된다.

- `ins_dt`, `upd_dt`: DB 적재·수정 시각일 수 있음
- 상위 테이블의 적재 시각 또는 `measured_dt`: 계보 확인에는 사용할 수 있으나 건강검진의 실제 측정일로 대체 불가

### 2.4 데이터 수집 및 통합 시 필수 메타데이터

같은 Samsung Health 이벤트가 기존 lifelog와 SDK 양쪽에서 들어올 수 있으므로 단순 행 결합은 금지한다. 원천 보존층에는 최소한 아래 필드를 유지한다.

| 필드 | 용도 |
|---|---|
| `source_system`, `source_record_id` | 출처 식별, 중복 제거, 계보 추적 |
| `data_type` | 심박·걸음·수면·영양 등 표준 분류 |
| `start_dt`, `end_dt`, `measured_dt` | 임상 시간 정렬 및 시간 누출 방지 |
| `origin_device`, `app_version`, `algorithm_version` | 기기·앱·알고리즘 변경에 따른 편향 점검 |
| `measurement_method` | 워치, 커프, 외부기기, 수동입력, 파생값 구분 |
| `unit`, `value`, `quality_flag` | 단위 표준화, 이상치·신호 품질 관리 |
| `is_user_entered`, `is_external_device`, `is_derived` | 값의 해석 가능성 및 신뢰도 구분 |
| `duplicate_suspected` | 중복 여부가 확정되지 않은 레코드 표시 |

| `sleep_detail` | 580,883 | 120 | 65 | 2026-03-01 ~ 2026-07-30 | 가능 | 수면 단계 특징 미구현 |
| `step` | 15,799 | 162 | 93 | 2026-02-17 ~ 2026-07-30 | 가능 | 최근 직접 요약 가능 |

`food`와 `meal`은 행 수가 존재해도, 현재 스키마에 임상 발생 시각이 없기 때문에 적재 시각을 건강검진 시점 전 특징으로 사용해서는 안 된다. “식이 기록이 있다”와 “언제 섭취했는지 안다”는 다른 문제다.

### 3.3 현재 생성 가능한 직접 측정 요약

다음은 예측 모델 결과가 아니라 기기·연결기기·입력 데이터의 관찰값을 요약한 것이다.

| 요약 | 원천 | 현재 산출 방식 |
|---|---|---|
| 혈압 | `bloodpressure` | 최근 30일 중앙값과 유효일 수 |
| 체중·신장·BMI | `body_info` | 최근 30일 이내 최신값 |
| 체지방·복부 관련 필드 | `bodyfat` | 최근 30일 이내 최신값 및 InBody 관련 필드 |
| 악력 | `grip_strength` | 최근 좌·우 악력 |
| 심박수 | `heartrate` | 최근 30일 중앙값, 10·90 분위수 |
| 산소포화도 | `oxygen_saturation` | 최근 30일 중앙값, 하위 분위수 |
| 걸음 수 | `step` | 최근 30일 중앙값, 평균, 유효일 수 |
| 수면 | `sleep` | 최근 30일 수면시간 중앙값, 유효일 수 |

직접 측정값의 출처·보정 여부·수동입력 여부를 함께 표시하지 않으면 건강검진값과 같은 의미로 오해될 수 있다.

## 4. 건강검진 목표 항목과 우선순위

### 4.1 건강검진에서 파싱 가능한 주요 실제값

현재 정규화 범위에는 키, 체중, BMI, 허리둘레, 수축기/이완기 혈압, AST, ALT, GGT, 혈색소, eGFR, 공복혈당, 크레아티닌, 총콜레스테롤, HDL, LDL, 중성지방, 요단백 등이 포함된다. 값의 별칭(alias), 단위, 원천 표기는 계보 파일로 관리한다.

### 4.2 초기 모델 후보

| 우선도 | 목표 | 과업 | 주된 웨어러블 후보 | 현재 판단 |
|---|---|---|---|---|
| 1 | 수축기·이완기 혈압 | 회귀 | 혈압, 심박, 수면, 활동, 체성분 | 직접 요약은 가능하나 예측 모델은 시간 정렬 표본 부족 |
| 1 | 체중·BMI·허리둘레 | 회귀 | 체중/체성분, 활동, 걸음, 수면 | 직접 요약 가능; 변화량 모델 검증 필요 |
| 2 | 공복혈당 | 회귀 | 혈당, 활동, 수면, 체성분, 시간 있는 식이 | 공복 여부·측정 출처·표본이 부족 |
| 2 | 중성지방·HDL·LDL·총콜레스테롤 | 회귀 | 활동, 체성분, 수면, 운동, 영양 | 약물·음주·공복 정보가 없으면 수치 예측 한계가 큼 |
| 3 | 대사위험 | 분류 | 혈압, 비만, 혈당, 활동, 수면 | 임상 정의·임계값 승인 후에만 진행 |
| 3 | 간기능 위험 | 분류 | 체성분, 활동, 수면, 영양 | 음주·약물·질환 정보 없이는 탐색적 수준 |

초기에는 항목별 모델을 사용한다. 혈압, 체중, 혈당, 지질은 결측 구조와 측정 조건, 유효한 특징이 다르므로 다중출력 모델로 한꺼번에 묶지 않는다.

### 4.3 모델이 답해야 하는 질문

- “이 사용자의 최근 웨어러블 패턴만으로 다음/현재 건강검진 항목을 추정할 수 있는가?” (M0)
- “과거 검진값과 그 이후 웨어러블 패턴을 함께 보았을 때, 이전 값을 그대로 유지하는 것보다 더 정확한가?” (M1)
- “검진 사이 누적 웨어러블 패턴이 실제 건강검진 변화량을 설명하는가?” (M2)

답이 검증되지 않은 항목은 숫자 대신 보류 사유와 추가로 필요한 데이터 조건을 제시한다.

## 5. 특징 생성과 시간 누출 방지

### 5.1 시간 누출 방지의 의미

건강검진 정답의 임상 시점이 `T`라면, 그 정답을 학습하거나 평가할 때 사용 가능한 웨어러블 데이터는 `T`보다 **엄격히 이전**에 관측된 데이터뿐이다.

```text
허용:  [T-180일, T) 웨어러블 데이터  →  T의 건강검진 결과
금지:  T 이후 웨어러블 데이터       →  T의 건강검진 결과
```

예를 들어 2026년 1월 건강검진값을 맞히기 위해 2026년 3월의 걸음 수나 수면 데이터를 쓰면, 실제 서비스 시점에는 알 수 없던 미래 정보를 모델에 넣는 것이므로 성능이 부당하게 좋아진다. 이것이 시간 누출이다.

M1/M2에서 과거 건강검진값을 입력으로 쓰는 것은 허용되지만, 그 입력은 예측 기준시점 이전의 값이어야 한다. 정확도 검증은 그 뒤에 새로 측정된 건강검진으로 해야 한다.

### 5.2 권장 특징 창과 특성

기본 관측 창은 예측 기준시점 직전 7일, 30일, 90일이며, 데이터가 충분해지면 180일까지 확장한다.

| 범주 | 예시 특징 |
|---|---|
| 수준 | 평균, 중앙값, 최소/최대, 분위수, 최근값 |
| 변동성 | 표준편차, 변동계수, 일간 변화량, 비정상 변동 비율 |
| 추세 | 7일 대 30일 차이, 선형 기울기, 최근 급변 플래그 |
| 규칙성 | 수면·운동·식사 시간의 주간 규칙성, 평일/주말 차이 |
| 품질 | 유효일 수, 결측률, 착용시간, 기기·출처 비율 |
| 문맥 | 운동 중/휴식 중/수면 중, 식전·식후, 외부기기·수동입력 여부 |

현재 구현에서 많은 원천은 7/30/90일 **관측일 수**까지만 등록돼 있다. 향후 우선적으로 활동량, 수면 단계, 심박 문맥, 혈당·식이의 측정 문맥을 값 기반 특징으로 확장해야 한다.

### 5.3 품질관리 규칙

- 측정시각, 단위, 값 범위를 검사하고 문서화된 sentinel 또는 생리적으로 불가능한 값은 제외한다.
- 단위·별칭 변환은 원천 필드와 변환 규칙을 계보로 남긴다.
- 동일 이벤트가 여러 수집 경로로 들어온 경우 원천 ID를 우선해 중복 제거한다.
- 중복 여부가 불명확하면 삭제 대신 `duplicate_suspected`로 표시해 민감도 분석이 가능하도록 한다.
- 임상 시각이 없는 데이터는 시간 정렬 모델 특징으로 사용하지 않는다.
- 사용자별 웨어러블 유효일 수가 충분하지 않으면 모델 출력 대신 `ABSTAIN`한다.

## 6. 모델링, 자동화, 검증 원칙

### 6.1 권장 알고리즘과 기준선

각 목표·모델 경로에 대해 먼저 단순하고 설명 가능한 기준선을 만든 뒤, 제한된 후보 모델을 비교한다.

| 문제 | 기준선 | 후보 모델 | 채택 기준 |
|---|---|---|---|
| 연속형 건강검진값 회귀 | 인구 중앙값, 최신 실제값 유지(M1), 최근 직접 측정값 | Elastic Net, Histogram Gradient Boosting | 봉인된 독립 평가에서 기준선 대비 실질적 개선, 보정·불확실성·단순성 충족 |
| 위험도 분류 | 유병률/단순 임상 규칙 | 보정된 Logistic Regression, 보정된 Histogram Gradient Boosting | AUROC/AUPRC뿐 아니라 Brier score·calibration·임상 정의 충족 |
| 변화량(M2) | 변화 없음(0), 최신 검진값 유지 | Elastic Net 또는 강건/부스팅 회귀 | 반복검진 간의 독립 검증에서 변화 없음 기준선을 이김 |

“최적 모델”은 교차검증 점수만 가장 높은 모델이 아니다. 사용자·시간 분리된 봉인 평가에서 아래를 함께 만족하는 모델이다.

- 단순 기준선보다 나은 성능
- 충분한 예측구간 포함률과 calibration
- 중요한 하위집단에서 과도하게 불안정하지 않음
- 필요한 웨어러블 유효일 수가 지나치게 높지 않음
- 재현 가능하고, 복잡도 대비 추가 이득이 있음

### 6.2 안전한 폐쇄루프 품질관리

이 프로젝트에서 말하는 자동화는 **자율형 엔드투엔드 ML 엔지니어링과 폐쇄루프 품질관리**다. 오류·품질 문제를 발견하면 미리 허용된 범위 안에서 수정하고, 다시 학습·검증해 개선 여부를 확인한다. 무제한 성능 최적화나 시험 데이터에 맞춘 반복 튜닝은 아니다.

허용된 자동 보완:

1. 스키마·형식 오류 수정
2. 단위 또는 별칭 매핑 수정(원천과 계보를 남길 것)
3. 문서화된 sentinel/명백한 불가능값 제거
4. 사전 정의된 7/30/90일 특징 창 비교
5. 특징 집합 축소 또는 모델 단순화
6. 학습·검증 내부에서만 하이퍼파라미터 조정
7. calibration 또는 예측구간 방법 비교

금지된 자동 보완:

1. 봉인된 독립 평가 세트를 반복적으로 보고 튜닝
2. 성능을 높이기 위해 건강검진 라벨 정의·임상 허용오차를 완화
3. coverage를 높이기 위해 품질 기준을 임의로 낮춤
4. 부족한 실제 정답을 합성 성능이나 복사된 실제값으로 대체
5. 환경 간 데이터 병합 또는 승인 범위 밖 데이터 추가
6. `actual_*` 값을 `pred_*`에 복사

### 6.3 최소 검증 설계

- 분할 단위: 사용자 단위. 동일 사용자가 학습과 평가 양쪽에 존재하면 안 됨.
- 시간 순서: 과거 웨어러블·검진으로 학습하고, 더 이후의 건강검진으로 평가.
- 표본 기준: 초기 정책상 최소 학습 사용자 100명, 독립 평가 사용자 30명, 분류의 각 사건 수 30건.
- 회귀 지표: MAE, RMSE, R², calibration, 예측구간 포함률, 95% 신뢰구간.
- 분류 지표: AUROC, AUPRC, Brier score, calibration, 민감도·특이도.
- 비교 대상: 인구 기준선, 이전 건강검진값 유지, 최근 웨어러블 직접값, 단순 선형모델.
- 하위집단: 연령, 성별, 기기/측정 출처, 웨어러블 수집량, 필요한 경우 질환·약물 관련 변수의 이용 가능성.

표본 기준을 충족하지 못하면 ‘낮은 성능의 모델’을 학습하는 것이 아니라 `BLOCKED_BY_DATA`로 종료해야 한다.

### 6.4 성능 보고 시 필수 시각화

검증이 가능해진 뒤, 처음 보는 사람도 성능을 이해할 수 있도록 최소한 아래를 생성한다.

| 목적 | 회귀 | 분류 |
|---|---|---|
| 오차의 크기 | 실제값 대 예측값 산점도, 오차 분포 | ROC, Precision–Recall |
| 보정 | 구간 포함률/잔차 대 예측값 | calibration plot, Brier score |
| 기준선 비교 | MAE·RMSE 기준선 비교표 | AUROC/AUPRC/Brier 기준선 비교표 |
| 신뢰성 | 사용자·시간 분리, 부트스트랩 95% CI | 사용자·시간 분리, 부트스트랩 95% CI |
| 적용 범위 | coverage·ABSTAIN 비율 | coverage·ABSTAIN 비율 |
| 공정성·안정성 | 하위집단 성능 표/forest plot | 하위집단 성능 표/forest plot |

현재 release 결과 폴더의 그림은 데이터 정렬·coverage·준비도 그림이며, **모델 성능 그림이 아니다**.

## 7. 모델 성능을 높이기 위해 필요한 데이터

### 7.1 가장 중요한 데이터 수집 과제

성능 향상의 선행 조건은 복잡한 알고리즘이 아니라, 예측 기준시점 이전의 웨어러블과 그 이후 건강검진이 연결된 종단 데이터다.

1. 웨어러블을 지속적으로 수집한 사용자의 **다음 건강검진**을 `measuredDt` 기준으로 연결한다.
2. 반복 건강검진 사용자에서 두 검진 사이 웨어러블 구간을 충분히 확보한다.
3. 혈압·체성분·혈당에 대해 기기/수동입력/외부기기 여부, 측정 조건, 단위를 수집한다.
4. 혈당과 지질에 대해 공복 여부, 식사 시각·식전/식후 상태, 약물, 음주 등 임상적 교란요인의 이용 가능성을 검토한다.
5. 웨어러블 유효일 수·착용 상태·기기 세대/알고리즘 버전 등을 수집해 결측·선택편향을 분석한다.

### 7.2 Samsung Health Data SDK 도입 시 우선순위

기준표 `01_통합 매트릭스`에서 Data SDK가 `O` 또는 `△`인 19개 항목을 대상으로 검토한 결과다. SDK 도입은 특징 공백을 줄이는 수단이지, 건강검진 정답·독립 검증을 대체하지 않는다.

| Data SDK 항목 | 현 SiBC 대응 | 우선도 | 고도화 목적 |
|---|---|---|---|
| 걸음수 | `step` | 유지 | 일별 변동성·주말 차이·장기 추세 |
| 활동/칼로리 | `activity`, `calories` | 최우선 | 활동시간·거리·강도·활동칼로리 확보 |
| 운동 세션 | 없음 | 최우선 | 운동 종류·시간·심박 반응 구조화 |
| 운동 GPS 경로 | 없음 | 선택 | 거리·야외 운동 문맥; 위치 최소화 필요 |
| 일상 심박수 | `heartrate` | 유지 | 안정·운동·수면 문맥 분리 |
| 부정맥/AFib 알림 | 없음 | 안전 전용 | 의료진 확인 플래그, 진단 대체 금지 |
| 혈압 | `bloodpressure` | 유지 | 출처·커프 보정·반복 측정 조건 |
| SpO₂ | `oxygen_saturation` | 유지 | 수면/온디맨드 문맥과 신호 품질 |
| 피부/체온 | 없음 | 중간 | 개인 기준선 대비 급성 변화 보조 |
| 수면(총/세션) | `sleep` | 유지 | 규칙성·분할수면·낮잠 특징 |
| 수면 단계 | `sleep_detail` | 최우선 | 깊은/REM/각성 비율, 수면 분절 |
| 수면 점수 | 없음 | 보조 | 원천 수면 지표 대비 추가 가치 검증 |
| 수면무호흡 | 없음 | 안전 전용 | 의료진 검토 플래그; 일반 회귀 입력 우선 제외 |
| 체중·체성분 | `body_info`, `bodyfat` | 유지 | 기기·자세·반복 측정·출처 관리 |
| 혈당 | `bloodglucose` | 최우선 | 식전/식후·단위·기기·식사시각 확보 |
| 식이(영양) | `food`, `meal` | 최우선 | 섭취 시각·영양소·기록 출처 확보 |
| 물 | 없음 | 낮음 | 운동·더위·식이의 보조 문맥 |
| VO2max | 없음 | 최우선 | 심폐체력의 장기 추세 |
| 에너지/준비도 점수 | 없음 | 보조 | 사용자 피드백용; 기초값 모델과 분리 검증 |

우선순위가 높은 신규/보완 데이터는 다음 다섯 가지다.

1. 실제 활동량/칼로리와 운동 세션
2. VO2max
3. 시간 정보가 있는 영양/식사 기록
4. 수면 단계의 구조화된 특징
5. 혈압·체성분·혈당의 출처와 측정 조건

`AFib 알림`, `수면무호흡`, `수면 점수`, `에너지/준비도 점수`는 기기·지역·알고리즘 의존성이 크다. 수집 가능 여부와 건강검진 예측의 임상적 유용성은 분리해 평가해야 한다.

## 8. 출력 계약과 사용자 결과 파일

최종 사용자 결과는 CSV/XLSX 한 사용자당 한 행을 기본으로 하되, 값의 출처와 예측 가능 여부를 함께 전달한다.

| 컬럼 예시 | 의미 |
|---|---|
| `user_key` | 원본 ID가 아닌 가명 사용자 키 |
| `actual_sbp`, `actual_sbp_measured_dt` | 최신 실제 건강검진 수축기 혈압과 검진일 |
| `actual_exam_provider` | 건강검진 기관/원천 정보; 공개 범위는 별도 정책에 따름 |
| `measured_bp_median_30d`, `measured_bp_source` | 최근 30일 웨어러블 혈압 요약과 출처 |
| `pred_sbp`, `pred_sbp_lower`, `pred_sbp_upper` | 검증 통과 후에만 채워지는 예측값과 불확실성 구간 |
| `pred_sbp_status`, `pred_sbp_method` | 예측/보류 상태 및 M0/M1/M2/기준선 방법 |
| `prediction_route` | 사용자별 적용 경로 |
| `coverage_grade` | 웨어러블 수집 충분성; 모델 성능 등급이 아님 |
| `abstain_reason` | 충분한 데이터 또는 검증 근거가 없어 보류한 이유 |
| `data_provenance_summary` | 워치·외부기기·수동입력·파생값 구성 요약 |

사용자에게 표시할 때는 다음을 명확히 한다.

- 실제값의 검진일과 예측 기준시점을 함께 표시한다.
- 웨어러블 측정 요약은 측정 출처와 기간을 표시한다.
- 예측값에는 불확실성 구간, 모델 버전, coverage, 보류 사유를 함께 제공한다.
- 건강검진·진단·치료 결정을 대체하지 않는다는 문구를 포함한다.

## 10. ChatGPT·Claude가 따라야 할 작업 규칙

### 10.1 기본 태도

1. 현재 상태를 `BLOCKED_BY_DATA`로 시작하고, 새로운 실행 근거 없이 ‘모델이 완성됐다’ 또는 ‘성능이 좋다’고 쓰지 않는다.
2. 검진 시점과 웨어러블 시점의 관계를 항상 명시한다.
3. 실제값·직접 측정값·예측값을 구분한다.
4. 데이터 부족은 실패가 아니라 안전한 의사결정 결과로 취급한다. 부족 사유, 근거 수치, 다음 수집 조건을 제시한다.
5. 의학적 진단·처방·질병 확정을 하지 않는다. 모델은 건강검진 관련 추정/연구·개발 목적이다.

### 10.2 데이터·보안 규칙

1. `.env` 내용을 출력, 복사, 커밋, 문서화하지 않는다.
2. DB 접속정보, 원본 `user_id`, 원시 건강검진 JSON, 민감한 사용자별 로그를 결과물에 넣지 않는다.
3. 원본 사용자 ID는 메모리에서 가명키로 변환한 뒤에만 디스크에 저장한다.
4. SQL은 승인된 읽기 전용 범위만 사용하고, 쓰기/DDL을 포함한 쿼리를 작성·실행하지 않는다.
5. `release`, `dev`, `stg`를 혼합하거나 한 환경의 모델을 다른 환경에 자동 적용하지 않는다.
6. 기존 사용자 변경 사항이나 산출물을 삭제·초기화하지 않는다.

### 10.3 분석·모델링 규칙

1. `measuredDt`만 건강검진 임상시각으로 사용한다.
2. 예측 기준시점 이후에 기록된 lifelog를 학습 특징으로 쓰지 않는다.
3. 사용자 단위 분리와 시간 순서 분리를 모두 지킨다.
4. 봉인된 독립 평가 결과로 반복 튜닝하지 않는다.
5. 실제값 복사, 라벨 정의 완화, 품질 기준 하향으로 성능을 만들지 않는다.
6. 임상시간이 없는 `food`, `meal`은 발생 시각이 확보되기 전까지 시간 정렬 모델의 특징으로 쓰지 않는다.
7. 충분한 검증 표본이 없으면 `pred_*`를 채우지 말고 `ABSTAIN`으로 표시한다.

### 10.4 작업 결과를 보고하는 형식

AI는 분석·코드·문서 작업 결과를 다음 순서로 간결하고 검증 가능하게 제시한다.

```text
1. 결론: 무엇이 가능/불가능하며, 현재 상태는 무엇인가
2. 근거: 사용한 데이터 범위, 표본 수, 시간 정렬, 파일/실행 ID
3. 변경: 생성·수정한 파일과 주요 변경점
4. 검증: 실행한 테스트, 데이터 품질 검사, 성능 지표 또는 미산출 사유
5. 제한사항: 남은 데이터/임상/운영상의 한계
6. 다음 의사결정: 사용자의 승인 또는 추가 데이터가 필요한 사항
```

가정이 필요하면 가정임을 명시하고, 모델의 범위·데이터 원천·성능 상태를 사실처럼 추정해서 채우지 않는다.

## 11. AI에게 바로 전달할 수 있는 시작 프롬프트

아래 블록은 이 파일과 함께 ChatGPT 또는 Claude 프로젝트의 지침으로 사용할 수 있다.

```text
당신은 SiBC 웨어러블 기반 건강검진 예측 프로젝트의 임상 예측·시계열 분석·데이터 엔지니어링·MLOps·통계 검증 담당자다.

업로드된 ‘SiBC 웨어러블 기반 건강검진 예측 모델: 프로젝트 컨텍스트 및 협업 지침’을 최우선 프로젝트 기준으로 사용하라. 이 문서의 최신 release 감사 상태는 BLOCKED_BY_DATA이며, 검증된 건강검진 예측 모델이나 성능 수치는 아직 없다는 점을 유지하라.

프로젝트 목표는 웨어러블 데이터만 있는 사용자(M0)와 과거 건강검진 후 웨어러블이 누적된 사용자(M1/M2) 모두에게 건강검진 관련 값을 안전하게 추정하는 것이다. 실제 건강검진값(actual), 웨어러블 직접 측정 요약(measured), 모델 예측(prediction)을 절대 혼용하지 마라.

건강검진 정답은 discovery.disc_medical_user_info.user_health_sn.health_info_data만 사용하며, 임상 측정일은 health_info_data[].measuredDt다. ins_dt와 upd_dt는 임상 측정일로 사용하지 마라. 허용된 15개 lifelog 원천만 사용하고, release/dev/stg 환경의 사용자 수준 데이터를 병합하지 마라.

모든 모델 제안은 시간 누출 방지(특징은 정답 시점 이전), 사용자 단위 분리, 시간 순서 분리, 봉인 독립 평가, 불확실성 및 ABSTAIN 규칙을 만족해야 한다. 표본 기준을 충족하지 못하면 성능을 추정하거나 예측값을 만들지 말고 BLOCKED_BY_DATA와 필요한 데이터 조건을 보고하라.

무엇을 답하든 다음 순서로 정리하라: 결론, 근거, 권장 조치, 검증 방법, 제한사항. 의료 진단·치료 권고를 하지 말고, DB 비밀정보·원본 사용자 식별자·원시 건강정보를 요청하거나 출력하지 마라.
```

## 13. 용어 정리

| 용어 | 뜻 |
|---|---|
| 건강검진값 | 의료/검진 기관에서 실제로 측정된 `health_info_data`의 결과 |
| 웨어러블 직접 측정 | 워치·연결 기기·입력으로 들어온 측정값; 모델 예측이 아님 |
| 예측 기준시점 | 모델이 ‘지금’의 상태를 추정하기 위해 특징을 마감하는 시점 |
| 라벨/정답 | 학습·평가에 사용하는 실제 건강검진 결과 |
| 시간 누출 | 예측 시점 이후 정보를 학습 특징에 넣어 성능이 부당하게 좋아지는 문제 |
| 사용자 분리 | 동일 사용자의 레코드가 학습·평가 양쪽에 동시에 존재하지 않게 하는 원칙 |
| 봉인된 평가 | 모델·특징 선택 과정에서 반복적으로 보지 않고 최종 평가에만 사용하는 데이터 |
| calibration(보정) | 예측 수치/확률이 실제 결과와 얼마나 일관되게 맞는지 |

## 최종 요약

SiBC의 방향은 타당하다. 웨어러블 데이터만 있는 사용자에게 적용할 M0과, 과거 건강검진 후 누적 웨어러블을 이용하는 M1/M2를 함께 설계하는 것이 적절하다. 다만 현재 release 데이터에서는 시간상 올바르게 정렬된 학습·검증 표본이 2명에 불과하므로, 지금은 예측 모델의 성능을 주장할 단계가 아니다.

지금 가장 가치 있는 작업은 (1) 다음 건강검진을 지속적으로 연결할 수 있는 종단 데이터 구조를 만들고, (2) 활동·운동·수면 단계·식이 시각·측정 출처를 보완하며, (3) 충분한 표본이 생긴 뒤 동일한 안전한 파이프라인으로 M0/M1/M2를 독립 검증하는 것이다. 이 원칙을 지키면, 데이터가 늘어났을 때 과장 없이 재현 가능하고 사용자별로 적용 가능한 웨어러블 기반 건강검진 예측 모델로 발전시킬 수 있다.
