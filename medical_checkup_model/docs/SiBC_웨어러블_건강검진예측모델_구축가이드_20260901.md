# SiBC 웨어러블 기반 건강검진 예측 모델 구축 가이드

## 1. 목적

### 1.1 프로젝트가 해결하려는 문제

건강검진은 보통 1년에 한 번 측정되므로, 검진과 검진 사이 또는 검진을 받지 않은
기간에는 사용자의 임상 수치를 알 수 없다. 반면 웨어러블(스마트워치, 연동 혈압계,
체성분계 등) 데이터는 일상에서 지속적으로 쌓인다. 이 프로젝트는 웨어러블 패턴으로
건강검진 항목을 추정하여 그 간극을 줄인다.

### 1.2 두 가지 사용자 시나리오

| 사용자 | 입력 | 산출 | 활용 |
|---|---|---|---|
| 건강검진 이력이 **있는** 사용자 | 과거 검진값 + 이후 웨어러블 데이터 | 현재 시점 검진 항목 예측값 | 과거 실제 검진값과 비교하여 "어떤 항목이 얼마나 나빠졌는지" 제시 |
| 건강검진 이력이 **없는** 사용자 | 웨어러블 데이터만 | 현재 시점 검진 항목 예측값 | "현재 어떤 항목이 얼마나 좋지 않은지" 제시 |

두 경우 모두 최종 목적은 **병원 방문 안내** 또는 (중국 운영 기준) **의료진 가정방문
연계**를 통해 사용자가 적시에 의료서비스를 받게 하는 것이다. 이 모델은 진단이
아니라 "검진·진료가 필요할 수 있다"는 안내 신호를 만드는 도구다.

### 1.3 모델 경로 M0 / M1 / M2

| 경로 | 대상 | 입력 | 예측 대상 |
|---|---|---|---|
| M0 (웨어러블 전용) | 검진 이력 없음 | 예측 기준시점 이전 웨어러블만 | 검진 항목 절대값 |
| M1 (개인화 절대값) | 과거 검진 1회 이상 | 이전 검진값 + 이후 웨어러블 + 경과시간 | 다음 검진 항목 절대값 |
| M2 (개인화 변화량) | 반복 검진 | 이전 검진값 + 두 검진 사이 웨어러블 | 다음 검진에서의 변화량 |

M1/M2는 과거 검진값을 "정답 복사"하는 것이 아니라 사용자별 기준선(baseline)으로
사용해 예측을 개인화한다. 건강검진이 없는 사용자에게는 M0가 유일한 경로다.

### 1.4 반드시 구분하는 세 종류의 값

| 구분 | 접두어 | 의미 |
|---|---|---|
| 실제 건강검진값 | `actual_*` | 검진기관에서 실제 측정된 결과 |
| 웨어러블 직접 측정 요약 | `measured_*` | 워치·연동기기 최근 관찰값의 요약 (예: 30일 혈압 중앙값) |
| 모델 예측값 | `pred_*` | 독립 검증을 통과한 모델의 추정값 |

`measured_bp_median_30d`(직접 측정 요약)와 `pred_sbp`(모델 예측)는 다른 값이며,
사용자·의료진 화면에서도 혼용하지 않는다. 모델이 검증되기 전에는 `actual_*`과
`measured_*`만 제공할 수 있다.

## 2. 데이터 자산 현황 (2026-09-01 DB 감사 기준)

아래 수치는 2026-09-01 release `invites_loop` 데이터베이스 읽기 전용 감사에서
측정한 값이다. 데이터는 계속 적재되므로 재인용 시 반드시 측정일을 함께 표기한다.

### 2.1 건강검진 데이터 (예측의 정답 = 라벨)

**승인된 유일한 논리 원천:**

```text
discovery.disc_medical_user_info.user_health_sn
  → discovery.disc_health_user_info.health_info_data (JSON)
```

- `disc_medical_user_info` (2,053행)는 `user_health_sn` 외래키로
  `disc_health_user_info` (935행, 483명)에 연결된다.
- `health_info_data`는 대부분 JSON 배열(900행)이며, 배열 원소 중
  `medicalUserMeasDetails` 키를 가진 원소가 건강검진 이벤트다.
- 임상 측정일은 반드시 `health_info_data[].measuredDt`를 사용한다.
  `ins_dt`/`upd_dt`는 DB 적재·수정 시각일 뿐이므로 라벨 시점으로 쓰면 안 된다.

**검진 이벤트 규모:**

| 지표 | 값 |
|---|---|
| 건강검진 이벤트 수 | 1,865건 |
| 검진 보유 사용자 | 374명 |
| `measuredDt` 범위 | 2017-01-06 ~ 2026-08-31 |
| 검진 2회 이상(M1/M2 후보) | 292명 |
| 검진 4회 이상 | 230명 |
| 연간 검진 이벤트 | 매년 약 165~229건으로 꾸준히 적재 (2026년은 8월까지 79건) |

### 2.3 가장 중요한 현재 병목: 시간 정렬된 라벨 부족

지도학습에는 "예측 기준시점 이전의 웨어러블 관측창 + 그 이후의 실제 검진 결과"
쌍이 필요하다. 그러나 검진 이력의 대부분은 2017~2025년(웨어러블 적재 시작 전)에
측정된 것이다.

> **2026-09-01 측정: 웨어러블(걸음) 데이터 시작 30일 이후에 건강검진을 받은
> 사용자는 6명(이벤트 9건)에 불과하다.**

즉 현재는 M0/M1/M2 어느 경로도 통계적으로 유의한 학습·독립 검증이 불가능하며
(`BLOCKED_BY_DATA`), 모델 구축은 다음 두 갈래로 진행해야 한다.

1. **지금 가능한 것**: 특징·라벨 파이프라인과 검증 체계를 완성해 두고,
   웨어러블 직접 측정 요약(`measured_*`)과 최신 실제 검진값(`actual_*`)을 먼저
   서비스한다.
2. **누적을 기다리지 않고 확보하는 것**: 관측창을 7일로 완화해도 2026년 학습
   가능 쌍은 13건(10명)에 그치므로(2026-09-01 측정) 기준 완화로는 해결되지
   않는다. 대신 7장의 통합 학습 프레임 — 공공데이터와 자체 데이터를 한
   테이블로 학습하고 재학습마다 자체 비중을 확대, 자기지도 사전학습과 라벨
   확보 캠페인을 병행 — 을 적용하고, 자체 라벨이 최소 기준(8장)을 넘는
   시점부터 M0 → M1 → M2 순으로 자체 지배 버전을 승격한다.

## 3. 어떤 검진 항목을 예측할 수 있는가

### 3.1 우선순위와 근거 요약

| 우선도 | 검진 항목 | 주요 웨어러블 입력 | 근거 수준 (4장 문헌) | 전제 |
|---|---|---|---|---|
| 1 | 수축기/이완기 혈압 | 웨어러블 혈압, 심박, 수면, 활동, 체성분 | 높음: 워치 혈압 검증 연구, 커프리스 BP 문헌, 수면-고혈압 메타분석 | 측정 출처·보정 관리, 시간 정렬 라벨 |
| 1 | 체중·BMI·허리둘레 | 체중/체성분, 걸음, 활동, 수면 | 높음: 걸음수-비만 코호트, BIA 검증 연구 | 기기/수동입력 구분 |
| 2 | 공복혈당 | 심박(안정심박·변동성), 수면, 활동, 체성분 | 중간: 웨어러블-임상검사 예측 연구, 안정심박-당뇨 메타분석, 수면-당뇨 메타분석 | 공복 여부·기기·단위 관리 |
| 2 | 지질 4종 (TG, HDL, LDL, 총콜레스테롤) | 활동, 운동 세션, 체성분, 수면 | 중간: 웨어러블-임상검사 예측 연구(HDL 등), 활동-지질 문헌 | 지질 충족률 43% → 라벨 수 관리 |
| 3 | 대사위험(대사증후군 위험 분류) | 혈압, 체성분, 혈당, 활동, 수면, 악력 | 중간: 걸음수-만성질환 코호트, 악력-심혈관대사 문헌 | 임상 정의·임계값 사전 승인 |
| 3 | 간기능 위험(탐색) | 체성분, 활동, 수면 | 낮음: 직접 예측 근거 부족 | 음주·약물 정보 없이는 탐색 수준 |

### 3.2 예측을 단정하면 안 되는 항목

AST, ALT, GGT, 혈색소, eGFR, 크레아티닌, 요단백은 검진 원본에 존재하지만
약물, 기저질환, 음주, 급성 질환, 검사 조건의 영향이 커서 현재 웨어러블만으로
수치 예측을 약속할 수 없다. Dunn 2021(4장)도 웨어러블 예측력이 항목별로 크게
다르며 일부 항목만 의미 있는 예측이 가능함을 보였다. 이 항목들은 충분한 임상
공변량과 독립 검증 근거가 생길 때 연구 후보로만 검토한다.

### 3.3 모델 예측 이전에 제공 가능한 직접 측정 요약

모델 검증 전에도 아래는 `measured_*`로 즉시 제공 가치가 있다 (30일 창 기준):

- 웨어러블 혈압: 유효 측정 중앙값, 측정일 수, 출처
- 체중·BMI·체성분: 최신 유효 측정값과 측정일, 기기/수동 구분
- 심박: 중앙값, 10/90 분위수, 유효일 수
- 산소포화도: 중앙값, 하위 분위수, 수면 연결 여부
- 걸음·거리·칼로리, 수면시간·수면 규칙성, 악력 최근값

### 4.5 문헌이 시사하는 설계 원칙

1. 웨어러블 예측력은 항목별로 다르다 — 혈액학 일부는 가능, 생화학 다수는 제한
   (Dunn 2021). 항목별 근거 수준을 예측 우선순위(3.1)에 반영한다.
2. 관측 기간이 길수록, 예측 시점에 가까울수록 성능이 좋다 (Dunn 2021) —
   7/30/90일 다중 관측창과 유효일 수 품질 특징의 근거.
3. 수면시간-대사 위험은 U자형이다 (Cappuccio 2010, Jike 2018) — 수면 특징은
   비선형 모델 또는 구간화로 다룬다.
4. 워치 혈압·BIA는 보정·출처 관리가 전제다 (Mukkamala 2021, Lee 2025,
   Bennett 2022) — provenance 특징과 "진단 대체 아님" 고지의 근거.
5. 걸음수 효과는 연령에 따라 다르다 (Paluch 2023, Master 2022) — 연령·성별
   하위집단 성능 평가(5.6)의 근거.

### 5.5 시간 누출 방지 (가장 중요한 규칙)

```text
허용:  [T - 관측창, T) 의 웨어러블 데이터  →  T 시점 검진 라벨
금지:  T 이후의 웨어러블 데이터           →  T 시점 검진 라벨
```

- 특징창의 끝은 라벨 시점 이전이어야 한다 (`feature_end_lte_label_time`).
- `ins_dt`(적재시각)가 아니라 `measuredDt`(임상 측정일)로 정렬한다.
- 서빙 시점에도 동일 규칙: 예측 기준시점 이전 데이터만 특징으로 계산한다.

### 5.6 학습·검증 설계

- **분리**: 사용자 단위 분리(동일 사용자가 학습·평가 양쪽에 못 들어감) +
  시간 순 분리(과거로 학습, 이후 검진으로 평가).
- **봉인된 독립 테스트**: 최종 평가 세트는 모델·특징·하이퍼파라미터 선택에
  반복 사용하지 않는다. 승격은 봉인 테스트 통과로만 한다.
- **후보 모델**: 회귀는 elastic net, histogram gradient boosting;
  분류는 보정된(calibrated) 로지스틱 회귀, 보정된 gradient boosting.
  소표본에서는 단순 모델과 강한 규제를 우선한다.
- **기준선 비교**: 모든 모델은 다음 기준선을 이겨야 한다.
  - M0: 모집단 평균/중앙값 예측
  - M1: "직전 검진값 그대로"(carry-forward) 예측 — 이걸 못 이기면 개인화 무의미
- **평가지표**: 회귀 MAE·RMSE·R²·bias·calibration slope·예측구간 포함률(PICP);
  분류 AUROC·AUPRC·Brier·calibration plot; 공통 coverage·ABSTAIN 비율·
  하위집단(기기·출처·연령·성별·수집량) 안정성.
- **불확실성**: 점 추정과 함께 예측구간(`pred_*_lower/upper`)을 제공하고,
  구간 포함률을 검증한다.

### 5.7 예측 보류 (ABSTAIN)

모든 사용자에게 숫자를 내는 것이 목표가 아니다. 다음이면 예측을 보류하고
이유를 표기한다.

- 관측창 내 유효일 수가 기준 미달 (예: 30일 창에 유효 14일 미만)
- 측정 출처 불명확 (수동입력만 존재, 기기 미상)
- 해당 항목 모델이 독립 검증을 통과하지 못함 (현재 전 항목이 여기 해당)
- 입력 분포가 학습 분포에서 크게 벗어남

## 7. 데이터·학습 전략: 통합 학습(joint training) 프레임

자체 라벨(웨어러블 관측창 + 이후 검진) 부족은 현재 최대 병목이다. 이를
돌파하는 공식 전략은 **공공데이터와 자체 데이터를 처음부터 한 학습 테이블에
넣어 단일 모델을 학습하고, 자체 데이터가 누적될 때마다 재학습하여 모델의
중심을 점진적으로 우리 사용자 쪽으로 이동시키는 통합 학습 프레임**이다.

이 프레임의 서사는 다음과 같이 정당하게 주장할 수 있다: "초기에는 데이터
양 확보를 위해 공공데이터를 함께 사용했지만, 검증은 처음부터 끝까지 자체
데이터로만 수행했고, 최종 모델은 자체 데이터 누적으로 완성했다." 이 주장이
성립하는 조건은 7.2에 명시한다.

### 7.1 합성(페르소나) 데이터에 대한 정책

"검진값에 맞는 웨어러블 페르소나 데이터를 생성해 학습"하는 접근은 채택하지
않는다. 이유는 순환 논리다: 검진값에 어울리는 웨어러블 패턴을 생성하려면
웨어러블–검진 관계를 이미 알아야 하는데, 그 관계가 바로 모델이 데이터에서
배워야 할 대상이다. 모델은 현실이 아니라 생성 규칙에 넣은 가정을 되배우며,
합성 데이터 위의 성능 수치는 실제 사용자에 대한 성능이 아니다. 이는
`modeling_policy.yaml`의 금지 조항
(`substitute_synthetic_performance_for_missing_labels`)에도 명문화되어 있다.

합성 데이터의 **허용 용도**는 다음으로 한정한다.

- 파이프라인 개발·단위/통합 테스트 (스키마·경계값·결측 시나리오)
- 데모·화면 시안 (합성임을 명시)
- 극단 입력 스트레스 테스트, 프라이버시 안전한 예제
- (제한적) 학습 증강 — 실데이터 검증 성능이 저하되지 않음을 확인한 경우에만

어떤 경우에도 합성 데이터에서 계산한 성능 지표를 모델 성능으로 보고하지
않는다.

### 7.2 통합 학습 프레임: 하나의 모델, 하나의 학습 테이블

공공데이터로 별도 모델을 만들어 나중에 교체하는 방식이 아니라, **처음부터
공공데이터 행과 자체 데이터 행을 공통 특징 스키마의 한 학습 테이블에 넣고
단일 모델을 학습**한다.

```text
통합 학습 테이블 (공통 특징 스키마)
├─ 공공데이터 행 : NHANES 활동량·악력·인구통계 + 검진값   [source=public, 가중치 낮음]
├─ 자체 데이터 행 : 걸음·심박·수면·혈압·체성분 + 검진값    [source=own,    가중치 높음]
└─ 출처 표시 변수(domain indicator) + 샘플 가중치 + 소스별 결측 마스크

재학습 주기(분기 권장)마다:
  자체 행 추가 → 자체 가중 비중 증가 → 모델 중심이 우리 사용자 쪽으로 이동
  → 자체 데이터만으로 재학습한 버전이 봉인 테스트를 통과하면 공공 행 제외
```

핵심 설계 장치:

- **출처 표시 변수**: 모델이 공공 코호트와 자체 사용자 간 체계적 차이
  (인구 구성, 측정 방식)를 명시적으로 구분해 학습하게 한다.
- **샘플 가중치**: 자체 행에 높은 가중치를 주되, 초기(수십 건)에는 자체
  행이 과적합을 유발하지 않도록 상한을 둔다. 자체 라벨 수가 늘 때마다
  가중 비중을 계획적으로 올린다.
- **소스별 결측 마스크**: NHANES에 없는 특징(연속 심박, 수면 단계 등)은
  결측 마스크로 처리하고, 해당 특징의 기여는 자체 데이터가 누적되면서
  자연스럽게 학습된다.
- **서비스 결합**: 과거 검진값 개인 앵커(M1 경로)는 이 모델의 입력 특징으로
  포함한다. 별도 퓨전 모델을 두지 않는다.

**스키마 앵커링 원칙 — 특징·목표는 SiBC 수집 항목 기준으로 고정한다.**

공공데이터와 자체 데이터의 항목 불일치는 두 방향이며, 취급이 다르다.

| 불일치 방향 | 예 | 취급 |
|---|---|---|
| SiBC는 수집하지만 공공에 없음 | 연속 심박, 수면 단계, 웨어러블 혈압·체성분 | **유지** — 공공 행에서 결측 마스크 처리. 자체 데이터가 누적되며 기여를 학습. 자체-only 재학습 시 오히려 완전해짐 |
| 공공에는 있지만 SiBC가 수집 불가 | NHANES 주변광·인종 변수, LifeSnaps EDA·VO2max 등 | **서비스 모델 입력에서 제외** — 서비스 시점에 영구 결측이라 성능 저하·편향을 만들고, 자체-only 재학습 시 학습 불가능한 죽은 입력(스키마 부채)이 됨 |

구체 규칙:

1. 통합 학습 테이블의 **입력 특징 스키마는 SiBC가 수집하는(수집 가능한)
   항목만으로 정의**한다. 공공 전용 변수는 처음부터 입력에 넣지 않는다.
2. **예측 목표는 SiBC 표준 검진 18항목과 매핑되는 것만** 생성한다. 공공
   데이터에만 있는 검사항목(예: HbA1c)은 자체 데이터로 검증할 수 없으므로
   목표로 만들지 않는다.
3. **단위 변환 방향은 항상 공공 → SiBC 단위로 고정**한다(브리징 층의 방향).
   NHANES 가속도를 SiBC 활동량 지표로 변환하며, 그 역은 하지 않는다.
4. 공공 전용 변수는 서비스에 불필요한 **사전학습·보조 과제**(auxiliary task)
   에서만 사용할 수 있다. 보조 과제의 출력은 서빙 경로에 남지 않아야 한다.
5. 이 원칙을 지키면 학습 테이블에 "우리가 만들 수 없는 값"이 존재하지
   않으므로, 자체 데이터만으로 재학습·고도화·최신화할 때 어떤 장애도 없다.

**"자체 데이터로 검증·완성했다"는 주장이 성립하는 세 가지 조건:**

1. **평가 세트에는 공공데이터가 단 한 행도 들어가지 않는다.** 모든 성능
   수치는 자체 봉인 라벨에서만 측정한다. (기존 검증 원칙과 동일)
2. **모델 버전별 데이터 계보(lineage)를 기록한다.** 버전마다 학습 구성
   (공공 n명 / 자체 n명 / 가중치)을 모델 레지스트리에 남긴다. "v1은 공공
   지배 → vN은 자체 지배 → 최종은 자체 100%"의 이력 자체가 주장의 증거다.
   TRIPOD+AI 보고 기준과도 부합한다.
3. **공공데이터 사용을 숨기지 않는다.** "자체 데이터만으로 만들었다"가 아니라
   "공공데이터로 초기 학습을 시작했고 검증·완성은 자체 데이터로 했다"로
   서술한다. ImageNet 사전학습 명시와 같은 표준 관행이며, 사용하는 공공
   데이터는 모두 상업적 이용이 허용된 라이선스다(부록 A).

**자체 모델 전환(공공 행 제외)의 계획 기준 규모** — 실제 전환은 규모가
아니라 "자체 데이터만으로 재학습한 버전이 봉인 테스트에서 통합 버전을
이기는 시점"으로 판정하되, 계획 수립에는 아래를 쓴다.

| 자체 라벨 규모 (관측창+검진 쌍) | 가능해지는 것 |
|---|---|
| 30~100명 | 내부 평가·보정 개시 (서비스 노출 없음) |
| 학습 100명 + 봉인 30명 | 자체 지도학습 개시 기준 (modeling_policy) |
| 약 300명 | 자체 지배 버전이 통합 버전과 대등~우세 시작 |
| 500~1,000명 (반복 검진 포함) | 전 항목 자체화, 하위집단 안정, M2까지 |

현재 유입 속도(연례 검진자 180명/년) 기준 1년 내 100~200쌍, 2년 내
300~400쌍이 현실적이므로, 완전 자체화 시점은 사용자 풀 확대(신규 사이트,
중국 배포)가 실질 변수다.

### 7.4 자기지도(self-supervised) 사전학습 — 통합 모델의 입력 인코더

딥러닝이 현 단계에서 정당하게 쓰이는 자리다. 라벨이 없어도 자체 웨어러블
시계열(심박 약 990만 행/217명, 수면단계 약 69만 행/183명, 걸음·활동·SpO2)과
LifeSnaps(동일 단위의 Fitbit 데이터)로 표현(representation)을 사전학습할 수
있다. 학습된 인코더의 임베딩은 통합 학습 테이블(7.2)의 특징으로 들어간다.

- 방식: 시계열 마스킹 복원(masked reconstruction), 대조 학습(contrastive),
  미래 구간 예측 등 표준 자기지도 목표로 사용자–주(week) 단위 시퀀스 인코더를
  학습한다.
- 산출: 사용자별 생체 리듬 임베딩. 이후 라벨이 수십~수백 건만 확보돼도 작은
  지도학습 헤드만 붙여 학습할 수 있어 소량 라벨 환경에 적합하다.
- 주의: 사전학습 자체는 성능 주장을 만들지 않는다. 임베딩 품질은 보조
  과제(기기 구분, 수면/활동 구간 구분 등)로만 점검하고, 검진 예측 성능은
  실제 라벨 확보 후 평가한다.
- 지금 라벨 9건에 지도학습 딥러닝을 직접 붙이는 것은 과적합만 남으므로
  금지한다. 자체 지도학습 초기는 정칙화가 강한 고전 모델(elastic net,
  histogram gradient boosting)부터 시작한다.

### 7.5 라벨 확보 가속 (가장 싸고 확실한 방법)

2026-09-01 측정: **웨어러블 사용자 중 180명이 2025년에 검진을 받은 연례
검진자**다. 이들은 대부분 향후 1년 내 2026년 검진을 받을 것이고, 이번에는
검진 전 웨어러블 이력이 존재한다. 즉 검진 결과가 앱/시스템에 연결되기만
하면 수개월 내 100~200쌍의 진짜 라벨 확보가 가능하다.

실행 항목:

1. 검진 결과 업로드 유도 캠페인 (앱 알림, 현장 안내, 검진 시즌 연계)
2. 업로드 리드타임 축소 (검진일 `measuredDt` 기준 자동 연결 확인)
3. 라벨 유입 대시보드: "관측창 보유 검진 이벤트 수"를 월별 재측정하여
   학습 개시 기준(학습 100명/봉인 30명) 도달 시점을 추적
4. 대상자 우선순위: 웨어러블 유효일 수 90일 이상(139명) 사용자부터

### 7.6 통합 프레임의 버전 궤도

```text
v1 (지금)      : 통합 테이블 구축(공공 행 지배적) + 자기지도 사전학습 + 캠페인 개시
                 → 실체는 공공데이터 모델. 자체 라벨로 참고 평가만 수행
v2~ (30~100쌍) : 재학습마다 자체 행·가중 비중 증가, 자체 봉인 라벨로 정식 평가 개시
vN (100쌍+)    : 자체 지배 버전. 항목별로 자체-only 재학습 버전과 봉인 테스트 비교
최종 (300쌍+)  : 자체-only 버전이 통합 버전을 이기는 항목부터 공공 행 제외
                 → "검증·완성은 자체 데이터" 주장 성립 (버전 계보가 증거)
```

모든 버전에서 봉인 테스트 통과 항목만 `pred_*`로 서비스하며, M1/M2 확장
조건은 8장 로드맵을 따른다.

## 8. 단계별 실행 로드맵

### Phase 0 — 지금 (통합 모델 v1 구축)

1. 별칭·단위 정규화 사전 확정(2.1 기반), 18개 표준 검진 컬럼 확정
2. 웨어러블 일별 집계 파이프라인 완성 (심박은 DB 측 집계)
3. `actual_*` + `measured_*` 산출물 서비스 개시 (모델 예측 아님을 명시)
4. 공공데이터 6종 확보(7.3) 및 **통합 학습 테이블 구축** — NHANES 브리징 층,
   출처 표시 변수, 소스별 결측 마스크 포함 (7.2)
5. 자기지도 사전학습 착수 — 자체 무라벨 데이터 + LifeSnaps (7.4)
6. 검진 결과 업로드 캠페인 개시, 라벨 유입 대시보드 (7.5)
7. 모델 레지스트리 구축 — 버전별 데이터 계보(공공/자체 구성비) 기록 (7.2)
8. 기기·수면단계·활동유형 코드북 확보
9. 합성 데이터는 파이프라인 테스트·데모 전용 (7.1)

### Phase 1 — 자체 라벨 30~100쌍 (v2~: 재학습·평가 개시)

- 재학습 주기(분기 권장) 가동: 자체 행 추가·가중 비중 상향 후 재학습
- NHIS/KNHANES 기준분포로 출력 보정, 자체 봉인 라벨로만 평가
- 이 단계의 성능 수치는 내부 참고용이며 서비스 노출 금지

### Phase 1.5 — 라벨이 최소 기준을 넘으면 (자체 지배 버전)

- 개시 조건 (modeling_policy 기준): 학습 사용자 100명 이상 + 봉인 테스트
  사용자 30명 이상 (분류는 클래스당 이벤트 30건 이상)
- 우선 항목: 혈압, 체중/BMI (근거 수준 최상, 라벨 충족률 최상)
- 항목별로 자체-only 재학습 버전을 통합 버전·기준선(모집단 평균,
  carry-forward)과 봉인 테스트에서 비교 — 이기는 항목부터 공공 행 제외

### Phase 2 — 반복 검진 라벨 누적 시 (M1/M2)

- M1: 직전 검진값 + 웨어러블. carry-forward 기준선을 이겨야 승격
- M2: 변화량 예측. 악화 방향 감지 성능(방향 정확도)을 별도 평가
- 공복혈당·지질로 항목 확장 (지질은 충족률 43%이므로 라벨 수 별도 확인)

### Phase 3 — 서비스 연계

- 검증 통과 항목만 `pred_*` 노출, 나머지는 `measured_*`/`actual_*` 유지
- "과거 검진 대비 변화" 화면은 M1/M2 검증 후에만 제공
- 병원 방문 안내·가정방문 연계 임계값은 의료진과 별도 승인 절차로 결정
- 운영 모니터링: 기기·펌웨어 변화에 따른 분포 이동 감지, 하위집단 성능 추적

### 데이터 확보 우선순위 (모델 고도화 관점)

1. **다음 검진 결과의 지속 연결** — 가장 중요. 센서 추가보다 라벨 누적이 먼저다
2. 운동 세션·VO₂max (Samsung Health Data SDK)
3. 실제 섭취시각이 있는 영양 데이터
4. 혈압·혈당·체성분 provenance (기기/보정/수동 구분)
5. 수면 단계·수면 중 SpO2 품질 정보

## 9. 안전·PII 원칙

1. 선택 환경 DB는 read-only 세션으로만 접근하고 SELECT만 실행한다.
2. 원본 사용자 식별자(UUID)와 원시 검진 JSON을 분석 산출물에 저장하지 않는다.
   사용자 키는 가명키로 치환한다.
3. DB 접속정보를 문서·코드·산출물에 포함하지 않는다.
4. `release`/`dev`/`stg`의 사용자 수준 데이터를 병합하지 않는다.
5. 검증되지 않은 성능·예측값을 사실처럼 표시하지 않는다.
6. 이 모델은 의료 진단·치료·질병 확정이 아니다. 산출물에는 "검진/진료 안내
   보조 도구"임을 명시한다.
7. 대용량 쿼리(심박 등)는 공유 DB 부하를 고려해 사전집계·타임아웃·실행시간대를
   관리한다.

## 최종 요약

- 정답(라벨)은 `discovery.disc_medical_user_info → disc_health_user_info.health_info_data`의
  검진 이벤트 1,865건(374명, 2017~2026)이며, 시간 기준은 `measuredDt`다.
- 입력(특징)은 16개 lifelog 소스이고, 심박·수면·걸음·혈압·체성분이 핵심이다.
- 우선 예측 항목은 혈압과 체중/BMI, 다음이 공복혈당과 지질이며, AST·ALT·eGFR
  등은 예측을 단정하지 않는다.
- 현재 최대 병목은 "웨어러블 관측창을 가진 검진 라벨"이 6명/9건뿐이라는 점이다
  (7일로 완화해도 13건/10명). 이를 **통합 학습 프레임**으로 돌파한다: 공공
  데이터(NHANES 등 확정 6종, 7.3)와 자체 데이터를 처음부터 한 학습 테이블에
  넣어 단일 모델을 학습하고, 재학습 주기마다 자체 비중을 키워 최종적으로
  자체-only 버전이 봉인 테스트를 통과하면 공공 행을 제외한다. 검증은 처음부터
  자체 봉인 라벨로만 하고 버전별 데이터 계보를 기록하므로 "검증·완성은 자체
  데이터로 했다"고 주장할 수 있다. 병행 수단은 자기지도 사전학습(자체 무라벨
  + LifeSnaps)과 연례 검진자 180명 업로드 캠페인이다.
- 합성(페르소나) 웨어러블 데이터로 예측모델을 학습·평가하지 않는다. 합성
  데이터는 파이프라인 테스트·데모 전용이다(순환 논리로 인해 실제 성능을
  만들지 못함).
- 모든 학습·평가는 시간 누출 금지, 사용자 분리, 봉인된 독립 테스트, ABSTAIN
  원칙을 따르며, 검증 전에는 어떤 예측값도 서비스하지 않는다.
