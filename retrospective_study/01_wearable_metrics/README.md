# 01 앱 참여도와 웨어러블 지표

앱 참여도가 높을수록 웨어러블 지표가 기준선보다 더 좋아지는지 봅니다. 특정 지표 하나로 좁히지 않고 웨어러블 지표 전체를 같은 규칙으로 분석합니다. 대상자 자격은 노출 전의 워치 착용으로 정하고(결과 기록으로 고르지 않음), 추적 자료가 부족한 대상자는 빼지 않고 결과 결측으로 둡니다.

## 자료

| 지표 | 원천 (`discovery.`) | 추출 블록 | 비고 |
|---|---|---|---|
| 걸음 | `disc_lifelog_user_step` | `steps` | 일별 합계, 0보 초과인 날만 유효 |
| 수면 | `disc_lifelog_user_sleep` | `sleep` | 수면 종료일 기준 일별 분 |
| 활동 | `disc_lifelog_user_activity` | `activity` | 일별 운동 세션 수·분 |
| 심박 | `disc_lifelog_user_heartrate` | `heartrate_days` | 기록이 있는 날만(값 없음). 표가 매우 커서 인덱스만 쓰도록 쓴 질의이며, 실행할 때 `--forbid-scan`으로 계획을 먼저 확인 |
| 산소포화도 | `disc_lifelog_user_oxygen_saturation` | `oxygen_saturation` | 일별 평균·측정 수 |
| 칼로리 | `disc_lifelog_user_calories` | `calories` | 일별 합계. 일부 기기에서만 기록 |
| 체중 | `disc_lifelog_user_body_info` | `body` | 현장 기기(플랫폼 20301103)와 개인 기기 |
| 체성분 | `disc_lifelog_user_bodyfat` | `bodyfat` | 현장 기기와 개인 기기 |
| 혈압 | `disc_lifelog_user_bloodpressure` | `bp` | 현장 기기(플랫폼 20301103, 기기 20301301)와 개인 기기 |
| 악력 | `disc_lifelog_user_grip_strength` | `grip_strength` | 현장 기기 |

추출문은 `sql/wearable_extracts.sql`(`-- @extract` 블록), 추출 파일은 `00_Data/`(2026-11-19)와 `00_Data/extract_20261120/`(git 제외)에 있습니다. 같은 SQL 파일에 현장 측정 장소와 걸음 업로드 시각 확인용 집계 블록(`site_location`, `site_location_user`, `bp_origin`, `step_origin`)도 있습니다. 심박 값(일 평균 등)은 큰 표 전체를 훑어야 하므로 아직 추출하지 않았습니다.

```bash
python3 00_common/src/run_extract.py 01_wearable_metrics/sql/wearable_extracts.sql heartrate_days 01_wearable_metrics/00_Data/extract_YYYYMMDD/heartrate_days.csv --forbid-scan disc_lifelog_user_heartrate
```

## 전 지표 목록 (`src/build_all_indicator_users.py`)

- **시간 축:** 시간 0 = 첫 걸음 기록일(등록 -30일 이후, 상한 없음). 기준선 0~13일. 노출 = 기준선이 끝난 다음 날과 등록 다음 날 중 늦은 날부터 28일. 추적 = 노출 직후 28일. 추적 창이 끝나고 28일(늦은 동기화 여유)이 자료 기준일 안에 들어와야 확정합니다.
- **대상자(노출 전):** 기준선 14일 중 워치 착용일(걸음과 심박이 모두 기록된 날)이 기준 일수 이상.
- **결과 확보(노출 후):** 닫힌 추적 28일 중 착용일(걸음 또는 심박 기록)이 기준 일수 이상. 못 채우면 '결과 결측'으로 대상자에 남깁니다.
- **지표별 판정:** 걸음·심박·수면·산소포화도·칼로리는 두 창에 각각 그 지표의 기록이 기준 일수 이상. 활동은 착용일 기준(운동이 없던 착용일은 0회). 체중·체성분·혈압·악력은 노출 창 전 90일 안 측정과 추적 시작일 이후 측정. 주 분석은 그중 추적 창(28일) 안의 첫 측정만 쓰고, 창 밖 측정은 자료 기준일까지 연장한 민감도 분석에 씁니다(목록의 `*_추적일`로 구분).
- **걸음 보조 분석:** 워치 착용과 무관하게(휴대폰 연동 포함) 두 창에 걸음 기록이 기준 일수 이상.
- 기준 일수는 `--min-days`(기본 4, 1~14)입니다. 7일·1일은 민감도 분석용입니다.
- 기본 입력은 의도한 고정 조합입니다. 공통 코호트는 공식 목록(`00_common/00_Data`, 자료 기준일 2026-11-17)이고, 지표는 2026-11-20 추출을 같은 기준일로 자른 것입니다. 다른 기준일로 만들 때는 `--data-dir`, `--common-data-dir`, `--cutoff`, `--tag`를 함께 바꿉니다.
- 사용자 목록에는 날짜·일수·상태만 적고 결과 값은 적지 않습니다.

```bash
python3 01_wearable_metrics/src/build_all_indicator_users.py --min-days 7 --tag 20261120_m7
```

## 걸음 목록 (`src/build_usable_users.py`, 2026-11-19 판 재현용)

- **걸음:** 시간 0 = 첫 걸음 기록일(등록 -28~+56일 안). 기준선 0~13일 중 7일 이상, 추적 84~111일 중 7일 이상. 추적 창이 끝나고 28일이 지나야 확정합니다.
- **수면:** 걸음과 같은 창의 유효일 수.
- **현장 측정:** 기준선 = 등록 -90~+56일의 첫 측정, 추적 = 기준선 90일 이후 첫 측정. 플랫폼 20301103에는 사이트 측정 거점이 아닌 장소의 기록과 장소가 비어 있는 다른 기기의 기록이 조금 섞여 있습니다. 장소로 걸러도 상태·기준선일·추적일은 같습니다(2026-11-20 확인, 상세는 `docs/local/`).

## 분석 자료 (`src/build_analysis_data.py`)

- DB 없이 로컬에서 분석하기 위한 지표 값 파일입니다. 사용자·창·상태는 전 지표 목록과 같은 규칙으로 다시 계산합니다.
- 대상: 주분석 대상(추적 확정 대상자)과 걸음 보조 분석 대상의 합집합. 추적 대기 대상자는 창이 닫힌 뒤 다시 만들 때 들어갑니다.
- 시트: `사용자`, `일별`(시간 0부터 12주 결과 창 끝까지 기록이 있는 날), `창별_요약`(기준선·결과·12주 창의 기록 일수와 평균), `측정`(노출 전 90일부터의 측정 행, 기록 출처·측정 장소), `측정_요약`(기준선, 결과창 안 첫 측정, 기준일까지 첫 측정), `열_설명`.
- 마곡부스 측정은 요약에서 쓰지 않습니다. 같은 날 여러 측정 행은 평균합니다. 일별 걸음은 같은 날 여러 플랫폼 기록이 추출 단계에서 합산되어 있어 `걸음_복수플랫폼`으로 표시합니다.
- 심박 값은 아직 없습니다(기록이 있는 날만). DevOps 용량 확인 뒤 추출해 추가합니다.
- 하루 운동 시간은 추출 단계에서 시작·종료 시각이 있는 세션만 합산됩니다. 일부 세션만 시간이 빈 날은 지금 추출로 구분할 수 없으므로, 다음 추출에서 시간 있는 세션 수를 함께 뽑아 확인합니다.
- 앱 사용량은 따로 둡니다(`00_common/src/build_app_usage.py`).

```bash
python3 01_wearable_metrics/src/build_analysis_data.py
```

## 정할 것

- 첫 동기화 때 그 전의 걸음 기록이 함께 올라올 수 있어, '첫 걸음 기록일'이 착용 시작일이나 첫 동기화일보다 앞설 수 있습니다. 전 지표 목록은 시간 0 범위를 등록 -30일까지 넓혀 이를 반영했습니다.
- 2026-11-20 개정판에 측정 지표와 전 지표 설계, 기록 출처(현장 기기, 개인 기기) 공변량, 거점 외 장소의 제외를 넣었습니다. 지표별 일별 값과 극단값 규칙은 통계분석계획서에 적습니다.
