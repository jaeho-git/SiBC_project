# 02 앱 참여도와 건강검진 지표

앱 참여도와 건강검진 지표의 관계를 봅니다. 특정 항목 하나로 좁히지 않고 승인 원천의 검진 항목 전체를 같은 규칙으로 분석합니다. 지금의 주 분석은 단면 분석(등록 전 검진 결과 → 등록 후 28일 앱 참여도)이고, 등록 전후 검진 변화 분석은 추적 검진이 쌓인 뒤 같은 규칙으로 합니다.

## 자료: 승인된 건강검진 원천만

- `discovery.disc_medical_user_info.user_health_sn → discovery.disc_health_user_info.health_info_data`
- JSON 배열의 `medicalUserMeasDetails` 항목, 검진일은 `measuredDt`
- 근거: `medical_checkup_model/docs/SiBC_웨어러블_건강검진예측모델_구축가이드_20260901.md`
- **쓰지 않는 자료:** 현장 측정(lifelog, 01에 속함), IRS 의료 입력값, `user_checkup_log`

추출문은 `sql/checkup_extracts.sql`에 있습니다(git 제외 추출 파일은 `00_Data/`).

| 블록 | 내용 | 추출 파일 |
|---|---|---|
| `checkup_events_all` (3판) | 분석 가능한 검진 항목 전체. 자유 기술 소견과 검진기관명·장소는 뽑지 않음 | `00_Data/extract_20261120/checkup_events_all.csv` |
| `checkup_events` (2판) | 신체계측·혈압·혈당·지질. 입력 시각과 레코드 번호, 빈 값 포함 | `00_Data/extract_20261120/checkup_events.csv` |

## 전 항목 목록 (`src/build_all_item_users.py`)

- **항목:** 22개(혈압은 수축기·이완기를 각각 한 항목으로 셈). 키, 체중, 체질량지수, 허리둘레, 수축기 혈압, 이완기 혈압, 공복혈당, 총콜레스테롤, HDL, LDL, 중성지방, 혈색소, AST, ALT, 감마지티피, 혈청 크레아티닌, 사구체여과율, 요단백, 시력, 청력, 흉부 소견, 종합 판정. 두 가지 이름으로 기록된 항목은 하나로 합칩니다. 골다공증·요소질소·적혈구용적률·혈소판은 인원이 적어 쓰지 않습니다.
- **중복 입력:** 같은 사용자·검진일·항목은 가장 늦게 입력된 값을 씁니다(입력 시각, 레코드 번호 순). 그 값이 비었거나 잘못되면 그 항목은 없는 것으로 봅니다. 범주 항목은 값이 있으면 유효로 보고, 판정 기준은 통계분석계획서에 적습니다.
- **기준선:** 항목별로 등록 전 24개월~등록일 사이 가장 최근의 유효한 검진일.
- **추적:** 항목별로 등록 후 29~365일 사이 첫 유효한 검진일(나중의 변화 분석용, 기준선이 있는 사용자만).
- 검진 값과 로그인 일수는 적지 않습니다. 단면 분석에서는 검진 결과가 노출이고 앱 참여도가 결과이기 때문입니다.
- 기본 입력은 의도한 고정 조합입니다. 공통 코호트는 공식 목록(자료 기준일 2026-11-17)이고, 3판 추출(2026-11-20)을 같은 기준일로 자른 것입니다. 다른 기준일로 만들 때는 `--data-dir`, `--common-data-dir`, `--cutoff`, `--tag`를 함께 바꿉니다. 분기마다 다시 만들면 추적 검진이 쌓이는 정도를 볼 수 있습니다.
- 겹치는 10개 항목의 기준선·추적 검진일은 2026-11-19 목록과 사용자 단위까지 같습니다(2026-11-20 확인).

## 2026-11-19 목록 (`src/build_usable_users.py`, 재현용)

- 2판·1판 추출의 체중·체질량지수·허리둘레, 혈압, 공복혈당, 지질 10개 항목만 씁니다. 같은 날 1판·2판으로 만든 목록과 11-19 목록이 사용자 단위까지 같음을 확인했습니다.
- 혈압 "120/80"은 수축기·이완기로 나눕니다. 기준선·추적 규칙은 위와 같습니다.
