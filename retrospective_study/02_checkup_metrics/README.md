# 02 앱 참여도와 건강검진 지표

앱 참여도와 건강검진 지표의 관계를 봅니다. 특정 항목 하나로 좁히지 않고 승인 원천의 검진 항목 전체를 같은 규칙으로 분석합니다. 전 항목 추출은 `sql/checkup_extracts.sql`의 `checkup_events_all`(신체계측, 혈압, 혈당, 지질, 혈색소, 간·신장 기능, 요단백, 시력·청력·흉부 소견, 종합 판정)입니다. 자유 기술 소견과 검진기관명·장소는 뽑지 않습니다. 항목 목록과 범주 값은 `checkup_field_catalog`, `checkup_category_values` 집계로 확인했습니다. 2026-11-19 목록 도구는 재현을 위해 2판(`checkup_events`, 신체계측·혈압·혈당·지질)을 그대로 씁니다.

## 자료: 승인된 건강검진 원천만

- `discovery.disc_medical_user_info.user_health_sn → discovery.disc_health_user_info.health_info_data`
- JSON 배열의 `medicalUserMeasDetails` 항목, 검진일은 `measuredDt`
- 근거: `medical_checkup_model/docs/SiBC_웨어러블_건강검진예측모델_구축가이드_20260901.md`
- **쓰지 않는 자료:** 현장 측정(lifelog, 01에 속함), IRS 의료 입력값, `user_checkup_log`

추출문은 `sql/checkup_extracts.sql`(`-- @extract checkup_events` 2판, `checkup_events_v1` 1판), 추출 파일은 `00_Data/checkup_events.csv`(2026-11-19, 1판)와 `00_Data/extract_20261120/checkup_events.csv`(2판)입니다(git 제외).

## 현재 기준 (`src/build_usable_users.py`)

- 같은 사용자·검진일·항목이 여러 번 들어온 경우 가장 늦게 입력된 값을 씁니다. 2026-11-19 추출(1판)에는 입력 날짜만 있어서, 2026-11-20 추출부터는 입력 시각과 레코드 번호, 빈 값까지 함께 뽑습니다(2판). 같은 날 1판·2판으로 만든 목록과 11-19 목록이 사용자 단위까지 같음을 확인했습니다. 가장 늦은 입력의 값이 비었거나 잘못된 값이면 그 항목은 없는 것으로 봅니다. 가장 늦은 입력이 같은데 값이 다른 경우는 xlsx `안내` 시트에 건수를 적습니다.
- 혈압 "120/80"은 수축기·이완기로 나눕니다.
- **기준선:** 등록 전 24개월~등록일 사이 가장 최근 검진(항목별로 그 항목의 가장 최근 검진).
- **추적:** 등록 후 29~365일 사이 첫 검진(항목별로 그 항목의 첫 검진).
- 사용자 목록에는 날짜와 상태만 적고 결과 값은 적지 않습니다.

## 현재 상태

등록 후 검진을 받은 사용자가 아직 적습니다. 그래서 기준선→추적 변화 분석은 추적 검진이 쌓일 때까지 기다립니다. 각 사용자의 `추적창_종료일`이 지나면 목록을 다시 만듭니다. 그때까지는 기준선 검진 상태와 앱 참여도의 관계(단면)만 볼 수 있습니다.
