# 채팅으로 제공된 최신 지시·세계관 요약 (원문 첨부파일 아님)

**주의:** 이 문서는 사용자가 채팅 본문으로 제공한 내용을 인수인계용으로 요약한 것이다. 사용자가 업로드한 독립 원문 파일로 가장하지 않는다.

## 2026-10-28 세계관 추가
- 슬로건 `Designing Your Life, Beyond Time`은 iSignature(과거)·iPresent(현재)·iFuture(미래 선택)를 한 시간축에서 연결하는 제품 정의.
- 환자여정은 W→M1→M2→M3→W의 나선형이며, 핵심 자산은 데이터 양이 아니라 개입·반응·결과가 연결된 종단 기록.
- EMR은 기록 계층, 인바이츠루프는 그 위의 운영 계층. IDW는 Population Health 운영 현장.
- 3대 KPI는 안정성/임상 유효성→수용성→재무구조 개선. 6대 지침은 판단 기준, 3+1은 진화 방향.
- **V5는 3대 KPI 측정체계 시작, V6는 3+1 본격 도입**. 단, 이번 컴피티션에서는 사용자가 3+1의 초기 실제 작동을 최우선 전략으로 지정.
- 실증 장소(울산·제주·심천·미국)와 효과는 지향/검증 계획이지 이 문서에서 성과를 검증한 것이 아님.

## UX/UI 관련 사용자 제공 장문
- `Everything Behind. Almost Nothing in Front.`; `Same Data, Different Expression.`; 누구도 소외되지 않는 UI.
- W는 대화 중심 건강 자아 공간, M1은 Patient Summary, M2는 Dynamic Priority Queue, M3는 Shared Health View.
- 조용한 홈, 사용자 선택에 따른 자아 생성 의식, 결론→이유→상세 데이터, 침묵을 포함하는 SiBC 개입.
- 기존 건강앱·EMR 요약·알람 대시보드·원격관리 포털처럼 보이면 재설계하라는 Design Kill Rule.

## 개발·데이터 최신 의사결정
- 실제 백그라운드 DB의 근거 확보·표준화·모델 검증은 2주에 완료하기 어렵다.
- **근거 기반 합성 페르소나 DB**로 3+1 작동을 검증하고, 데이터 사용 가능성·품질·근거·권한·상태 전이를 표준 계약으로 구현.
- 데이터분석가의 핵심 역할은 Persona DB, Data Usability Gate, Evidence Trace, 종단간 테스트셋, KPI 측정 명세, 개선안 평가.
- 합성 결과를 실제 임상·재무 성과로 혼동하지 않는다.

## H1 보강 관련 제공 설명
- 권한·환자 분리, 최신 계획 조회, 근거 없는 임상 초안 제거, 승인/취소 반영, 중복 요청/보류/재개, 외부 출력 검증 보강.
- 사용자 설명상 코어 62/62, Chromium 34/34, 명시적 테스트 저장소 98/98 통과. **실제 테스트 로그/코드는 본 패키지에서 독립 검증하지 않음**.
