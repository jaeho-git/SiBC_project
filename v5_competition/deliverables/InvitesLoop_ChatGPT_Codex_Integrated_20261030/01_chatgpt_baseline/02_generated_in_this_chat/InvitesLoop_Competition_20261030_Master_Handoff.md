# 인바이츠루프 AI Agent 컴피티션 — 최신 통합본 / Codex 인수인계

**2026-10-30 기준.** 본 문서는 이전 4개 분석·전략·인수인계 문서의 중복을 최신 사용자 지시로 통합한다. 공식 공지, 회장님 비전, 실행 제안을 구분한다. 실제 코드·임상 결과는 독립 검증하지 않았다.

## PART 1. 결론
공식 개발 대상은 **V5 프로토타입 고도화**다. 실무 방향은 **V6를 지향하는 3+1(JITAI·온톨로지·Human-in-the-Loop·재귀적 자기개선)의 최소 작동을 V5 고도화 결과물에 구현**하는 것이다. 공식 버전명이 V6로 변경된 것은 아니다. 회장님 최신 세계관은 ‘V5=3대 KPI 측정체계 시작, V6=3+1 본격 구현’으로 구분한다. 이번 공지의 3+1 ‘이해·적용’ 및 사용자의 최신 우선순위를 반영해 **완전 구현이 아닌 검증 가능한 초기 구현**을 목표로 한다.

실제 건강 데이터·근거·예측모델을 2주 안에 모두 완성하려 하지 않는다. **근거 기반 합성 페르소나 DB → 데이터 품질/사용 적합성 → 온톨로지 → JITAI → 의료진 승인 → 결과 기록 → 개선안 평가**를 하나의 여정에서 실행한다. 합성 데모를 임상적 유효성으로 주장하지 않는다.

- 과제: **W→M1→M3** 연속 경험, IRS+·SiBC·iCHMS 연계, V5 세계관/기능, 설치·운영·유지보수 표준화. M2는 전체 세계관에 포함되지만 공지의 필수 연결 경로와 구분.
- **34점:** 세계관·3대 KPI·6대 지침·3+1 이해/적용. **33점:** 기술 완성도/통합. **33점:** 현장 구축/운영/재구현. 3+1만 34점인 것은 아니므로 운영 66점도 준비.
- 공지상 우승팀 기술/개발방식 중심 통합, 임원 제외 전원 특진 및 연봉 재협상 권한. 상세 채점표/평가 시연 방식은 미확인.

## PART 3. 세계관·OS·UX
**Designing Your Life, Beyond Time:** iSignature(과거), iPresent(현재), iFuture(미래의 조건·선택)를 한 시간축에 연결한다. 미래를 예언하는 것이 아니라 삶의 궤적을 이해하고 변경 가능한 선택을 탐색한다. W(일상)→M1(외래)→M2(입원)→M3(퇴원 후)→W의 나선형 환자여정에서 **개입·반응·결과**를 연결해 축적한다.

- **L3 OS:** 앱·키오스크·닥터웹·경영 화면, 미래 Agent/Physical AI의 공통 기억·권한·명령.
- **IRS+:** 유전체 기술 융합 위험 특성. 실제 개인 유전체 입력 여부와 검증된 개인 위험 산출 여부 구분.
- **Signature:** 축적된 개인 맥락·목표·제약·표현 선호. **SiBC:** 개입·침묵·재확인; JITAI는 SiBC 내부 기능. **iCHMS:** 계획·승인·수행·운영/재무 백본.
- **C1/C2/L3:** 데이터·관계 / LLM 해석·설명 후보 / 권한 검증된 명령 실행. C2가 원장·의사 승인·실제 완료를 임의 확정하지 않음.
- **UX:** Everything Behind, Almost Nothing in Front; Same Data, Different Expression; 누구도 소외되지 않는 UI. W 대화 중심, M1 Patient Summary, M2 Dynamic Priority Queue, M3 Shared Health View. 결론→이유→상세. 기존 건강 대시보드/EMR 요약/알람 나열의 단순 복제 금지.

## PART 4. 3대 KPI·6대 지침·3+1
**3대 KPI(측정의 축):** ① 구동 안정성(임상 유효성·규제 적합성 포함) ② 사용자·환자·의료진 수용성 ③ 병원 재무개선 효과성. 안정성→수용성→재무효과는 실증해야 할 가설이다. 재무 시뮬레이션/관찰 실적/검증된 귀속효과를 혼동하지 않는다.

**6대 지침(판단의 기준):** ① AI·유전체 기업 역사와 IRS+ 위험·우선순위를 W/M1/M2/M3에 반영(법률 검토 후 표시) ② 의사 확정 질환은 다음 W에서 의사 판단으로 전달 ③ 첫 W의 위험 이해→M 의료진 확인→신뢰 실증 ④ 지침 인용과 개인 판정 구분, 개인 맥락 온톨로지 ⑤ 규제 불명확 기능은 법률·병원 협의/샌드박스 검토 ⑥ 유전체 기관 분석·의사 화면·동의 연구군 실증 및 신뢰·이행률·의사 불일치율 측정.

| 3+1 | 이번 경쟁의 최소 실제 작동 | V6 본격 고도화 |
|---|---|---|
| JITAI | 맥락·동의·데이터 품질·유효 계획에 따라 개입/침묵/재확인, 이유 기록 | 개인별 적응 최적화 |
| 온톨로지 | 자기보고·측정·추정·임상판단·계획·개입·반응·결과의 관계/출처/시점/버전 | 장기 개인 온톨로지 |
| HITL | 검토·승인·수정·보류·거절·적용/수행 상태 및 권한 | 돌봄 최적화 협업 |
| +1 자기개선 | 평가→개선 후보→고정 시험→인간 승인→버전 적용/롤백 | 검증된 반복 최적화 |

## PART 5. 합성 페르소나 DB 전략
실제 백그라운드 데이터의 품질·근거·표준화·모델 검증은 별도 장기 과제다. **Evidence-Driven Persona Simulation**으로 기능과 실패 처리를 검증한다. 모든 시드는 **SYNTHETIC / DEMO ONLY**. 페르소나별 답변 하드코딩 금지, 데이터 변경에 따른 판단 변화 입증.

| 페르소나 | 검증 목적 |
|---|---|
| P01: 품질 적합·승인 계획 | 기본 W→M1→M3→W |
| P02: 결측·오래된 값·충돌 | ABSTAIN/재확인 |
| P03: 생활 제약 변경 | JITAI·변경 요청 |
| P04: 의료진 승인 대기 | HITL·계획 버전 |
| P05: 반복 개입·반응·결과 | 개선안 평가·롤백 |

**최소 데이터 계약(제안):** `persona_id`(가상), `source_kind`, `value_kind`, `observed_at`, `recorded_at`, `valid_until`, `unit`, `quality_flags`, `purpose`, `consent_scope`, `evidence_refs`, `model_version`, `validation_status`, `plan_version`, `decision_id`, `intervention_id`, `outcome_id`, `approval_state`. 실제 저장소 스키마 확인 후 확정. `actual`, `measured`, `pred`, `risk`, `scenario` 및 품질점수·위험점수·확률 구분. **time/user/environment leakage** 방지. 품질점수와 사용 가능성 판정은 별개(권한·목적·시점도 필요). 상태값은 공식 사전 확인 후 매핑.

**SiBC 강제 경계:** Reliability 공식 scoring scope는 **exercise only**. 건강검진 예측은 **BLOCKED_BY_DATA**로 검증된 모델 성능·개인 예측이 없다. 근거 부족 시 **ABSTAIN/검토 필요**. 원시 식별자·원시 건강정보·Secret 출력 금지. 의료 진단/치료 판단 대체 금지.

## PART 6. 종단간 3+1 데모
1. **W:** P03이 저녁 운동이 어렵다고 말함 → `reported` 기록, 동의·유효 계획 조회.
2. **온톨로지:** 자기보고·측정·추정·의사 확정과 근거/시점/계획 버전 구분.
3. **데이터 게이트:** 출처·신선도·권한·목적 확인, 부족하면 보류/재확인.
4. **JITAI:** 허용된 일정 변경 후보 제안 또는 침묵. 장기 IRS+ 위험만으로 급성 안전 신호 낮추지 않음.
5. **M1/HITL:** 의료진 승인·수정·보류. 미승인 변경은 현재 계획으로 표시 금지.
6. **M3→W:** 같은 사실을 역할별 표현으로 공유, 최신 승인 계획만 다시 W에 적용.
7. **+1:** 합성 반응/수행/결과 별도 기록→개선안 평가→인간 승인 후 적용/롤백.
8. **실패 데모:** P02에서 ABSTAIN; 타 환자/기관 접근 거부; 중복 요청 중복 실행 금지; 취소 요청≠취소 확인; 준비 완료≠측정 완료.
