# 인바이츠루프 다중 데이터 기반 UX UI 심화 분석과 추가 자료 요구사항

2026-10-30 정리: 현재 요청과 변경 사항은 [최신 요청 통합본](InvitesLoop_Latest_Request_Handoff_20261030.md)을 우선 적용한다. 이 파일은 데이터·과업·추가 자료에 관한 상세 분석으로 보존한다.

작성일: 2026년 10월 29일 한국시간  
상태: 제품 발견·콘텐츠 설계 분석. 새 시스템·모델의 구현 또는 임상·사용성 검증 결과가 아님.  
적용 문서: [콘텐츠 분석 개정안](UX_UI_Content_Strategy_v2_20261029.md), [시안 비교 기준](UX_UI_Concept_Comparison_Criteria_20261029.md)

## 1 이번에 확인된 전제

1. 일반사용자·의료진·병원 재무담당자 모두 필수 대상이다. 한 집단의 UX로 나머지를 대체하지 않는다.
2. 회장님은 챗봇 형태를 오래된 방식으로 지적했다. 특정 선호 제품·화면은 없다.
3. 채팅 중심의 주 화면과 긴 대화 이력에 의존하는 과업은 제외한다. 필요한 자연어 입력은 보조 수단으로 검토한다.
4. 새 시스템을 개발하되 웨어러블·건강검진·식이분석·루틴·개인화에 관한 과거 경험을 참고한다. 기존 구현을 그대로 이어 붙이는 작업은 아니다.
5. 현재 단계는 콘텐츠와 사용 방식의 전문적 분석이다. 실제 화면·DB·에이전트 구현은 시작하지 않는다.

이 분석에서 중요하게 다룰 질문은 ‘어떤 데이터를 많이 보여줄 것인가’가 아니라 ‘어떤 상황에서 누가 어떤 결정을 내리기 위해 어느 수준의 근거를 필요로 하는가’다. 데이터 출처별 메뉴나 에이전트별 화면을 먼저 확정하지 않는다.

## 2 전문화를 위해 보완할 분석 수준

기존 개정안은 제품 방향과 콘텐츠 범위를 정리한 문서다. 역할별 실제 과업과 운영 제약을 현장에서 확인한 요구사항 명세는 아직 아니다. 전문화는 용어와 분량을 늘리는 작업보다, 설계 판단과 근거·미확인 사항을 추적할 수 있게 만드는 작업이어야 한다.

| 분석 수준 | 현재 확인한 내용 | 더 필요한 근거 | 결정할 수 있는 것 |
|---|---|---|---|
| 제품 의도 | 회장님의 방향·세계관·세 역할·챗봇 지양 | 실제 업무에서 가장 바뀌어야 할 경험과 우선 과업 | 제품의 첫 가치와 시안의 비교 장면 |
| 사용자 맥락 | 역할 범주 | 실제 생활·진료·정산 과정, 언어·기기·이해도·접근 제약 | 역할 안의 하위 사용자와 제공 방식 |
| 서비스 흐름 | W·M1·M3·다음 W의 원칙 | 누가 접수·판단·실행·확인하며 어디서 끊기는지 | 화면 간 인계, 담당·기한·상태 |
| 데이터 의미 | 기존 데이터 종류와 일부 설계 문서 | 최신 항목 사전·코드·출처·시간·결측·적용 범위 | 표시 가능 정보와 확인이 필요한 정보 |
| 판단과 행동 | 승인·권한·근거 원칙 | 임상·운영 책임, 도구·서비스의 실제 가능 범위 | 자동 수행·사용자 확인·의료진 검토의 경계 |
| 경험의 검증 | 평가표와 합성 과업 제안 | 기존 불편·사용 로그·역할별 관찰과 인터뷰 | 가설의 수정과 시안 선택 |

NHS는 의료 서비스의 임상적·실무적·정서적 요구와 주변 업무 체계를 함께 이해하도록 안내한다. GOV.UK도 기존 증거·관찰·인터뷰를 바탕으로 사용자 요구와 과업을 추적하도록 권고한다. 여기서는 분석 방법의 참고로 사용하며 우리 제품의 유효성을 입증하는 근거로 사용하지 않는다 [P1–P3].

원시 건강정보·DB·인증정보를 열거나 조회하지 않았다. 아래는 문서와 정의 파일을 읽은 범위다. 과거 문서의 데이터 현황·모델 수치·API 상태를 현재 시점에서 재검증한 것은 아니다.

| 자료 | 검토 범위와 확인한 의미 | 재사용 후보 | 자동 승계하지 않을 것 |
|---|---|---|---|
| 식이분석 README | 목적·역할·2026-10-26 상태·규칙·문서 관계 | 미기록과 결식 구분, 거짓 알람 부담, 결과·규칙과 전달의 분리 | 과거 구현·DB·성능이 새 제품에도 적합하다는 주장 |
| 식이분석 시스템 설계 | 목적·결정·입력·처리·완전성·시간 정렬 관련 절 | 식사와 웨어러블의 시간 차이, 비교 기간, 판정 범위 축소 | 수신 지연 통계·초안 임계치·알람 주기의 새 제품 적용 |
| 건강검진 모델 README | 과거 실험·설계·감사·출력 분리 관련 내용 | 실제 검진·기기 관찰·예측 구분, 적용 가능성 검토 항목 | 기록된 실험 성능의 재인증 또는 새 제품 사용 승인 |
| 건강검진 schema.yaml | 항목·단위·별칭·특징·창 정의 | 항목 사전 초안과 검진값 출처 설명 | 해당 항목 전체가 현재 사용 가능하다는 가정 |
| 생활패턴 질문 뱅크 v4 | 목적·응답·노출 조건·통계 원칙·대표 문항 | 쉬운 표현, 모름 응답, 개인 내 비교, 반박보다 재확인 | 수면·스트레스·식이의 공식 Reliability 점수 |
| SDK–Lifelog 통합 분석 | 2026-07-31 문서의 구분·인벤토리·시간·수집 검토 절 | 직접값·요약·예측의 구분, 기기·출처·관찰일 관리 | 과거 수집 현황이나 미래 수집 제안을 현재 기능으로 표시 |
| Clinical Validation 데이터 계약 | 모의 어댑터·근거·판단 상태의 개념 | 자료·판단·근거·보류·검토 상태 구분 | 운영 Clinical Layer API가 존재한다는 가정 |
| 저장소 전체 README | 모델 목록·역할·보안·상태 | 과거 업무의 범위와 자료 탐색 | 모듈별 최신 README와 다른 상태 표기 |

Lifestyle Change Model README와 PROJECT_RULES는 현재 내용이 비어 있었다. 따라서 그 파일만으로 생활습관 변화 기능의 구현 상태를 판단할 수 없다.

건강검진 모델 README에는 과거 실험 결과가 기록돼 있고, 이번 Handoff는 예측 기능을 BLOCKED_BY_DATA로 제한한다. 검토 범위·시점이 다를 수 있으므로 이 차이를 ‘모든 연구 결과가 없음’ 또는 ‘이미 제품 검증 완료’로 단정하지 않는다. 이번 경쟁에서는 Handoff의 제한을 유지하고, 향후 적용 여부는 최신 모델 카드·입력 범위·평가 보고서·책임자 확인 자료로 판단한다. 실제 건강검진 결과를 보여주는 기능은 검진값을 예측하는 기능과 별개다.

## 4 데이터별로 맡길 역할

| 데이터 | 제품에서 답할 질문 | 필요한 맥락 | 적절한 표현 | 피할 해석 |
|---|---|---|---|---|
| 건강검진 | 언제 무엇이 실제로 확인됐고 이후 무엇을 점검할 것인가 | 검사일·항목·단위·검사기관·검토 상태·재검 여부 | 날짜가 명확한 결과와 승인된 후속 계획 | 몇 달 전 값을 현재 상태로 표현, 개인 예측으로 대체 |
| 웨어러블·연결기기 | 관찰 가능한 생활·측정에서 무엇이 달라졌는가 | 기기·측정/추정/수동입력·착용·관찰창·수신 시점 | 비교 가능한 변화와 자료 범위 | 미착용=비활동, 늦게 받은 자료=현재 자료 |
| 식사 기록·식이분석 | 기록 범위에서 어떤 식사 패턴과 검토 근거가 있는가 | 음식·양·식사시각·기록일·완전성·추정 방법·기준 | 기록된 범위의 변화와 필요한 확인 | 미기록=결식, 사진 추정=실제 섭취량의 정답 |
| 루틴의 계획·완료 | 무엇을 하기로 했고 실제로 무엇이 확인됐는가 | 목표·승인 계획·사용자 응답·실행 증거·시점 | 계획·보고·관찰·미확인을 분리 | ‘했다고 답함’=기기가 증명함, 열람=수행 |
| 생활패턴 인식 | 사용자가 자신의 생활을 어떻게 인식하는가 | 질문 목적·응답·근거 기간·기기 관찰 범위 | 쉬운 패턴 확인과 모름·정정 | 불일치=거짓말, 연관 패턴=원인 |
| 선호·목표·생활 제약 | 어떤 도움을 받아들이고 실제로 할 수 있는가 | 직접 표현 여부·확인 시점·사용 허용 범위·변경 | 바꿀 수 있는 개인 맥락과 선택 | 한 번의 발언을 영구 성향으로 고정 |
| 의료진 판단·관리계획 | 어떤 판단이 현재 계획의 근거인가 | 확정 주체·일시·버전·적용 기간·제약 | 확정 판단과 현재 유효한 계획 | AI 초안을 의사 확정으로 표시 |
| 서비스·운영·재무 | 조치가 실제로 어디까지 진행됐고 비용이 어떻게 발생했는가 | 담당·접수·실행·확인·비용·청구·수납 | 상태와 집계 범위가 분명한 진행·실적 | 요청만으로 매출·절감·성과 생성 |

웨어러블에서 수신한 값이라도 모두 생리량의 직접 측정은 아니다. 예를 들어 기기 산출 소모열량·수면단계 같은 파생 값은 해당 기기·알고리즘의 추정으로 식별해야 한다. ‘수신된 관찰’, ‘기기가 계산한 추정’, ‘새 제품 모델의 예측’도 구분한다.

검진은 간헐적이고 웨어러블은 연속적으로 보이지만, 실제로 언제 자료가 도착했는지는 별도다. 식사 발생 시각·입력 시각·수신 시각, 검진 채혈일·보고일, 기기 측정 시각·동기화 시각을 구분해야 한다. FHIR Observation도 관찰의 유효 시점, 공개 시점, 값 부재 사유를 구분한다. 이 문서가 FHIR 채택이나 적합성 구현을 결정하는 것은 아니다 [P4].

## 5 여러 데이터를 함께 해석할 때의 원칙

### 5.1 연결 전에 확인할 조건

1. 같은 사람의 자료인지, 해당 역할이 그 목적으로 사용할 수 있는지
2. 관찰 기간·현지 날짜·수신 시점이 실제로 비교 가능한지
3. 자료가 해당 결정을 뒷받침할 만큼 존재하고 의미가 확인됐는지
4. 직접 관찰·자기보고·계산·추정·의료진 판단을 구분했는지
5. 충돌·결측이 있을 때 확인할 주체와 진행 경로가 있는지

조건이 맞지 않으면 유용한 정보 전체를 지우기보다 해당 설명·비교·조치를 제한한다. 식사 기록만 설명할 수 있어도 섭취–소모 비교는 보류할 수 있다. 웨어러블이 없어도 검진 확인·의료진 계획·도움 요청은 가능할 수 있다. 각 기능의 적용 조건은 별도로 정한다.

### 5.2 다중 데이터가 늘어날수록 필요한 절제

- 늦은 식사와 검진값 변화가 함께 나타나도 원인으로 단정하지 않는다.
- 활동량이 적게 관찰됐는데 사용자가 운동했다고 답하면 운동 종류·착용·관찰 범위를 확인한다. 사용자의 정직성 점수로 바꾸지 않는다.
- 한 번의 거절이나 참여 감소를 동기 부족으로 고정하지 않는다. 비용·통증·돌봄·시간·접근 문제일 수 있다.
- 여러 도메인을 합쳐 단일 건강·신뢰 점수를 만들지 않는다. 공식 Reliability exercise only 원칙을 유지한다.
- 과거 한국 기준·집단 참조·식품 DB가 중국 개인에게 적합하다고 가정하지 않는다. 목표 지역의 적용 대상·단위·음식·표준·권한을 확인한다.

### 5.3 기존 자산의 규칙과 새 제품의 선택권

과거 식이분석은 사용자 목표를 직접 판정 기준으로 쓰지 않는 설계다. 이것은 해당 분석 모듈의 범위이며 새 제품 전체에서 목표·선호를 받지 말라는 요구는 아니다. 새 제품에서는 사용자의 생활 목표, 임상적으로 승인된 계획, 영양 평가 기준을 구분해야 한다. 목표를 전달할 수 있어도 검증된 기준·안전·의료진 계획을 임의로 덮어쓰게 하지 않는다.

기존 계산 규칙을 참고하는 것과 기존 알림 빈도·기본 홈·설문 흐름·임계치를 복제하는 것은 다르다. 새 제품에서 필요한 판단을 먼저 정의하고 적합한 과거 자산만 추적 가능하게 참조한다.

## 6 세 사용자군별 심화 분석

### 6.1 일반사용자

초기 가설은 검진 이후 관리가 필요한 사람, 지속 관리 중인 사람, 진료·퇴원 이후 사람, 기기 없이 생활 지원을 받는 사람을 구분하는 것이다. 실제 분포·우선 사례는 아직 확인되지 않았다. 가족·보조 이용자의 권한도 별도로 다룬다.

| 결정 | 필요한 근거 | 전면에 둘 내용 | 필요한 보조 행동 |
|---|---|---|---|
| 지금 무엇을 확인할까 | 최신 승인 계획·현재 서비스 상태·중요한 변화 | 다음 행동과 이유·시점 | 확인·일정 변경·도움 요청 |
| 이 내용은 내게 왜 해당할까 | 검진·생활 맥락·관련 기록 범위·의료진 판단 | 관련된 개인 맥락과 자료 시점 | 근거 확인·오류 정정 |
| 오늘 계획을 어떻게 이어갈까 | 일정·통증·시설·선호·승인된 범위 | 실행 가능한 선택과 확인 필요 상태 | 제약 전달·변경 요청 |
| 내 상황이 제대로 반영됐나 | 최근 응답·관찰·맥락 확인 이력 | 반영된 내용과 아직 모르는 내용 | 정정·사용 중지·보류 |
| 누가 나를 도와주나 | 접수·담당·운영시간·연락·의뢰 상태 | 사람과 서비스의 연결 상태 | 문의·연락·연결 실패 대응 |

추가 조사에서는 ‘어떤 데이터를 좋아하는가’보다 마지막으로 결과를 이해하지 못했던 순간, 기록을 포기한 순간, 계획을 지키기 어려웠던 이유, 사람의 설명이 필요했던 순간을 묻는다. 모두 실제 경험에서 확인한다. 자연어로 모든 것을 설명하게 하거나 알고 있는 정보를 반복 입력하게 하지 않는 것이 핵심 가설이다.

### 6.2 의료진

의사·간호사·상담사·사례관리자·약사의 실제 참여 여부와 업무를 확인해야 한다. 각자 확인·승인·실행할 수 있는 범위가 다르므로 ‘의료진’ 단일 권한을 가정하지 않는다. 모두를 별도 시안으로 만들어야 한다는 뜻은 아니며 주요 과업과 권한에 따라 구분한다.

| 결정 | 필요한 근거 | 전면에 둘 내용 | 필요한 보조 행동 |
|---|---|---|---|
| 이 환자의 무엇이 달라졌나 | 마지막 검토 시점·검진·관찰·자가보고 | 중요한 변화·시점·미확인 사실 | 원자료 확인·추가 확인 |
| 자료를 이 판단에 써도 되나 | 수집 의미·관찰 기간·결측·충돌·모델 상태 | 적용 범위와 판단 제한 | 보류·자료 요청 |
| 현재 계획이 적합한가 | 병력·약물·기능·통증·수행·생활 제약 | 기존 계획과 검토 근거 | 독립적 수정·승인·거절 |
| 누가 다음 일을 맡나 | 기관 업무·책임·연락 경로·처리 여력 | 담당·기한·실행·결과 상태 | 배정·인계·재확인 |
| 무엇을 환자에게 전달할까 | 확정 판단·설명 선호·현재 계획 | 환자가 이해할 변화와 다음 행동 | 설명 수정·이해 확인 |

핵심 추가 자료는 진료 전·중·후 실제 흐름과 허용 시간이다. 알림을 만들 수 있어도 검토할 사람이 없다면 좋은 UX가 아니다. 민감한 상태의 분류 기준, 평상시와 운영시간 외 대응, 접수 이후 책임을 확인해야 한다. 시안으로 임상 임계치를 정하지 않는다.

### 6.3 병원 재무담당자

경영 책임자·관리회계·청구·수납·계약 담당 중 누가 실제 사용자인지 확인한다. ‘병원 재무’에 필요한 모든 업무를 처음부터 하나의 화면으로 합치지 않는다. 세 사용자군의 동등한 포함과 역할 안의 과업 우선순위는 별개다.

| 결정 | 필요한 근거 | 전면에 둘 내용 | 필요한 보조 행동 |
|---|---|---|---|
| 실적 차이는 어디서 왔나 | 기간·범위·서비스·이용·매출·비용·기준 | 차이와 주요 원인 | 집계 정의·원인 상세 |
| 이 서비스는 지속 가능한가 | 검토·상담·연락·배송·수수료·계약 | 수익과 관리 부담을 연결한 집계 | 서비스별 비교 |
| 미완료는 무엇인가 | 청구·수납·미수·환불·정산 | 담당·기한·금액·지연 이유 | 해당 업무로 연결 |
| 조건을 바꾸면 무엇이 달라지나 | 승인된 가정·비용 포함 범위·산식 | 기준안과 변경안의 차이 | 가정 변경·비교·저장 |
| 제품 효과라고 말할 수 있나 | 비교설계·귀속 검증·자료의 완결성 | 관찰 변화와 미검증 가정의 구분 | 근거·책임자 확인 |

건강검진·식이·루틴의 개인 원자료를 재무 화면에 직접 넣을 이유는 보통 별도로 입증해야 한다. 재무 판단에는 관련 서비스 이용과 업무량·비용의 적정 집계가 우선이다. 개인 건강 위험을 구매 가능성이나 매출 잠재력으로 변환하는 것을 기본 경험으로 두지 않는다.

## 7 같은 합성 사례로 콘텐츠를 구체화하는 방법

아래는 분석을 위한 상황 설명이다. 실제 환자도, 의학적 판정도, 제작된 화면도 아니다.

### 사례 A 검진과 생활 기록의 시간과 범위가 다른 경우

- 과거 검진 결과가 있다. 현재 상태와 동일하다는 근거는 없다.
- 최근 식사 기록이 일부 있지만 전체 식사인지 확인되지 않았다.
- 웨어러블 자료는 다른 기간에서 늦게 도착했다.
- 사용자는 근무 일정 때문에 식사 시간이 달라졌다고 말했다.

| 역할 | 제공할 내용 | 보류·배제할 해석 |
|---|---|---|
| 일반사용자 | 검진일·현재 관리계획·기록 범위·필요한 다음 확인, 생활 제약 정정 | 식사 변화가 검진 악화 원인이라는 단정, 현재 섭취–소모 균형 |
| 의료진 | 자료별 시간과 관찰 범위, 사용자 제약, 확인할 질문, 현재 계획 | 비교 불가능한 기간을 합친 종합 위험 결론 |
| 재무담당자 | 실제 상담·후속 연결이 발생했다면 관련 업무·비용 집계 | 건강정보 자체를 매출이나 예방 성과로 환산 |

이 사례는 데이터가 많을수록 무조건 정교한 개인 판정을 만들 수 있다는 가정을 점검한다.

### 사례 B 승인된 관리계획을 수행하기 어려운 경우

일정 제약과 운동 후 불편을 전달했을 때, 일반사용자는 짧게 상황을 전하고 도움·변경 요청 상태를 확인한다. 의료진은 임상적 검토가 필요한 내용과 일정 조정을 구분하고 근거를 확인한다. 재무담당자는 실제로 발생한 상담·검토·후속 업무의 적정 집계만 확인한다. 이 단계에서 운동 강도 변경이나 추가 약 구매를 자동 결정하지 않는다.

### 사례 C 웨어러블이나 식사 기록이 없는 경우

기기 연결이나 매일의 기록을 모든 가치의 진입 조건으로 만들지 않는다. 사용할 수 있는 검진·계획·자기보고만으로 제공 가능한 서비스를 정의하고, 특정 비교·개인화는 자료가 없어 제한됨을 표현한다. 전 데이터 수집을 완료할 때까지 이용을 막거나, 누락을 나쁜 건강·낮은 참여·거짓 응답으로 해석하지 않는다.

## 8 추가 자료의 우선순위

### 8.1 먼저 준비하면 가장 도움이 되는 다섯 묶음

파일이 없으면 아래 내용을 텍스트로 설명해도 된다. 기존 자료는 최신본 경로와 유효 범위를 알려주면 된다. 원본 환자 자료, 전체 DB 덤프, 인증정보는 현재 분석에 필요하지 않다.

| 순서 | 요청 자료 | 최소 준비 범위 | 해결할 설계 결정 | 현재 상태 |
|---|---|---|---|---|
| 1 | 세 역할의 실제 대표 과업·불편 | 각 역할에서 가장 중요한 과업 3개, 최근 사례 1개, 현재 처리 방법 | 역할별 시작점과 콘텐츠 우선순위 | 세 역할 모두 필수인 것은 확인. 세부 과업은 미확인 |
| 2 | 기존 제품에서 배울 경험 | 개인정보를 가린 주요 화면·사용 흐름·사용자/의료진 의견. 가능하면 ‘유지/개선/폐기’ 이유 | 과거 시행착오의 재발 방지, 챗봇을 대체할 상호작용 | 방향 자료는 있음. 실제 이용 경험 근거는 추가 필요 |
| 3 | 최신 데이터 항목 사전과 대표 출력 | 웨어러블·검진·식이·루틴별 항목 뜻·단위·시각·결측·파생 방법과 합성 예시 | 어떤 판단을 어떤 수준으로 설명할 수 있는지 | 일부 옛 정의·설계 확보. 최신 적용 범위는 미확인 |
| 4 | 서비스 업무·권한·책임 흐름 | 검토·승인·연락·예약·처방·약사 심사·배송·후속 확인의 실제 담당·상태 | 화면 행동의 의미, 자동화 범위, 실패 후 연결 | 원칙은 있음. 현장 흐름·도구는 미확인 |
| 5 | 중국 VISTA의 이용·운영·재무 조건 | 사용 언어·기기·접점, 실제 제공 서비스, 가격·비용·정산 항목과 가정 구분 | 현지 적합성, 세 역할의 서비스 연결, 재무 콘텐츠 | 사업 시뮬레이션 참고자료는 있음. 실제 운영 조건은 추가 필요 |

첫 묶음의 예시 형식은 ‘검진 후 어떤 행동을 해야 할지 모르는 사용자’, ‘진료 전 생활 변화를 확인할 시간이 부족한 의료진’, ‘서비스별 인력 부담을 알기 어려운 재무담당자’다. 이것들은 현재 확인된 실제 요구가 아니라 작성 형식을 설명하는 가설이다.

회장님이 선호하는 제품이 없다는 답변은 이미 받았으므로 이를 필수 요청 자료로 다시 올리지 않는다. 시안 단계에서 새로운 비교 자극을 만들어 반응을 확인하는 방법이 적합하다. 말풍선·긴 대화 중심의 경험을 지양한다는 제약은 현재부터 적용한다.

### 8.2 있으면 분석의 신뢰도를 높이는 자료

| 자료 | 필요한 범위 | 용도 |
|---|---|---|
| 과거 사용 분석 | 집계된 진입·이탈·기록 중단·알림 반응·오류·문의 유형과 기간·분모 | 실제 부담이 있는 지점 확인. 관찰 차이를 인과로 단정하지 않음 |
| 모델·규칙 카드 | 입력·출력·목적·적용 대상·검증 상태·금지 용도·책임자 | 예측·판정·단순 요약의 표시 가능 범위 |
| 현장 의견·회의 기록 | 사용자·의료진·재무 각각의 불편과 원하는 결과, 발언 맥락 | 실제 요구와 이해관계자 가설의 구분 |
| 권한·동의·서비스 경계 | 기관·역할·공유·철회·위임·전문가 검토 범위 | 개인화와 자동화의 범위 |
| 브랜드·언어 기준 | 로고·서체·톤·중문 명칭·접근성·기기 제약 | 시안의 시각적 품질과 일관성 |
| 평가단의 추가 공지 | 이미 알려진 배점 외 직접 조작·설치·라이브 시연 방식의 변경 | 경쟁 시나리오와 검증 범위 |

추가 모델 학습 데이터·전체 DB 구조·모든 지역 법률 검토·전 지역 상세 원가는 콘텐츠 분석을 시작하기 위한 선행조건으로 두지 않는다. 다만 실제 운영·연동·출시 전에는 해당 범위의 자료가 필요할 수 있다.

## 9 데이터 담당자에게 요청할 간단한 항목 설명 양식

각 도메인의 핵심 항목부터 작성한다. 모든 컬럼을 한 번에 정리할 필요는 없다. 값은 합성 예시로 충분하다.

| 항목 | 작성할 내용 |
|---|---|
| 이름·뜻 | 사용자에게 말할 수 있는 의미, 관련 코드·단위 |
| 생성 경로 | 직접 측정·기기 추정·자기보고·기록·모델 계산·의료진 판단 |
| 시간 | 실제 발생·측정 시각, 입력·수신·갱신 시각, 시간대 |
| 관찰 범위 | 일·회·기간 단위, 필요한 유효 관찰 범위 |
| 부재 의미 | 미수집·미착용·미기록·거절·적용 불가·실패 구분 |
| 사용 조건 | 동의·역할·목적·신선도·확인·모델 검증 |
| 갱신·정정 | 변경·철회·오류 정정 경로와 반영 시점 |
| 출력과 한계 | 대표 결과, 확실히 말할 수 있는 것과 말할 수 없는 것 |
| 버전·담당 | 최신 정의·규칙 버전, 의미와 적용 범위를 확인할 담당 |

특히 루틴은 먼저 세 가지를 확인해야 한다. 행동을 하기로 한 계획인지, 수행 여부의 자기보고인지, 평소 생활패턴에 대한 인식 질문인지다. 같은 ‘루틴’ 이름으로 합치면 표시 문구·효과 평가·사용자 신뢰에 모두 오류가 생길 수 있다.

## 10 이후 콘텐츠마다 작성할 의사결정 기록

이 양식은 구현 스키마가 아니라 콘텐츠의 필요성과 근거를 검토하는 도구다.

| 필드 | 기록할 내용 |
|---|---|
| 역할·상황·목적 | 누가 언제 무엇을 결정하려는가 |
| 요구 근거 | 실제 경험·관찰·회의 지시·설계 가설 중 무엇인가 |
| 입력 근거 | 어떤 도메인의 어느 기간·시점·출처를 쓰는가 |
| 적용 조건 | 의미·품질·권한·검증이 충분한가 |
| 첫 요약 | 그 순간 먼저 알아야 하는 사실·의미·행동은 무엇인가 |
| 상세 근거 | 어떤 자료·기간·기준·한계를 확인할 수 있는가 |
| 가능한 행동 | 선택·수정·검토·승인·요청 중 무엇이 가능한가 |
| 책임과 상태 | 누가 판단·실행하며 완료는 무엇으로 확인하는가 |
| 부재·실패 | 자료 부족·충돌·연결 실패에 무엇을 보여주는가 |
| 개인화와 통제 | 어떤 선호·제약을 반영하며 정정·중지는 가능한가 |
| 평가 | 사용자가 해당 과업을 채팅 없이 이해·완료했는지 어떻게 확인할 것인가 |

## 11 실제 조사와 분석의 진행 순서

1. 이미 확인된 요구와 자료를 바탕으로 세 역할 각각의 과업 가설·미확인 사항을 작성한다.
2. 추가 자료 다섯 묶음에서 핵심 정보만 받아 실제 사례와 비교한다. 자료가 없는 곳은 가설로 남긴다.
3. 각 역할의 생활·진료·정산 흐름에서 자료·판단·담당·실행·결과가 끊기는 지점을 정리한다.
4. 다중 데이터의 의미·시간·적용 조건을 검토해 콘텐츠 의사결정 기록을 만든다.
5. 필수·상황별·상세·제외 콘텐츠와 보조 입력을 확정할 수 있는 수준으로 정리한다.
6. 사용자 확인 후 화면 후보를 제작한다. 세 역할에 동일한 자료·과업을 두고 미감과 사용 방식의 지속성을 별도 비교한다.

필요하면 각 역할의 실제 사용자와 짧은 과업 인터뷰·관찰을 반복한다. 최소한 최근 사례와 기존 처리 과정을 살피고, 가상 기능의 선호만 묻지 않는다. 인터뷰·시험 인원은 목적과 접근 여건에 맞춰 정하며 소수의 탐색 결과를 전체 수용성·효과 검증으로 보고하지 않는다. 이번 작업에서 외부 사용자·의료진에게 연락하거나 조사를 실행한 것은 아니다.

## 12 최소 회신 양식

아래 양식은 파일 없이 텍스트로 답해도 된다. 모르면 미정으로 남기고 분석을 진행한다.

1. 일반사용자: 가장 중요한 과업 3개 / 기존 서비스에서 불편했던 장면 1개
2. 의료진: 가장 중요한 과업 3개 / 진료·관리 중 실제 확인 가능한 시간과 담당
3. 재무담당자: 가장 중요한 과업 3개 / 필요한 실적·비용·정산 지표
4. 기존 제품·운영 참고자료: 최신 자료 경로 / 유지할 점 / 바꿀 점
5. 데이터: 최신 정의 파일 경로 / 루틴의 의미 / 대표 출력 합성 예시의 유무
6. 중국 적용 조건: 주요 언어·기기·앱 접점 / 실제 제공 서비스 / 검토·수행 책임의 미정 사항

모든 항목에 답하기 전까지 작업을 멈추는 방식은 아니다. 현재 자료로 할 수 있는 분석은 진행하고, 최종 콘텐츠·기능 범위를 확정할 수 없는 부분을 표시한다. 세 역할 필수·챗봇 형태 지양·선호 제품 없음은 이미 확인됐으므로 양식에서 다시 묻지 않는다.
