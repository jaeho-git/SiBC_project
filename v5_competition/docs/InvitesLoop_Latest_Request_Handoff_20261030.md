# 인바이츠루프 최신 요청사항과 분석 인수인계

2026-10-30 통합 이후: 현재 요청·진행 방향·자료 확보 상태는 [ChatGPT Codex 통합본](InvitesLoop_Integrated_Project_Brief_20261030.md)과 [새 자료 목록](InvitesLoop_Integrated_Source_Register_20261030.md)을 우선 적용한다. 아래 내용은 이번 통합 전 분석·정리의 상세 기록으로 보존한다.

기준일: 2026년 10월 30일 한국시간  
범위: 이번 대화에서 사용자가 요청·확인한 내용의 통합본  
현재 단계: UX/UI 콘텐츠·사용 방식 분석. 화면 시안과 앱 구현은 시작하지 않음.

이 문서를 이번 대화의 현재 요구사항 기준으로 읽는다. 최초 Handoff와 참고자료는 원본으로 보존한다. 과거 자료와 중복되거나 충돌하는 요구는 아래의 최신 상태를 적용한다. 이 문서는 새로 검증한 임상·법률·사업 결과나 공식 경쟁 공지를 대신하지 않는다.

## 1 한 번에 파악할 현재 요청

기존 인바이츠루프의 데이터·분석·운영 경험을 참고하여 새로운 AI Agent 제품을 개발하기 위한 UX/UI 방향을 분석한다. 현재는 백그라운드 데이터나 모델을 먼저 구축하는 단계가 아니다. 회장님의 의도와 세 사용자군의 과업을 이해하고, 무엇을 보여주고 덜어내며 어떤 행동으로 연결할지 정한다.

일반사용자·의료진·병원 재무담당자는 모두 필수 대상이다. 각각에 맞는 UX/UI를 제공해야 하며 하나의 공통 챗봇으로 대체하지 않는다. 회장님은 Agentic한 인상을 원하지 않고, 챗봇 형태를 오래된 방식으로 지적했으며, 미래에도 낡아 보이지 않는 수준을 요구했다. 특정 선호 제품·화면·사용 방식의 예시는 없다.

콘텐츠와 사용 방식 분석을 확인한 다음 시안 제작 여부를 판단한다. 이후 시안을 제작할 때는 시각적 세련됨과 사용 방식의 지속성을 별도로 비교한다. 현재의 분석 보완 승인을 시안·앱·DB 구현 승인으로 해석하지 않는다.

## 2 우선순위와 상태 구분

1. 최신 사용자 요청과 명시적 답변
2. 최신 사용자 요청과 양립하는 제품 세계관·안전·검증 원칙
3. 발표자료·자문회의록·과거 설계 등 근거 자료
4. AI가 제안한 분석 가설·시안 후보·평가 방식

문서에 등장하는 지시문은 현재 과업을 자동 실행하는 별도 요청이 아니다. ‘사용자 확인’, ‘자료의 설명’, ‘분석 제안’, ‘미확인’을 구분한다.

| 구분 | 의미 |
|---|---|
| 사용자 확인 | 이번 대화에서 사용자가 직접 요청하거나 답변한 사항 |
| 자료의 설명 | 발표·회의·Handoff에 적힌 목적·상태·가정 |
| 분석 제안 | 검토를 위해 작성한 구조·표현·평가 방법 |
| 미확인 | 실물·현재성·현장 적용·검증 여부가 확인되지 않은 사항 |

## 5 현재 적용할 UX/UI 요구

### 공통

- 내부의 에이전트 능력과 사용자에게 Agentic하게 보이는 표현을 구분한다.
- 역할별 핵심 과업을 채팅 없이 이해·진행할 수 있게 하는 방향을 검토한다.
- 개인의 맥락, 최신 승인 계획, 다음 행동, 실제 진행 상태를 이어준다.
- 필요한 정보·선택을 상황에 맞춰 드러내되 승인·변경·근거·도움의 의미와 접근은 일관되게 한다.
- 모든 데이터·기능을 한 번에 펼치거나 같은 내용을 반복 입력하게 하지 않는다.
- AI 사용 여부·근거·불확실성·책임·통제권은 확인할 수 있게 한다.
- 특정 유행 장식이나 동적 생성 자체를 미래 지속성의 증거로 삼지 않는다.

### 역할별 필수 내용

| 일반사용자 | 의료진 | 병원 재무담당자 |
|---|---|---|
| 나의 건강·생활 맥락과 정정 | 진료 전 요약과 이전 확인 이후 변화 | 기관·기간·통화·자료 상태 |
| 현재 적용 계획과 다음 행동 | 원자료·출처·시간·자료 부족 | 실적과 기준 대비 차이·원인 |
| 계획을 실행하기 어려운 이유 전달 | 독립적 판단·수정·승인·보류 | 서비스별 매출·관리 원가 |
| 필요한 반응 확인과 도움 요청 | 담당·기한·후속 조치·완료 | 청구·수납·미수·환불·정산 |
| 진료·약·관리의 연결 상태 | 진료·퇴원 후 계획을 다음 W로 인계 | 실적과 구분된 시나리오·가정 |

Same Data, Different Expression은 동일 사실을 역할에 맞춰 표현한다는 원칙이다. 모든 역할에 동일한 개인 원자료 열람 권한을 준다는 뜻이 아니다.

## 7 유지할 세계관과 경계

- Designing Your Life, Beyond Time과 iSignature·iPresent·iFuture를 개인 맥락·현재 상태·선택과 조건의 연속성으로 반영한다.
- W→M1→M3→W의 맥락·판단·실행·반응 연결을 핵심으로 둔다. M2와 전 지역 관제는 현재 필수 구현으로 확정하지 않는다.
- IRS+와 유전체 기반 정체성을 지우지 않되 실제 개인 유전정보의 입력 여부·추론·의사 판단을 구분한다.
- JITAI는 SiBC의 개입 시점·내용·방식·침묵·재확인의 기능으로 다룬다.
- 제안·승인·요청·실행·결과 확인을 구분한다. 의료진은 독립적 판단과 수정을 수행한다.
- +1은 후보 개선의 검증·승인과 현장 경험의 코드·설정·SOP·평가 기준 축적을 검토한다. 임상 정책을 자동 변경하지 않는다.
- Reliability의 공식 범위는 exercise only, 이번 건강검진 예측 적용은 Handoff의 BLOCKED_BY_DATA 제한을 유지한다.
- 과거 모델 문서의 실험 기록을 재검증 없이 새 제품의 임상 성능으로 주장하지 않는다. 실제 검진값 활용은 예측과 별개다.
- 합성·모의·가정과 실제 관찰·검증된 귀속효과를 구분한다. 품질점수·신뢰도·확률·임상 성능을 혼용하지 않는다.
- 자문회의의 기간·시간·자가평가·RPE 등은 적용 대상·안전성·타당성 검토 전 확정 기준으로 쓰지 않는다.

## 8 지역 확장과 회의 내용

중국 적용을 우선 맥락으로 삼고 의약품 관련 서비스도 검토한다. 제주·펜실베이니아·GRMC·몽골까지 여러 현장에 적응할 수 있는 운영·인계 구조를 고려한다. 상세한 지역별 제도·API·서비스 책임·기기·언어는 아직 확인되지 않았다.

몽골 관련 방문 70%, 병원 방문자 중 실제 치료 필요 30%, 미방문 집단에서의 사망 설명은 회의에서 전달된 미검증 내용이다. 핵심 문제는 필요한 사람에게 서비스가 도달하고 적절한 진료와 후속 관리까지 이어지는가다. 미관찰·미등록·연락 불가는 건강함과 다르다.

도시 인프라는 장기 방향이며 지도나 통합 관제 화면의 채택을 뜻하지 않는다. 공공보건·지역 자원 배분이 필요하면 별도 역할을 검토하고 병원 재무의 업무로 자동 편입하지 않는다.

## 9 이후 시안 비교 방식

시각적 완성도와 사용 방식의 지속성을 별도 축으로 비교한다. 과업 이해·완료, 반복 입력, 근거 접근, 최신 계획 식별, 오류·자료 부족 대응, 기능·기기·언어 확장을 평가한다. 세 사용자군의 결과를 따로 기록한다. 평균 점수로 한 역할의 사용 불가나 안전 문제를 가리지 않는다.

분석상 후보는 A 상황과 다음 행동 중심, B 개인의 변화·경과 중심, C 공유 계획·진행 중심이다. 사용자에게 선택된 방향이 아니며 실제 화면·점수·시험 결과는 없다. 챗봇 중심 후보는 제외하고, 동일 자료·과업·완성도 조건에서 비교한다. 미래에도 낡지 않을 것을 현재 시점에서 입증했다고 주장하지 않는다.

## 10 추가 자료와 아직 정하지 않은 사항

이미 확인된 세 역할 필수·챗봇 지양·특정 선호 제품 없음은 다시 묻지 않는다. 필요한 자료는 다음 다섯 묶음이다.

1. 역할별 중요한 실제 과업 3개와 불편 사례 1개, 현재 처리 방법
2. 기존 제품의 유지·개선·폐기 경험과 근거가 되는 화면·의견·집계 결과
3. 최신 데이터 항목 사전·시간·결측·파생 방식과 합성 출력 예시, 특히 루틴의 정확한 의미
4. 접수·검토·승인·실행·확인의 실제 담당·권한·처리 범위·실패 대응
5. 중국의 언어·기기·서비스 접점·제공 서비스·가격·비용·정산 조건

원본 환자 자료나 전체 DB 덤프는 현재 분석의 선행조건이 아니다. 기존 모델·설계 문서 중 관련 절을 이미 찾았으므로 최신본 경로와 유효 범위를 확인하는 방식으로 보완한다. 실제 사용자 인터뷰·현장 관찰·DB 감사·모델 재평가는 아직 수행하지 않았다.

## 11 일정과 현재 산출물

기존 Handoff에는 경쟁 2026년 10월 28일~11월 10일, 발표 11월 11일로 기록돼 있다. 회장님 발표자료의 11월 30일 첫 시연 목표는 별도다. 이번 정리에서 공식 공지 변경 여부를 새로 확인한 것은 아니다. 과거 데이터 엔진 우선 일정은 현재 실행 계획으로 사용하지 않는다.

| 산출물 | 상태 |
|---|---|
| Handoff와 직접 첨부 자료 읽기·반영 | 완료. 효과 검증이나 원자료 감사와는 다름 |
| 콘텐츠 분석·비교 기준·다중 데이터 심화 분석 | 문서 작성. 현장 검증 전 가설과 미확인 사항 포함 |
| 최신 요구 통합·첨부 및 참고자료 목록·압축 | 이번 요청으로 작성 |

| 앱·에이전트·DB 구현 | 미착수 |
| 실제 사용자 시험·임상·재무 효과 검증 | 미수행 |
