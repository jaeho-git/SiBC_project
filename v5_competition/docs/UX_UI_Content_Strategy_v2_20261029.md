# 인바이츠루프 UX UI 콘텐츠 분석 개정안

2026-10-30 통합 이후: 현재 요청·진행 방향·자료 확보 상태는 [ChatGPT Codex 통합본](InvitesLoop_Integrated_Project_Brief_20261030.md)과 [새 자료 목록](InvitesLoop_Integrated_Source_Register_20261030.md)을 우선 적용한다. 아래 내용은 이번 통합 전 분석·정리의 상세 기록으로 보존한다.

2026-10-30 정리: 현재 요청과 변경 사항은 [최신 요청 통합본](InvitesLoop_Latest_Request_Handoff_20261030.md)을 우선 적용한다. 이 파일은 역할별 콘텐츠의 상세 분석으로 보존한다.

작성일: 2026년 10월 29일 한국시간  
상태: 콘텐츠 검토안. 최신 사용자 확인 사항과 다중 데이터 심화 분석을 추가함. 화면 시안과 앱 구현은 아직 진행하지 않음.  
범위: 중국 적용 V5 컴피티션을 위한 세 사용자군의 정보·행동 설계. 지역 확장은 후속 호환성 관점에서 검토.

이 문서는 대화에서 작성한 분석에 회장님 발표자료, 운동처방 전문가 자문회의록, 최신 디자인 요구를 반영한 첫 파일 저장본이다. 파일의 v2는 대화상 분석의 개정을 뜻한다. 이번에 승인된 작업은 분석 보완과 이후 시안 비교 기준 수립이다. 구체적인 화면 제작은 콘텐츠 확인 이후에 진행한다.

추가 확인 사항: 세 사용자군 모두 필수 대상이다. 회장님이 특정 선호 제품을 제시한 것은 아니지만, 챗봇 형태를 오래된 방식으로 지적했다. 따라서 채팅창·말풍선·대화 이력을 주 화면과 주요 업무 흐름으로 삼는 안은 제외한다. 자연어는 필요한 상황 전달·검색·짧은 응답을 위한 보조 입력으로 검토한다. 각 역할의 계획·판단·조치·분석을 구조적으로 확인할 수 있어야 한다. 이 확인은 아래의 이전 검토 가설보다 우선한다.

웨어러블·건강검진·식이분석·루틴 및 개인 맥락의 역할, 실제 자료 확인 범위, 추가로 필요한 자료와 조사 방법은 [다중 데이터 심화 분석과 추가 자료 요구사항](UX_UI_Research_Requirements_and_Multisource_Analysis_20261029.md)을 함께 적용한다. 기존 모델·규칙·DB 구조는 참고 자산이며 새 제품에 자동 승계하지 않는다.

## 1 목적과 핵심 판단

인바이츠루프는 사용자가 여러 에이전트를 지휘하지 않아도 개인의 건강 맥락, 의료진의 판단, 실제 서비스 수행이 이어지는 경험을 지향한다. 동시에 현재의 채팅창이나 대시보드 형식에 제품 전체를 고정하지 않는다.

장기적으로 유지할 핵심은 개인의 맥락, 현재 유효한 계획, 다음 행동, 판단·승인 주체, 수행과 반응의 연속성이다. 입력과 표현 방식은 사용자·상황·기기에 맞게 발전할 수 있어야 한다. 특정 외형이 미래에도 낡지 않을 것이라고 보장할 수는 없다. 이번 분석에서는 재학습 부담, 맥락 승계, 기능 확장과 오류 대응 능력을 통해 그 가능성을 검토한다.

| 사용자군 | 먼저 답할 질문 | 콘텐츠의 중심 |
|---|---|---|
| 일반사용자 | 내 상황에서 지금 무엇을 선택하거나 확인하면 되는가 | 나의 맥락, 현재 계획, 다음 행동, 반응 전달, 의료 연결 |
| 의료진 | 누구의 어떤 변화를 확인하고 무엇을 판단·조치해야 하는가 | 중요한 변화, 근거, 독립적 판단, 계획 변경, 후속 조치 |
| 병원 재무담당자 | 실적과 비용이 왜 달라졌고 무엇을 조정해야 하는가 | 실적·가정 구분, 변동 원인, 정산, 관리 원가, 시나리오 |

## 2 요구와 근거를 구분하는 방법

| 구분 | 자료의 의미 | 이번 적용 |
|---|---|---|
| 최신 사용자 지시 | 현재 수행 범위와 우선순위 | 콘텐츠 분석을 먼저 보완하고 시안은 이후 검토 |
| 회장님 발표자료 | 제품 방향, 세계관, 조직 차원의 현황 설명 | 개인 정체성, 나선형 여정, 조치·결과·원가 연결을 반영 |
| 전문가 자문회의록 | 운동·생활관리 개선에 대한 전문가 의견 | 입력 부담, 주관적 반응, 개인별 기능과 사람의 개입을 반영 |
| Handoff | 개발·검증 지침과 제약 | 안전·권한·근거·상태 구분을 유지하고 개발 순서는 현재 요청에 맞춤 |
| 공개 자료 | 특정 시점의 제품 사례와 설계 원칙 | 사례의 존재와 발표 시점을 뒷받침. 우리 제품의 효과나 선호를 입증하지 않음 |
| 이 문서의 제안 | 자료를 프로젝트에 적용한 해석 | 실제 사용자·회장님 검토와 후속 시험이 필요한 설계 가설 |

발표자료 12장의 ‘입력창 하나’는 과거 제품 방향의 근거로 보존한다. 최신 사용자 확인에서는 챗봇 형태에서 벗어나는 것을 요구했으므로 입력창 중심의 시작 화면을 이번 권고로 채택하지 않는다. 필요한 자연어 입력과, 계획·선택·승인·결과를 확인하는 업무 구조를 구분한다. 에이전트가 내부에서 작동해도 사용자가 에이전트와 계속 대화해야 서비스를 이용할 수 있는 구조로 만들지 않는다.

발표자료에 조직 차원의 프로토타입과 연동 진행이 설명돼 있어도 이번 작업 공간에 소스가 제공된 것은 아니다. 사용자 지시에 따라 로컬 V5 코드는 없는 상태로 취급한다. 기능 성숙도는 설계·구현·현장 사용·효과 검증을 구분한다.

## 3 과거 사례에서 가져올 원칙

다음은 2020년부터 현재까지의 대표 사례를 이번 의사결정에 연결한 요약이다. 전 시장의 완전한 계보나 우열 평가가 아니며, 초기 AI 기능과 현재의 에이전트 제품을 같은 범주로 단정하지 않는다.

| 시기와 사례 | 확인한 내용 | 이번 적용 |
|---|---|---|
| 2020 Microsoft 인간 AI 상호작용 지침 | AI의 능력·한계와 맥락에 맞는 기대 설정 | 근거 부족과 승인 필요를 숨기지 않음 [E1] |
| 2021 Apple Health | 변화 추세와 사용자가 선택하는 정보 공유 | 건강정보 전체 나열보다 중요한 변화와 공유 통제 [E2] |
| 2023 Bard 발표 | 자연어 대화를 통한 탐색 | 일상 언어 진입을 활용하되 모든 업무를 대화에 가두지 않음 [E3] |
| 2024 Claude Artifacts | 대화와 분리된 결과물 공간 | 결정·계획·결과를 다시 찾고 확인할 수 있게 함 [E4] |
| 2025 Gemini Canvas | 결과물을 확인하고 수정하는 상호작용 | 설명을 읽는 것에서 비교·선택·수정으로 연결 [E5] |
| 2025 Dragon Copilot | 임상 기록·후속 문서 등 업무 흐름과 AI의 연결 | 의료진의 기존 판단 흐름 안에서 정보와 조치를 제공 [E6] |
| 2026 EHR 요약 도구 무작위시험 사전공개 연구 | 업무 부담 감소와 별개로 시간 절감·지속 사용의 과제가 보고됨 | AI 요약량보다 실제 과업과 오류 확인을 평가. 단일 의료체계의 미동료심사 연구임 [E7] |

이 사례들에서 ‘대화는 오래됐고 동적 화면은 미래’라는 결론을 내리지 않는다. 필요한 표현과 안정적인 조작을 조합하는 것이 이번 설계의 가설이다.

## 4 미래에도 유지할 경험의 기준

### 4.1 사용자에게 보일 것

- 나를 어떤 맥락으로 이해하고 있는지와 정정 방법
- 현재 유효한 계획, 중요한 변화, 다음에 필요한 행동
- 제안·검토·승인·실행·결과의 구분과 책임 주체
- 정보를 확인한 시점·출처와 판단의 한계
- 선택·거절·보류·도움 요청과 오류 이후의 진행 경로

### 4.2 노출을 줄일 것

- 에이전트별 이름·분업·추론 과정과 작업 중계
- 모든 측정값·설정·가정을 한 번에 펼치는 정보 과밀
- 사용자가 매번 과거 상황을 다시 설명해야 하는 흐름
- 반복 문진·일률적 알림·프롬프트 학습 부담
- 기술적 새로움을 대신하는 장식과 과도한 움직임

AI 사용 사실과 승인·불확실성은 확인 가능해야 한다. 조용한 경험은 설명 책임을 없앤다는 뜻이 아니다. 자동 수집도 동의와 권한이 확인된 범위에서만 가능하다.

### 4.3 일관성과 적응의 경계

| 유지할 것 | 상황에 맞게 바꿀 것 |
|---|---|
| 승인·변경 요청·근거·도움 요청의 의미와 찾는 방법 | 현재 가장 필요한 정보의 우선순위 |
| 현재 계획과 초안의 구분 | 설명의 길이와 전문성 |
| 동일 기능의 이름과 반복 탐색의 일관성 | 글·음성·선택 응답 등 입력 방식 |
| 개인정보·공유·취소에 대한 사용자 통제 | 상황 설명, 경과, 비교, 진행 상태의 표현 |
| 현재 사용자·환자·기관·기간의 식별 | 기기·언어·접근성에 맞는 밀도와 배치 |

중요 조작을 AI가 임의로 이동하거나 매번 새 이름으로 생성하는 방식은 지양한다. W3C의 일관된 탐색·기능 식별 지침과 Google PAIR의 맥락 설명·통제 원칙을 참고한다 [E8–E10].

## 5 일반사용자 콘텐츠

일반사용자는 건강한 사람, 지속 관리 중인 환자, 진료·퇴원 직후의 사람을 포함한다. 가족의 보조 이용은 별도 권한과 공유 범위를 전제로 한다. 모든 상태에 같은 과제·점수·상품을 제공하지 않는다.

| 내용 | 보여줄 시점 | 표현과 가능한 행동 | 상세로 둘 내용 |
|---|---|---|---|
| 나의 건강 맥락 | 최초 확인, 중요한 정정·변화 때 | 확인된 사실·선호·생활 제약 요약, 정정 | 전체 기록과 출처 |
| 현재 계획과 다음 행동 | 일상 진입, 진료 후, 계획 변경 후 | 적용 내용·시점·확인 주체, 선택·일정 변경 요청 | 전체 계획과 이전 버전 |
| 중요한 변화 | 검토할 변화가 있을 때 | 이전 대비 변화·관찰 시점·확인 필요 여부 | 원자료와 긴 경과 |
| 운동·생활관리 반응 | 필요한 수행 전후와 재검토 때 | 체감 강도·통증·피로·회복·어려움의 짧은 전달 | 동의한 세부 기록 |
| 의료·돌봄 연결 | 상담·진료·후속 확인이 필요할 때 | 이용 경로·담당·진행·연결 실패 시 대안 | 기관 정보·이용 조건 |
| 의약품 | 관련 처방·주문·복약 관리가 있을 때 | 검토·구매·조제·배송·수령과 문의 구분 | 품목·비용·상세 안내 |
| 나의 변화와 선택 | 정기 검토, 목표·계획 선택 때 | 확인된 경과와 다음 선택, 적용 조건 | 검증 근거가 있는 분석 |
| 지지자·지역 활동 | 사용자가 원하거나 관련 지원이 있을 때 | 선택 참여·공유 범위·중단 | 프로그램 설명 |

입력은 자연어·음성·선택 응답 등으로 열어두되, 반드시 필요한 안전 확인을 빠뜨리지 않는다. 기본 확인과 심화 확인을 나누고, 이미 확인한 정보는 최신성·목적·권한에 문제가 없는 범위에서 재사용하는 것을 검토한다.

운동 미수행은 시간 부족·이동·시설·통증·부담 등 이유를 전달할 수 있게 한다. 일정 변경과 임상적 운동량·강도 변경을 구분한다. 실제 RPE 척도와 해석, 자가평가 항목, 조정 기준은 전문가 검토 전 확정하지 않는다 [S3].

iSignature는 유전체에 한정하지 않는 건강 맥락이다. IRS+의 역할은 관련 설명에서 드러내되, 실제 개인 유전정보 입력 여부와 추론을 구분한다. 신규 검사를 이용 조건으로 만들지 않는다. iFuture는 선택의 조건과 계획을 비교할 수 있게 하되 검증되지 않은 질병 확률이나 건강 개선 수치를 제시하지 않는다 [S2: 13·20·23장].

기본 화면에서 제외할 내용은 근거 없는 종합 건강점수, 에이전트 지휘 기능, 모든 원자료의 동시 나열, 건강 위험과 결합한 구매 압박이다. 아바타·게임화·카메라 자세분석은 후속 검토 대상으로 둔다.

## 6 의료진 콘텐츠

진료 담당과 지역 돌봄·사례관리 담당의 업무·열람 권한을 구분한다. 검토 대상 목록은 공통 업무 기능이며, 이를 M2 입원 Priority Queue의 구현으로 간주하지 않는다.

| 내용 | 보여줄 시점 | 표현과 가능한 행동 | 상세로 둘 내용 |
|---|---|---|---|

임상적 긴급성, 연락 필요, 자료 부족을 하나의 모호한 점수로 합치지 않는다. 분류·임계치·에스컬레이션 기준은 확정된 임상·운영 규칙이 있을 때 적용한다. 데이터가 없다는 이유로 안전한 상태를 추정하지 않는다.

의사는 AI 제안에 동의하는 역할에 한정되지 않는다. AI 추론과 의사 확정을 구분하고, 수정·보류·추가 확인을 동등한 업무로 제공한다. 출처 없는 결론, 긴 반복 요약, 개별 환자의 매출 잠재력은 주요 판단 내용에서 제외한다 [S2: 23장].

실적을 표현하는 항목은 실제 자료가 확보됐을 때의 요구사항이다. 현재 경쟁용 예시 수치는 합성·가정으로 표시한다. 자료가 없으면 공백·미수신 상태를 보여주고 0이나 가상의 실적으로 대체하지 않는다.

`simulation`, `observed`, `verified_attributable`을 구분한다. 유지율 변화가 곧 제품의 귀속효과는 아니다. 관리 요청·실제 수행·청구·수납도 같은 실적이 아니다. 환자 수·방문 건수·주문 건수의 단위를 구분한다.

병원의 ΔEBITDA, 건강보험의 의료비, 지자체의 돌봄 지출, 제공 조직의 구축·유지보수 원가를 하나로 합치지 않는다. 추정 회피비용은 실제 재정 절감액과 다르다. 기관 간 효과 중복과 추가 운영비를 검토해야 한다 [S2: 14·17·22·28장].

VISTA 페이지의 입력·가정·시나리오 구분을 참고하되 페이지 계산의 정확성이나 사업 가정을 이번 문서에서 독립적으로 검증한 것은 아니다 [S4]. 첫 진입에서 전체 드라이버를 펼치기보다 실적·차이에서 관련 원인과 가정을 확인하는 순서를 제안한다.

## 8 공통 사실과 지역 확장

### 8.1 여정에서 유지할 공통 사실

각 역할은 같은 환자·계획·서비스의 사실을 권한에 맞는 범위에서 다르게 표현한다. 재무담당자에게는 개인 건강정보보다 필요한 집계를 제공한다.

| 사실 | 반드시 구분할 상태 |
|---|---|
| 판단 | 자기보고·측정·모델 추론·의사 확정 |
| 계획 | 초안·검토·승인·적용·보류·취소 |
| 조치 | 제안·담당 배정·요청·실행·결과 확인 |
| 참여 | 전달·열람·수용·거절·실제 수행·미확인 |
| 의약품 | 처방·심사·주문·조제·배송·수령·복용 보고 |
| 자료 | 최신·오래됨·결측·충돌·사용 불가 |
| 재무 | 가정·관찰 실적·검증된 귀속효과 |

### 8.2 지역 운영으로의 확장

중국 V5를 우선 검토하면서 제주·펜실베이니아·GRMC·몽골에 공통으로 필요한 서비스 연결과 맥락 승계를 고려한다. 현재 모든 지역의 제도·운영·연계 방식이 확인된 것은 아니다.

몽골 회의 수치인 방문 70%, 치료 필요 30%, 미방문 집단의 사망 관련 설명은 출처 미검증이다. 기준·성과 수치로 쓰지 않는다. WHO의 몽골 사례는 원격지 접근, 이동·방문 의료, 일차의료와 의뢰·후속 연결을 다룬다 [E11].

인구집단 콘텐츠는 대상 인구, 등록·동의, 최근 상태 확인, 확인·연결 필요, 연결 완료를 구분한다. 미등록·연락 불가·관찰 없음은 건강함과 다르다. 전체 대상 인구 자료가 없다면 인구 전체의 도달률을 계산하지 않는다. 필요한 진료까지 지연할 수 있으므로 방문 감소만을 성공 지표로 두지 않는다.

지역 지도나 통합 관제의 외형은 필수로 확정하지 않는다. 서비스 연결의 누락·책임·결과를 먼저 정의한다. 공공보건·지역 자원 배분은 별도 역할 검토 사항이며 병원 재무담당자의 업무로 자동 편입하지 않는다.

## 9 안전과 적용 범위

- Reliability의 공식 scoring scope는 exercise only로 유지한다.
- 건강검진 예측은 BLOCKED_BY_DATA로 유지한다. 합성 결과를 개인 예측이나 임상 성능으로 제시하지 않는다.
- 근거·권한·자료가 부족할 때 ABSTAIN 또는 REVIEW_REQUIRED를 사용자에게 이해 가능한 말로 표현한다.
- 전문가 자문 수치·자가평가·RPE·식사기록·수면·영양·자세분석은 대상·타당도·오차·안전성 검토 후 적용한다. 자문 의견을 확정 임상 규칙으로 취급하지 않는다.
- 중국 의약품 판매가 무규제라는 회의 표현은 확정 전제로 쓰지 않는다. NMPA 규정에는 자격·실명·처방·약사 심사 등 요건이 있다. 실제 판매 주체·품목·운영 조건에 대한 검토는 남아 있다 [E12].
- 규제 검토가 필요한 가치는 관리 목록에 남기고, 허용된 기능과 보류한 기능의 상태를 구분한다. 검토 전 실제 진단·처방·판매가 가능한 것처럼 제시하지 않는다.
- V6와 제주 최대 10만 명 범위는 기획·제안이다. 3+1의 전체 구현·효과 검증을 이번 경쟁의 완료 사실로 주장하지 않는다.
- +1은 개입 후보의 검증·승인·롤백과 현장 경험의 코드·설정·SOP·평가 기준 축적을 함께 검토한다. 임상 정책·진단·안전 임계치를 자동 변경하지 않는다.
- 경쟁 발표 2026년 11월 11일과 발표자료의 11월 30일 시연 목표는 별도 일정이다.

## 10 우선순위와 이후 시안 비교

| 우선 | 콘텐츠 범위 |
|---|---|
| 우선 포함 | 개인 맥락, 역할별 상황·업무 진입, 최신 계획, 다음 행동, 근거·승인, 짧은 반응, 사람의 도움, 실제 수행 상태. 자연어는 보조 입력으로 검토 |
| 우선 포함 | M1 판단과 M3 후속 관리, 다음 W의 맥락 승계, 실적·가정 구분, 관리 원가 |
| 조건부 포함 | 처방·구매·배송·복약의 상태 예시, 사례관리 대상·연결 상태. 모의 여부와 적용 조건 명시 |
| 후속 검토 | 본격 M2, 전 지역 관제, 아바타·게임화, 카메라 자세분석, 광범위한 상품 탐색 |
| 제외 | 허위 정상 판정, 미검증 예측, 승인 전 계획 적용, 임의 생성된 실적, 에이전트 지휘를 요구하는 기본 경험 |

세 사용자군의 콘텐츠 목록을 검토한 뒤 시안 제작 여부를 결정한다. 이후에는 동일한 시나리오·자료·기능 범위를 두고 시각적 완성도와 사용 방식의 지속성을 별도 평가한다. 세부 기준은 [시안 비교 기준](UX_UI_Concept_Comparison_Criteria_20261029.md)에 정리했다. 현재 시안 점수나 우승안은 없다.

남은 결정은 다음과 같다.

1. 챗봇 중심 형태를 제외한 상태에서 일반사용자 첫 진입의 현재 상태·다음 행동·개인 맥락을 얼마나 드러낼지
2. 의료진 시안에 사례관리 역할까지 포함할지
3. 의약품 여정을 어느 단계까지 예시로 보여줄지
4. 병원 재무와 지역 경제성의 시안 범위를 어디서 구분할지
5. 실증 가능한 자료와 담당자가 확보되는 시점, 지역별 언어·기기·연계 조건

세 사용자군 포함 여부와 특정 선호 제품의 유무는 확인됐다. 추가로 다시 묻지 않는다. 필요한 것은 세 사용자군 각각의 핵심 과업, 서비스 책임과 처리 범위, 실제 불편의 근거다.
